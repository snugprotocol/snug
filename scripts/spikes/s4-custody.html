Operator walk
  1. Wait for the capabilities line to resolve. Click 1 generate, then 2 publish as file. For a latency median click 2 twice more, a few seconds apart (each click mints a version; the samples accumulate under publish.samples, publish.medianMs). The record is append-only: every attempt of every click stays under publish.attempts (tagged by run), publish.accepted is the first success and never changes, and a rejected re-click (rate_limited) lands in publish.lastRun only.
  2. Reload the page (a files publish does not reload this view; relative URLs still serve the version it loaded). Click 3 verify — it passes only when this page load began after the last accepted publish (verify.loadedAfterPublish); an un-reloaded click reads red with "reload first". Tell the session "verified".
  3. The session bumps BUILD in this file (r1 → r2) and republishes the html through the Artifact tool — same file_path, capabilities and contract OMITTED so the stored declaration carries forward, a conflict resolved by read → publish, never force (force would discard the data file). If the page did not reload on its own, reload it. Confirm the build tag above reads r2, then click 4 re-check after tool republish.
  4. Click 5 export; accept the save prompt for snug-user.snug.json (the first call, snug-user.snug, is expected to be refused before any prompt).
  5. Click 6 storage limits + env. Say "done": the session then fills sessionChecks (version picker readable, the tool republish's version id) with a write_db update on results/s4. The page re-adopts those slots from the db before each of its own writes (get → merge → set), so a later click does not erase them. Session-side reset = write_db delete results/s4.
  1. 2 MiB Uint8Array, mulberry32 seed 0x534e5547, first 16 bytes = SQLite format 3\0, sha256 via crypto.subtle, compared to the reference sha reproduced in Node.
  2. Files form, first success wins: data/user.snug bare Blob (octet-stream, the AC's literal shape) → wrapped octet-stream → vnd.sqlite3 → x-sqlite3 → data/user.snug.bin octet-stream → data/user.snug.txt base64 text/plain. Each attempt is saved before the next; the chain stops on a permanent lifecycle code, conflict, too_large (the remaining payloads are the same size or larger) or a 60 s probe timeout (a late answer lands under publish.lateResults). Append-only across clicks: attempts keeps every run, accepted is the first success and is never overwritten by a later rejection.
  3. Reload FIRST. fetch(path, {cache:'no-store'}) with a 30 s timeout, hash the bytes (base64-decode for the .txt form), compare to the sha recorded at publish; records status, content-type (an html fallback is not "found"), byteLength, first bytes, page-load time, build tag, whether this is still the view that published, and loadedAfterPublish (page load > last accepted publish) — pass = equal + loadedAfterPublish.
  4. Same check under afterToolRepublish, plus loadedAfterVerify (page load time > verify time) and buildChangedSinceVerify (r2 vs r1). Pass = all three.
  5. downloads.save of a Blob {format:'snug-user-file/1', sha256, bytesBase64} — first as snug-user.snug (expect rejected_extension), then as snug-user.snug.json (a prompt; accept it).
  6. Namespace members, whether any limits() exists, documented caps from the d.ts files, origin, claude.use presence, version ids seen, empty sessionChecks slots for the session.
  7. Two clicks within 8 s. Clears sessionStorage and deletes db results/s4 for a clean rerun.
