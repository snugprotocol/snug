## Spec (what & why)

Wrap the existing static hub client (playground) in a **Tauri 2** native shell at `apps/desktop`, making Snug a downloadable desktop app a non-technical user ("grandma") can install and use with connected apps. Desktop is the launch-day artifact for LAN-class connectors (Hue) and kills the BYOK CORS wall via a native fetch behind the existing `fetchImpl` seam — zero security-model change (C1/C2 intact; the app iframe still has `connect-src 'none'`; the host page is the only fetch caller). **BYOK/Local modes only** — no subscription mode in the desktop shell (consistent with ADR-0013 posture for the hosted instance).

Scope pillars:
1. **Native fetch proxy** behind the connected-fetch `fetchImpl` seam — no CORS wall, LAN-reachable (Hue-class), SSRF/host-ceiling guards preserved (host-side checks stay; the browser's CORS was never the security boundary — the executor's allowlist is).
2. **File-backed userdb at `~/Snug`** via the persistence-backend seam — sql.js bytes persisted to a real `user.sqlite` file (A/B-slot safe-write pattern carried over); OPFS remains the web path, untouched.
3. **Ollama autodetect** via the existing local adapter (probe localhost:11434, offer local mode when present).
4. **`.snug` file association** — double-click imports/opens.
5. **Desktop OAuth transports** via the existing `RedirectUriProvider`/`CallbackSink` seams: loopback listener default (fixed port for exact-match providers — Spotify: explicit `127.0.0.1`, never `localhost`; ephemeral for Google-class), with the four-rung ladder (loopback / custom-scheme deep link / hosted https-bridge / device-flow) mapped per provider. Flow logic, HMAC-signed state, flowId binding, PKCE all carry over untouched. **Provider logins open in the SYSTEM browser only (RFC 8252)** — never in the webview (Google blocks embedded webviews, `disallowed_useragent`).
6. **Registry: per-entry desktop redirect posture** — a human-authored, dashboard-verified `desktopRedirectPosture` field (`loopback | loopback-fixed-port | custom-scheme | https-bridge | device-flow`) plus a `browserCallable` disclosure flag, so the wizard renders the right registration walkthrough per platform and **refuses honestly at connect time** instead of failing mid-flow. Provider capability differences become reviewed registry data — the registry is the authority (consistent with TASK-20260812-registry-authoritative-auth).
7. **UI/UX**: grandma-simple, Jony-Ive-calibre intuitive. Wizard walkthroughs per posture; desktop-only affordances labeled; no jargon on the happy path.

**HARD GATE (before desktop is called first-class):** the runner C2 CSP/sandbox suites and one connection-wizard e2e journey must pass **inside the shell** on macOS + Windows (Linux/WebKitGTK best-effort per roadmap B3). If WebKit breaks something structural, fall back to Electron **through the same seams**. (This session can execute the macOS leg; Windows leg runs in CI or is explicitly journaled as pending owner hardware.)

**Acceptance criteria** (each becomes at least one test):
1. **AC1 — fetchImpl seam carries the desktop fetch on BOTH call paths**: with a desktop platform fetch injected, connected-fetch requests execute through it (not page `fetch`) via the RunView net handler AND the wizard's `executeConnectionTestRequest` probe (single shared seam: `connectedFetchDepsFor`'s default), and all existing executor guards (host ceiling, SSRF policy as amended for desktop, strict injection, response scrubbing) still run — proven by unit tests over the seam + at least one in-shell probe against a CORS-hostile endpoint that fails in the browser and succeeds in the shell.
2. **AC2 — file-backed userdb**: desktop persistence backend writes `~/Snug/user.sqlite` bytes via safe-write (new-file + atomic pointer/rename, magic check on read; zero-byte/magic-less read = CORRUPT/quarantine, never "fresh"); survives kill-mid-write (crash-safety test at the backend level); web OPFS path unchanged (regression: existing db suites green).
3. **AC3 — Ollama autodetect**: when an Ollama endpoint responds on localhost, desktop boot surfaces local mode with detected models; when absent, no error surfaces and BYOK remains default. Unit-tested probe logic; manual in-shell verification journaled.
4. **AC4 — `.snug` association**: opening a `.snug` file (double-click / Open With) routes into the existing import flow — macOS `RunEvent::Opened` and Windows argv paths both handled; unit-test the routing seam, in-shell manual proof journaled.
5. **AC5 — desktop OAuth loopback**: a full PKCE flow completes with the loopback CallbackSink — `RedirectUriProvider` yields `http://127.0.0.1:{port}/callback` (fixed port for `loopback-fixed-port` entries, ephemeral otherwise; NEVER `localhost`; recorded-string identical across both service calls); the token-exchange POST goes through the platform fetch; the login URL is opened via the system-browser opener (asserted at the pre-open seam — the webview is never navigated to a provider). Negative tests: forged/wrong state rejected AND the valid-state/foreign-code injection documented as defeated by provider PKCE binding — which is why a structural registry test refuses `pkce:false` + loopback posture. One integration test completes the round trip through the ACTUAL listener (not the injected seam).
6. **AC6 — registry posture is authoritative + honest refusal**: every OAuth-capable registry entry carries a valid `desktopRedirectPosture`; schema validation rejects unknown values; the wizard (a) renders the posture-matched walkthrough, (b) at connect time on desktop, an entry whose posture is unsupported by the running shell build (e.g. `https-bridge` before the bridge ships) gets a clear refusal screen BEFORE credentials are pasted — never a mid-flow failure. `browserCallable: false` entries disclose "this provider can't be called from a browser" in the web wizard (advisory's disclosure) and are callable on desktop.
7. **AC7 — C2 inside the shell (HARD GATE)**: the 14 `BROWSER_CSP_CHECKS` **plus shell IPC-unreachability checks** pass against the webview inside the Tauri shell on macOS (this session) — `allow-scripts` only, `connect-src` blocked, CDN allowlist enforced, AND the Tauri IPC handles (`__TAURI_INTERNALS__`/`webkit.messageHandlers`/`chrome.webview`) unreachable (or invoke refused) from inside a sandboxed srcdoc iframe — every verdict present, enforcement-signal assertions (not API return values). Capabilities scoped to the main window. IPC injected into subframes with no off-switch = structural breakage → Electron fallback. Windows run wired into CI or journaled as pending.
8. **AC8 — wizard e2e inside the shell**: one connection-wizard journey (api-key-class starter connect) passes inside the shell.
9. **AC9 — C1 unchanged**: desktop introduces no new credential egress — tokens still live only in the user file's `snug_secrets`; the loopback listener response page contains no token material (the sink receives only `code`+`state`; exchange happens in the host); no secrets in Rust-side logs. Negative tests at the sink boundary.
10. **AC10 — no-regression**: full root suite (turbo, uncached) green; web playground behavior unchanged when no desktop platform is injected.

**Out of scope**: subscription mode in the shell; the hosted https-bridge page itself (posture value + refusal path ship now; CF Pages bridge is its own task); device-flow implementation (posture value reserved; refusal path covers it); auto-update/signing/notarization + installers for distribution (dev-build proof only this task); Linux first-class support (best-effort); OAuth popup web-path changes; MCP bridge; iOS/Android.

### Decisions being made now (→ ADR-0021 "Desktop shell transports", drafted in this task)

1. **Posture is registry data**: `desktopRedirectPosture?: 'loopback' | 'loopback-fixed-port' | 'custom-scheme' | 'https-bridge' | 'device-flow'` on `WellKnownOauthProvider` AND `WellKnownAuthOption` (option overrides entry, per ADR-0020's flow-seat rules — but hosts/identity stay the entry's). `browserCallable?: boolean` on the entry (advisory's disclosure flag; absent = unknown, disclosed as such — absence must never render as "works in browser"). No runtime zod on the registry; enforcement = TS union + a structural test (every `oauth2_auth_code`-capable entry/option carries a posture, authored against the provider's real dashboard docs; `registration.instructions` for desktop rendered per posture).
2. **Fixed port for BYO-registration exact-match providers.** Ephemeral ports would invalidate the redirect URI the user registered in the provider dashboard on every restart — so `loopback-fixed-port` is the posture for Spotify-class (exact-match) providers; `loopback` (ephemeral, any-port loopback per RFC 8252 §7.3) only where the provider honors it (Google-class). Desktop fixed port: **41420** (`SNUG_DESKTOP_OAUTH_PORT`), collision → honest wizard error naming the port and the likely cause, never a silent fallback port (a fallback port would break the registered URI anyway). Redirect URI shape: `http://127.0.0.1:41420/callback` — literal `127.0.0.1`, never `localhost` (Spotify bans it; RFC 8252 prefers the literal).
3. **System browser only** (RFC 8252 §8.12): desktop swaps the popup seam for the OS opener; the webview never navigates to a provider. The register-step copy and the service's `redirectUriProvider` draw from ONE platform source.
4. **Loopback listener = `tauri-plugin-oauth` v2** (verified current: fixed-port via `ports: Some(vec![41420])`, bind failure errors rather than silently falling back — exactly the honest-collision behavior we need; ephemeral = omit ports; custom branded response HTML). Response page contains zero token material (only `code`/`state` transit, already public in the URL); listener binds `127.0.0.1` only; TS transport wrapper enforces single active flow + cancel-on-teardown + 10-min TTL matching `STATE_TTL_MS`; delivery via the plugin's `onUrl` → a desktop `ConnectionChannelLike` adapter (the existing `ConnectionOAuthHooks.channelFactory` seam) → the untouched `handleConnectionDelivery` guards (held `expectedFlowId`, HMAC state verify, nonce, PKCE).
5. **Unsupported postures refuse honestly at wizard entry**: `custom-scheme`, `https-bridge`, `device-flow` render a "not yet on desktop" screen with provider-specific explanation BEFORE any credential entry (AC6). Slack-family stays connectable by its non-OAuth options where the registry has them.
6. **LAN/Hue-class reach (scheme policy)**: desktop's connected-fetch transport profile allows `http://` **only** for RFC-1918/private-range IP-literal hosts that the user explicitly approved into the connection's frozen host ceiling; public hosts stay https-only; loopback/localhost stays refused; browser profile totally unchanged. This is the narrowest change that makes Hue reachable, it keys on the strong-reviewed ceiling, and it gets negative tests both ways + a threat-model delta noting the DNS-rebinding residual (public-hostname pin-resolution deferred with a dated next-step).
7. **Desktop persistence**: `~/Snug/user.sqlite` via a `'file'` `PersistenceBackend` implemented webview-side over two Rust commands (`read_user_file`/`write_user_file` with temp+rename atomicity, magic-checked reads, quarantine preserved); sidecar + userdb share the backend; `flush()` wired to Tauri's close-requested event. Single-instance plugin prevents two shells on one file; the web-vs-desktop same-file concern doesn't exist (different stores).
8. **`.snug` association**: desktop registers `.snug`; export path on desktop names files `*.snug` (same sqlite bytes; magic unchanged); open events (macOS `RunEvent::Opened`, Win/Linux argv + single-instance) route into a confirm dialog → `importUserFile` (F15 arms). No silent import, ever.
9. **Shell composition**: `apps/desktop` = Tauri 2 Rust crate + its own thin vite app whose `main-desktop.tsx` sets the platform then renders the playground `App` via source alias (`HashRouter` — the `tauri://` origin has no SPA fallback; web `BrowserRouter` untouched). Playground gains ONE new seam: `src/platform/` (`SnugPlatform` interface + `setPlatform`/`getPlatform`, browser default = current behavior), consumed at exactly: `state/net.ts` (fetchImpl), `state/userdb.ts` + `state/sync.ts` (backend), `agent/adapter.ts` (LLM fetch), `connectionWizard.ts` + `ConnectionWizardSheet.tsx` (redirect URI source, opener, channel), `run/exportDb.ts` (save dialog), Settings/App (Ollama probe, import confirm). Every consumer defaults to today's behavior when no platform is set — AC10's no-regression hinges on that.
10. **BYOK/local only in the shell**: desktop UI never offers subscription mode (mode store constrained by platform capability flag).
11. **Native fetch = `tauri-plugin-http` ≥ 2.5.9** (reqwest-backed, CORS-free, `ReadableStream` bodies since 2.4.0 with abort/cancel fixes through 2.5.7 — SSE-capable for Ollama/BYOK streaming). Tauri capability scope set explicitly (`https` any host + `http://10.*`,`http://172.16-31.*`,`http://192.168.*` for the LAN rung) — the REAL ceiling remains the connected-fetch executor's frozen per-connection allowlist, exactly as in the browser where page fetch is also unscoped (C1's guarantee never rested on the transport). Two contract facts to prove in-shell at P2/P4, with fallback to a custom Rust command fetch if either fails: `redirect: 'manual'` is honored (B2 guard), and streamed reads enforce the 1 MiB cap.
12. **macOS secure-context risk (verified open question)**: wry does not register `tauri://` as a secure scheme on WKWebView, so `crypto.subtle` (HMAC state signing, `signState`) and OPFS may be absent. Desktop doesn't use OPFS (file backend), but WebCrypto is load-bearing for OAuth. P2 boots with a day-one probe (`window.isSecureContext`, `crypto.subtle`, sql.js wasm); if insecure, ship a scoped pure-JS SHA-256/HMAC fallback injected ONLY on the desktop platform (never web), with byte-parity tests against WebCrypto vectors. `crypto.getRandomValues` is context-independent and unaffected.

Versions pinned by research (2026-08): tauri crate 2.11.5 / `@tauri-apps/cli` 2.11.4 / `@tauri-apps/api` 2.11.1, MSRV 1.77.2 (toolchain updated on this machine); `tauri-plugin-http` 2.5.9; `tauri-plugin-oauth` v2 branch; `tauri-plugin-opener` for system browser (RFC 8252); `tauri-plugin-single-instance` (+`deep-link` feature ordering caveat) for Win/Linux second-instance argv; file associations via `bundle > fileAssociations`, macOS delivery via `RunEvent::Opened`, Win/Linux via argv. Spotify officially permits `http://127.0.0.1:PORT` loopback (exact-match; `localhost` banned; portless registration with dynamic port allowed — we still ship the fixed-port walkthrough because one stable copy-paste URI is the simpler grandma story). Unsigned local dev builds run fine on the building machine (signing/notarization is distribution-only, out of scope).
