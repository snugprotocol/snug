## Spec (what & why)

**What.** Binding B (ADR-0068) is merged and walked, but the plugin it produces is not yet something a person can install from a marketplace and use: it carries the process and the page and **no skill** — an agent that installs it gets four tools and a 37-line launch note, not the app-authoring knowledge base, so it cannot build a Snug app. Its `.mcp.json` says `command: node`, which fails under a desktop host whose spawned processes have no user PATH (measured: `launchctl getenv PATH` is empty on the owner's Mac; `node` and `claude` live under nvm). Its brain spawns a cold `claude -p` per think (~3.5 s of overhead each, measured on 2.1.270), cannot tell an outdated CLI from an unknown failure (the owner's 2.1.211 had silently stopped working for every call), and buffers a whole build before the page sees a byte. This task closes those four gaps and assembles the tree the community marketplace takes, then stops at the owner acts (create the distribution repo, push, submit).

**Why now.** The owner's direction of 2026-09-13 (ADR-0069): Binding B with the child-CLI brain is the primary path for Claude Code and Claude Desktop/Cowork; the audience is non-technical; setup must be one plugin install. Everything here is what stands between "merged" and "installable".

**Acceptance criteria** (each becomes at least one test; owner walks are marked 🔑):

1. **The skill rides in the plugin.** `dist/plugin/skills/snug/SKILL.md` exists with frontmatter `name: snug`, a `description` ≤ 200 chars that says what and when, `license: MIT`; its body carries the launch protocol (Binding B first: `snug_status` → `snug_open` → build → `snug_hand_in`; Binding A as the fallback when the tools are absent and an `Artifact` tool exists; else the one-line install), the authoring order over `references/`, the custody sentence, and the never-list (no `--bare`, no keys in child envs, no connected-app claims under A/C, never "built on MCP"). `references/*.md` are the app-authoring KB files 10–95 rendered by `@snugprotocol/knowledge` (headers stripped, `{{cdnAllowlist}}` resolved, `##` headings byte-identical to the source's). `claude plugin validate --strict dist/plugin` and `uvx --from skills-ref agentskills validate dist/plugin/skills/snug` both exit 0. Tests: frontmatter limits; the references' heading lists equal the KB's; a mutation (edit the built SKILL.md) reds the gate's byte-compare.
2. **The SKILL.md source lives in the prompt store and not in `content.ts`.** `packages/knowledge/prompts/skills/snug/SKILL.md` is the one source (ADR-0004); `gen-content.mjs` excludes `skills/snug/**` by an explicit list; a test regenerates and asserts the key is absent; the centralization lint stays green; `prompts/README.md` names the exclusion.
3. **The launcher starts the process with no user PATH.** `.mcp.json` is `{"command":"sh","args":["${CLAUDE_PLUGIN_ROOT}/scripts/snug"]}`; `scripts/snug` (POSIX sh, no bashisms) finds `node` ≥ 20 on `PATH`, then `~/.nvm/versions/node/*/bin` (highest), `~/.volta/bin`, `~/.local/share/fnm`/`~/.fnm`, `/opt/homebrew/bin`, `/usr/local/bin`, and execs `node <dir>/snug-local-host.mjs "$@"`; with none it prints one line to stderr naming the install (`https://nodejs.org` or `brew install node`) and exits 1. Tests (node:test): spawn `sh scripts/snug` with a controlled `PATH`/`HOME` and a fake `node` shim that records argv; the no-node case; a `node` 18 on PATH skipped in favour of a 22 under nvm; `sh -n` parses the script.
4. **The brain finds its binary and names five states.** `resolveClaudeBinary({env, exists})` checks `PATH`, then `~/.local/bin/claude`, `~/.claude/local/claude`, `/opt/homebrew/bin/claude`, `/usr/local/bin/claude`, `~/.nvm/versions/node/*/bin/claude` (highest), `~/.volta/bin/claude`, fnm; `probeBrain` returns `ready | logged-out | outdated | absent | unknown` — `outdated` from the CLI's `version X or newer is required` sentence, remedy `claude update`; `absent` carries the installer line (`curl -fsSL https://claude.ai/install.sh | bash`, then `claude` + `/login`). The chip on the local page shows each state's sentence; the e2e pinned-state list gains `outdated`. Tests: a fake `exists`; each state from a captured stdout; the release bundle's env-read gate still passes (the resolver reads `HOME` and `PATH` only).
5. **The brain keeps a warm child, and a single-turn request never inherits a turn.** `createClaudeBrain` owns a `SessionPool` keyed by `sha256(system)`: `acquire(system, messages)` returns a child whose transcript equals `messages[0..-1]` (send the last user turn only) or a virgin child (send the rendered conversation as one turn); after a request the child holds the transcript; a request that does not extend a used child's transcript never reuses it; one virgin child per system prompt is pre-warmed after a request (`maxChildren` 4, idle TTL 10 min, both constants named); `stop()` kills every child; an abort kills the child it aborted; a child that emits `is_error` or exits is discarded. The wire is `--input-format stream-json --output-format stream-json --verbose --include-partial-messages` with the argv posture of ADR-0068 §5 (`--tools ""`, `--disallowedTools *`, `--max-turns 1`, `--no-session-persistence`, never `--bare`, allowlisted env). Tests: a fake child (a duplex that scripts stream-json events) — prefix reuse sends exactly one `user` message; a virgin child gets the whole conversation; a used child is not offered a fresh single-turn request; pre-warm happens and costs no message; TTL reaps (fake timers); `stop()` reaps all; abort kills; error discards; the interop suite still lists four tools. An opt-in live test (`SNUG_LIVE_BRAIN=1`) runs two turns on the real CLI and asserts the second is faster than the first's spawn.
6. **The page sees tokens as they arrive.** The chat route writes SSE chunks as `content_block_delta` events arrive and a final chunk with `finish_reason` + `[DONE]`; `openaiAdapter`'s `onDelta` fires before the result. Tests: the route with a fake brain that yields three deltas → three `data:` frames before the finish; an error after the first delta closes the stream with no finish (the adapter's "stream died" path is the honest reading, pinned).
7. **The assembled tree is complete and gated.** `build-plugin.mjs` writes `.claude-plugin/{plugin,marketplace}.json` (source `./`), `.mcp.json`, `skills/snug/**`, `scripts/{snug,snug-local-host.mjs,snug-host-local.html,snug-host.html}`, `README.md`, `LICENSE`; `check-local-host.mjs` (the renamed gate) builds it into a temp dir on every run, runs both validators when they are on the machine and prints `NOT VERIFIED: <validator>` otherwise, byte-compares SKILL.md against its rendered source, and keeps the release-bundle sweeps (test hooks, env reads — the whole-env count rises to **4** for the resolver's PATH walk only if it reads the whole object; prefer named reads). - **Q3 — Ship both kits inside the plugin (~4.5 MB) or fetch them from a Release on first use (D11)?** **Ship inside, for now.** A Release is an owner act that does not exist yet; a marketplace clone of 5 MB is unremarkable; D11 stays the design for when the Release exists (the kits are then dropped from the tree and `kits.json` takes their place).
- **Q4 — The pool's limits.** **4 children, 10-minute idle TTL, one pre-warmed virgin child per system prompt, pre-warm only after a request has used that prompt** (a boot-time pre-warm would spawn a `claude` for a page nobody opened).
- **Q5 — Should Binding B's hand-in admit a bundle whose `connections` are REQUIREMENTS (credential-free by shape, ADR-0063), so an agent-built connected app arrives with its connect card?** **Not here.** Today the agent's declaration is lost at hand-in and the user re-declares in the wizard; ADR-0017's requirement/grant split says a requirement is not a grant and the sharing path already admits them with review, so the change is plausible — but the D6 pin (2026-08-12) makes admission changes their own task + ADR. Queued in next-steps with this reasoning; the SKILL.md tells the agent the truth for now.
- **Q6 — Marketplace target.** **The community marketplace** (form → pinned SHA). The curated one has no submission path (verified 2026-09-13).
- **Q7 — The SKILL.md's placement of the launch protocol relative to `instructions.md`.** **Both, one source.** `instructions.md` stays the process's `initialize` text (D-B12); SKILL.md's launch section is generated FROM it by the skill build (byte-compared), so the agent reads one protocol twice rather than two protocols once.

### Threat model (delta rows to write)

- **The warm child**: N long-lived `claude` processes per user, each holding one system prompt in argv (`ps`-visible, as before) and a conversation in memory; reaped on stop/parent death/TTL/abort/error; the pool cap bounds it. Residual: a wedged child holds its slot until the TTL. No credential is anywhere near it (the brain never sees `snug_secrets`; the executor is the page's).
- **The launcher's PATH walk**: it executes the first `node` it finds under the user's own home — the same trust as the user's shell. It never downloads anything (that step is a later, pinned-and-verified one).
- **The binary resolution**: same posture; a `claude` under `~/.local/bin` is the user's install.

## Decisions & surprises

- **2026-09-13 — Binding B IS the owner's "path 2".** The memory summary and the package names said "MCP"; the code says: the host spawns a process, the process serves the page, the page's executor calls the process, the process runs `claude -p`. MCP is the spawn channel and four control tools. → ADR-0069 §1–3; Q1.
- **2026-09-13 — the owner's CLI was broken for every call and nothing in Snug knew.** `claude -p` on 2.1.211 answered `400 … version 2.1.251 or newer is required` with `duration_api_ms: 0`; `probeBrain` would have said `unknown`. Updated to 2.1.270 (the CLI's own instruction) to measure. → AC4's `outdated` state.
- **2026-09-13 — measured, CLI 2.1.270, allowlisted env:** cold `-p` 5,047 ms wall / 1,546 ms model (second call; the first 7,263 / 3,567); warm child: `system/init` at 2,815 ms, turn 1 4,211 ms, turn 2 **1,424 ms**, turn 3 **1,321 ms**; the child kept the conversation (turn 2 answered "Teal." from turn 1); `session_id` constant across turns; `--include-partial-messages` yields `stream_event/content_block_delta` with `text_delta`; exit 0 after stdin end. The `--input-format stream-json` flag is in `--help` (2.1.211 and 2.1.270) though absent from the public docs.
- **2026-09-13 — `launchctl getenv PATH` is EMPTY on the owner's Mac;** `node` and `claude` are nvm installs. Claude Desktop's `Application Support/Claude/claude-code-vm/2.1.266/claude` is a **Linux ARM64 ELF** (Cowork's VM), so the Mac has no Desktop-provided CLI. → AC3, AC4.
- **2026-09-13 — the Agent SDK bundles its own binary and authenticates with an API key or a cloud provider**, never the user's subscription (docs, 2026-09-13). → not a brain option (ADR-0069 alternatives).
- **2026-09-13 — the curated marketplace has no submission path; the community one has a form and pins a SHA.** → Q6.
- **2026-09-13 — every `{{appBuilderToolName}}` in the KB files 10–95 sits in the stripped header comment**, so the rendered references are tool-free without an edit. `00-summary.md` (three mentions) is excluded from `getKnowledgeBase()` already.
- **2026-09-13 — the hand-in under Binding B refuses a bundle whose `connections` are requirements** (`handin.ts`, `runner.ts`); the agent's declaration is lost and the user re-declares. → Q5, next-steps.
