## Spec (what & why)

**What.** Binding B (ADR-0068) is merged and walked, but the plugin it produces is not yet something a person can install from a marketplace and use: it carried the process and the page and **no skill** — an agent that installed it got four tools and a 37-line launch note, not the app-authoring knowledge base, so it could not build a Snug app. Its `.mcp.json` said `command: node`, which fails under a desktop host whose spawned processes have no user PATH (measured: `launchctl getenv PATH` is empty on the owner's Mac; `node` and `claude` live under nvm). Its brain spawned a cold `claude -p` per think (~3.5 s of process overhead each on 2.1.270), could not tell an outdated CLI from an unknown failure (the owner's 2.1.211 had silently stopped working for every call), and buffered a whole build before the page saw a byte. This task closes those gaps and assembles the tree the community marketplace takes, then stops at the owner acts (create the distribution repo, push, submit).

**Why now.** The owner's direction of 2026-09-13 (ADR-0069): Binding B with the child-CLI brain is the primary path for Claude Code and Claude Desktop/Cowork; the audience is non-technical; setup must be one plugin install.

### Threat model (rows for the delta)

- **The pre-warmed child**: up to two idle `claude` processes per user (~257 MB each), each holding one system prompt in argv and nothing else until its one request; reaped after five idle minutes, on stop, on parent death (their stdin is a pipe from the parent — EOF ends the CLI), on abort, on error. No credential is anywhere near it; a child answers only the request that took it.
- **The launcher's PATH walk**: executes the first `node` it finds under the user's own home — the user's shell's trust (residual 1); it downloads nothing.
- **The binary resolution**: same posture for `claude`.

## Decisions & surprises

- **2026-09-13 — Binding B IS the owner's "path 2".** The memory summary and the package names said "MCP"; the code says: the host spawns a process, the process serves the page, the page's executor calls the process, the process runs `claude -p`. → ADR-0069 §1–3; Q1.
- **2026-09-13 — the owner's CLI was broken for every call and nothing in Snug knew.** `claude -p` on 2.1.211 answered `400 … version 2.1.251 or newer is required` with `duration_api_ms: 0`; `probeBrain` would have said `unknown`. Updated to 2.1.270 in-session (the CLI's own instruction). → AC4's `outdated`.
- **2026-09-13 — measured, CLI 2.1.270, allowlisted env:** cold `-p` 5,047 ms wall / 1,546 ms model (second call; the first 7,263 / 3,567); one warm child: `system/init` at 2,815 ms, turn 1 4,211 ms, turn 2 **1,424 ms**, turn 3 **1,321 ms**, conversation kept, `session_id` constant; `--include-partial-messages` yields `stream_event/content_block_delta` with `text_delta`; exit 0 after stdin end. **A child left idle 5 s with NO input then sent one message answered in 1,663 ms wall (1,619 ms model)** — the start-up happens before input; it emits `system/init` only on the first message; idle RSS 262,880 KB. `--input-format stream-json` is in `--help` on 2.1.211 and 2.1.270 though absent from the public docs; `--max-turns` still is not.
- **2026-09-13 — `launchctl getenv PATH` is EMPTY on the owner's Mac;** `node` and `claude` are nvm installs. Claude Desktop's `Application Support/Claude/claude-code-vm/2.1.266/claude` is a **Linux ARM64 ELF** (Cowork's VM); the Mac has no Desktop-provided CLI. → AC3, AC4.
- **2026-09-13 — the launcher test harness failed on its own PATH**: `spawnSync('sh', …, {env: {PATH: '<no /bin>'}})` resolves `sh` against the CHILD's PATH → ENOENT for every case. And the first script called `dirname`, which is not on an empty PATH either. → `/bin/sh` absolute in the manifest and the tests; builtins only in the script. Then every "no node anywhere" case exited 0 because the real list names `/opt/homebrew/bin`, where the owner has a Node → the tests isolate the roots under the temp dir.
- **2026-09-13 — the store's header lint requires every prompt file to START with the header comment; a skill must start with frontmatter.** → the source carries the header above the frontmatter; the build strips it. The placeholder-integrity lint forbids raw `snug:<word>` literals → the launch marker is `<!-- launch-protocol -->`. The prompts README rides in `content.ts` → regenerated.
- **2026-09-13 — the Agent SDK bundles its own binary and authenticates with an API key or a cloud provider**, never the user's subscription. → not a brain option.
- **2026-09-13 — the curated marketplace has no submission path; the community one has a form and pins a SHA.** → Q6.
- **2026-09-13 — every `{{appBuilderToolName}}` in KB files 10–95 sits in the stripped header comment**; the auth reference keeps `{{api_key}}`-style RUNTIME template placeholders on purpose (the first reference test flagged them; the check now names the protocol placeholders only).
- **2026-09-13 — the hand-in under Binding B refuses a bundle whose `connections` are requirements** (`handin.ts`, `runner.ts`); the agent's declaration is lost. → Q5, next-steps.
- **2026-09-13 — `snug status` through the launcher found a LIVE runner on 43127** (the owner's own session) — the e2e's isolated `SNUG_HOME` and ephemeral fallback keep the suites off it.
