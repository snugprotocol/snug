## Spec (what & why)

**What.** Under Binding A1 (the hosted artifact, brain = the viewer's `sample`) the brain chip's popover gains a **thinking-level control**: the tiers the runtime contract offers — `quick`, `default`, `complex` — as one dropdown, its initial selection matching the viewer's default, switchable by the user; the next call carries the chosen tier. The chip stays the ONE disclosure surface (ADR-0059): the control renders only where a brain carries a tier seat (the hosted artifact), never on the web, the desktop, the chat brain (`window.claude.complete` has no tier) or the demo brain. Switching never spends anything (no call on switch, no call on load — lesson 2026-09-04). The chip is honest about substitution: the contract says the viewer "may serve a nearby cheaper tier when the viewer's plan lacks the one asked for" and reports the answer in `modelTierApplied` — "if you offer a tier choice, this is how you tell the viewer it could not be honoured" — so after a call whose applied tier differs from the ask, the popover says so by name.

**Why.** The owner's ask (2026-09-06): see the viewer's thinking levels on the runner and switch between them. This amends **D15**'s clause *"Model choice inside a binding (for example `sample`'s `modelTier`) is a per-contract host decision made in T4 from S3's numbers, not a control"* — narrowly: the BRAIN stays the host's (no mode, provider, key, URL, account or demo choice anywhere — every other D15 sentence stands); within a brain whose contract offers tiers, the tier becomes the user's. Recorded as ADR-0067 and a dated amendment on D15.

**Facts this design stands on (contract 0.2.41 `sample.d.ts`, read 2026-09-06; T1 S3; T4 S11):**
- The ONE knob is `modelTier: "quick" | "default" | "complex"`; there is no separate thinking/effort option — **the tier IS the thinking level**: `quick` "does not think first, so text starts almost at once"; `default` (omitted) "the balanced everyday model", "thinks silently before it writes"; `complex` "the most capable, for hard reasoning (thinks longest)". **The viewer's default is `default`.**
- `limits()` lists NO tiers (only `maxPromptBytes`, `images?`, `tools?`); availability is discovered only per call through `modelTierApplied`. So the dropdown lists the contract's three, and a tier the plan lacks is learned from the first answer, never known at boot.
- Measured: `quick` chess replies median 1.2 s, 48/48 legal (S3); on a 33 KB whole-app rewrite, first token 0.9–1.1 s on `quick`, 4.1–5.8 s on `default`, 3.7 s on `complex`; whole rewrite 107 s / 94 s / 115 s (S11 B/A/H). The contract's own range: first text 5–60 s on `default`/`complex`. Today the kit pins **`quick` for app replies** (`probe.ts:346`) and **`default` for building and inferring** (`probe.ts:347`), one adapter per purpose.
- Answer caching is keyed by tier (irrelevant: the kit sends `cache: false`). The A2 `complete` verb has no tier.

**Acceptance criteria** (each becomes at least one test):

1. **The seat.** `PlatformBrain`'s `'host'` arm gains an optional `tiers: TierSeat` (`{ options: readonly HostModelTier[]; viewerDefault: HostModelTier; state: { get(): TierState; subscribe }; set(choice): void }`; `HostModelTier` typed in `platform.ts` — the playground owns the seat types, the kit imports them, the `CustodyState` precedent). The kit pins it only on the `sample` brain: options `['quick', 'default', 'complex']`, `viewerDefault: 'default'`. The `complete` brain and the demo brain carry none. Positive twin: web and desktop platforms are unchanged.
2. **The tier is read at CALL time.** `createSampleAdapter` takes the tier from the store (a getter), never a value frozen at construction: switch → the NEXT `sample` call carries the new `modelTier`; a switch makes ZERO calls (pinned: the fake records none); boot makes none (unchanged AC1 pin). **Q2 = B:** the choice is `'auto' | 'quick' | 'default' | 'complex'`; under `auto` the app adapter reads `quick` and the chat (builder/inferrer) adapter reads `default` (today's pins, unchanged); any explicit tier overrides BOTH adapters. Pinned for both adapters, both rules.
3. **Persistence (Q3 = this browser).** The store reads `localStorage['snug-host:tier']` at boot (an unknown value → `auto`), writes on `set`, and falls back to memory where storage throws (Safari's denied rung) — all three pinned. Never in the user file: not exported, not written into the page on save (pinned: a save after a switch publishes a page whose db block is unchanged by the choice).
4. **Honesty about substitution.** The adapter reports `{ asked, answered }` to the store when `modelTierApplied !== modelTier`; the popover then says "asked for complex — this view answered on default (the viewer's plan)"; the note is derived from the store (never parallel state — ADR-0059 rule 2). **Q4 = disable + annotate:** the asked-for tier stays listed but `disabled`, annotated "not on this plan — answered on <applied>", and the selection falls back to the tier that answered (the store records `unavailable: { [asked]: answered }`; a later answer that honours the tier clears it). The inspector's model line stays `claude (<applied>)` (unchanged).
5. **The control.** In `BrainChip`'s popover, under the headline and body: a labelled `<select>` (`aria-label="thinking level"`, `data-testid="brain-menu-tier"`) listing `auto — quick for app replies, default for building` first, then `quick` / `default` / `complex` with `default` marked "(the viewer's default)", the current choice selected, an unavailable tier disabled with its annotation (AC4); changing it calls `set` and closes nothing (the popover stays so the user reads the level). Renders ONLY when the active brain is `'host'` and the seat exists — pinned with the D15 twin (no brain section, BYOK rows, local-URL field or mode segment appear; `hostSurfaces` and `platform-host` pins unchanged). The chip LABEL is unchanged (the 375 px header tripwire); the chip gains `data-tier` for tests.
6. **e2e on the built page (hosted fake).** The fake `sample` gains a `substitute` map (asked → answered) and keeps echoing `modelTierApplied`: (a) pick `complex` → one chess move → the recorded call carries `modelTier: 'complex'`; zero calls at the switch; (b) with `substitute: { complex: 'default' }` the popover shows the substitution note after the move; (c) the choice survives a reload (Q3's rung); (d) the chat harness (A2) shows no control.
7. **Real walk (owner, journaled).** On the artifact: pick `complex`, one move, read the popover and the inspector's `claude (<tier>)`; pick `quick`, one move; reload → the choice held. Records whether the owner's plan honours `complex`.

**Out of scope**: any choice of brain, provider, mode, key, URL, account or demo (D15's other sentences stand); a tier control for the `complete` brain (the contract has none); a per-app tier stored with the app (Q2 C is per PURPOSE, not per app); `sample.json` or tools; the chip label's wording; the playground/desktop BYOK model picker (GA scope, unrelated).

## Interview — Q1–Q4 (answered 2026-09-06: all four recommended defaults — folded into AC2/AC3/AC4/AC5 above)

- **Q1 — D15 amendment scope.** ✅ **Narrow:** the brain stays the host's; within a brain whose contract offers tiers the tier is the user's, from the chip. Every other D15 sentence stands. — or — Wider (say what).
- **Q2 — What the dropdown governs, and its default.** The kit today uses two tiers by PURPOSE (app replies `quick`, building `default`) for measured reasons (S3/S11 above).
  - ✅ **(B) One dropdown; the first entry is "auto — quick for app replies, default for building" (today's pins), the other three override EVERY turn.** Keeps chess at ~1 s until the user chooses otherwise; "auto" is labelled as Snug's pick, not as the viewer's default.
  - **(A, the literal ask) One dropdown, one tier for every turn, initial selection = the viewer's `default`.** Consequence: app replies move from `quick` (1.2 s median) to `default` (first text 4–6 s measured on a large prompt; the contract says 5–60 s) unless the user switches to `quick`.
  - **(C) Two dropdowns — app replies / building — each defaulting to today's pin.** Most control, most copy.
- **Q3 — Where the choice lives.** ✅ **This browser, this artifact origin** (`localStorage` — T1: 5 ms, 10 GiB quota; memory where storage is denied; NOT in the user file, so it is not exported and not written into the page on save). — or — In the user file (a settings row: travels with export/import and into the artifact on save; ignored on desktop/web). — or — This tab only.
- **Q4 — A tier the viewer's plan lacks** (learned only from `modelTierApplied`). ✅ **Keep it listed but DISABLED after the first substitution, annotated "not on this plan — answered on default"; the selection falls back to the applied tier.** — or — Hide it after the first substitution (the AC5 save-act pattern). — or — Keep it selectable, note only.

## Decisions & surprises

- **2026-09-06 — the contract has ONE knob.** There is no thinking/effort setting apart from `modelTier`; the three tiers ARE the thinking levels (quick = no thinking first; default/complex think before writing). The dropdown therefore lists exactly those three, labelled by what they do, not by model names the contract does not expose.
- **2026-09-06 — availability is per call, not per view.** `limits()` names no tiers; a plan that lacks `complex` is learned from `modelTierApplied` on the first answer. The chip cannot promise a tier at boot; it can only report what answered (Q4).
- **2026-09-06 — this is a D15 reversal by the owner, scoped narrowly.** The clause "not a control" was the owner's own (2026-09-05); the ask of 2026-09-06 reverses it for the tier only. ADR-0067 records it; the brain choice stays closed.
