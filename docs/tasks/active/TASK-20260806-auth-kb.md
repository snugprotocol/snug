## Spec (what & why)

The Dynamic Auth port (AL-02→AL-04) shipped the machinery: `useConnectedFetch` in the app template, the `net` frame, the auth wizard, and the `auth_wizard` render directive with parse-don't-trust scanning. But the **builder LLM has never been taught any of it** (code-map row 26 ⭕), and — the v1 review's blocker — the KB reaches the builder ONLY as top-5 keyword-scored sections from `searchKnowledge(query)`, so teaching that isn't retrievable at build time doesn't exist. AL-05 closes the knowledge gap **and proves delivery**: the builder learns to declare that an app requires auth (roadmap A5's `auth_required`, realized by the shipped directive mechanism — see Decisions), to design app code against `useConnectedFetch` with a graceful pre-connection state, to never place credentials in app code, and the retrieval path that serves this teaching at emission time is deterministically tested.

## Decisions & surprises

- **`auth_required` = the shipped directive mechanism.** Roadmap A5's "builder declares `auth_required`" is realized by teaching `auth_wizard` directive emission + connected-fetch design. The reserved `ERROR_CODES.AUTH_REQUIRED` + `authRequiredPayloadSchema` ("auth broker is v1.1") stay untaught — teaching a reserved, unwired code would teach vapor.
- **Retrieval is the delivery mechanism, so retrieval is tested (v2, from the review's blocker).** The app-builder tool serves top-5 keyword-scored sections (no stemming, heading hits ×2, ties keep document order, `90-*` sorts last). Teaching that can't win retrieval doesn't exist; AC10 makes that deterministic instead of live-sweep-only.
- **Hosts doctrine (v2, review MAJOR):** `declaredApiHosts` = the hosts the app's code calls — the builder always knows them because it wrote the fetch calls. The v1 "only when user-named" rule under-declared and could strand a NET_HOST_BLOCKED mismatch between the app's coded host and a docs-derived ceiling. Endpoints stay never-taught; minimal-hints now means "no hosts beyond what the app calls", not "no hosts".
- **Keyless public APIs are NOT supported at 1.0 (v2, review MAJOR — Gate-2 decision).** Every persisted spec is a five-kind credentialed discriminated union (`auth-schema.ts:35`, static kinds require `fields` min 1); connected-fetch fails closed (`NET_NOT_APPROVED`) for unapproved hosts; the builder cannot propose `fields` (omit-set). Teaching: prefer a credentialed provider when one fits; for a genuinely keyless provider, say so to the user and design the app with manual/demo data until keyless connections ship. Queued to next-steps: keyless-host support (spec-level `none` kind or optional-credential approval — AL-12 staging candidate) + **coordination flag: AL-09's "Crypto Portfolio (none/CoinGecko)" starter collides with this gap head-on and must resolve it (demo-key vs manual-data) at its own Gate 2**.
- **Seam formalized, not retired** (AC8). **Disclosure = honest copy** here; server twin to AL-10 (AC7).
