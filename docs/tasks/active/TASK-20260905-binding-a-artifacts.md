## Spec (what & why)

**What.** The host kit (`snug-host.html`, T2) learns to live inside a Claude artifact. Today it boots on the demo brain with the browser bucket; after this task, when `window.claude.use` exists and `sample` resolves (A1 — Claude Code / Cowork hosted artifacts) the probe pins **`sample`** as the brain and the page's own html republish as the durable record of the user's file; when `window.claude.complete` exists (A2 — claude.ai / Claude Desktop chat artifacts) it pins **`claude-complete`** as the brain and **`window.storage`** as the file's home. Export leaves through the artifact `downloads` seat as **`snug-user.snug.json`** (a wrapper: the `downloads` allowlist has no `.snug`), and the playground learns to import that wrapper everywhere. A **"your file" chip** beside the brain chip says where the file lives, in which host, and what a republish does to it. Apps are **handed in** by the agent as `snug-app-bundle/1` blocks embedded in the page: boot installs a new lineage as an owned, versioned, editable app and applies a changed html as a new version with data kept (never over a copy the user re-authored — that one is offered); `scripts/snug-embed.mjs` merges bundles into a live page mechanically so an edit is a republish, never a second runner. The nested runner stays exactly as it is (S1: `RUNNER_CSP` is enforced inside the artifact's nested frame); the embedder's narrower CDN policy becomes a knowledge-base rule and an embed-time lint (a loading aid, never a security control — R-21).

**Why.** This is the first demonstrable milestone of the program (T2 → **T4** → T6-Claude → owner E2E): a user with only the `snug` skill builds an app and sees it running inside the Claude they already pay for, with their file under their control (export any time) and every invariant where it was — the sandbox (nested, CSP enforced), the credential boundary (no keys exist in the kit), the one file. Nothing here is an MCP server (ADR-0061).

**Measured facts this design stands on (T1, 2026-09-05):** `sample` on `quick`: median 1.2 s, 48/48 legal chess moves, consent exactly once, every `quick` reply code-fenced (so `sample()` TEXT + Snug's graduated parser is the one parse path; `sample.json` unfences but reports neither `truncated` nor `modelTierApplied`); one concatenated user turn ≡ two turns; `limits().maxPromptBytes` = 65,536; the files form of `artifact.publish` is `capability_disabled` in the owner's own view; html republish of 2 MiB = 1.8 s + a view reload, byte-identical after; `localStorage` 5 ms with a 10 GiB quota at the artifact origin; `window.storage` persists across reloads but is **per view** (in-chat and published link hold separate stores); in chat `<a download>` is inert, `navigator.clipboard` blocked, `execCommand('copy')` works; both viewers block jsDelivr `/gh/` and unpkg, allow jsDelivr `/npm/` and cdnjs, and the hosted viewer blocks every CDN stylesheet/font. **S11 (2026-09-05, this task's Gate 2):** the builder's whole-app turn works on `sample` — 8 of 8 calls that reached Claude returned a COMPLETE fenced document (33 KB chess edit ≈ 94 s on `default`, 107 s on `quick`; a 51 KB app came back as a complete 54 KB document in 223 s with a 70 s first token; a fresh 10 KB build in 40 s), `truncated: false` on all eight, every tier honoured, the input cap inclusive at exactly 65,536 UTF-8 bytes, over-cap refused in 0 ms with `prompt_too_large` and no usage. **Unmeasured, owed here:** `window.claude.complete` (latency, JSON, consent, truncation — only detected); `RUNNER_CSP` enforcement inside the CHAT nested runner; the hosted `downloads.save` path; whether a session-side html republish preserves the page's `snug-db` block; **what the hosted viewer injects into the document before the page's script runs** (the shape of the injected runtime — decides nothing, but the first walk records it).

**Acceptance criteria** (each becomes at least one test; the real-runtime rows are journaled walks with the artifact URL):

1. **`sample` brain (A1).** When `window.claude.use` exists, the probe resolves `sample`, `artifact` and `downloads` in one `Promise.all` behind one named guard (sized from the contract's 10 s; the walk journals the real answer time); `sample` resolved pins `{ kind: 'host', label: 'Claude · this artifact’s viewer', streaming: true, tools: false, maxPromptBytes }` (`limits().maxPromptBytes`, falling back to 65,536 when `limits()` rejects), and `createTurnAdapter`'s `'host'` arm hands back the adapter **for the purpose it was asked for** (the seat gains `chatAdapter?`; absent → `adapter`): the app adapter uses `modelTier: 'quick'`, the builder/inferrer adapter `'default'` (a per-purpose host decision, D15 — never a control; S11 confirmed it: the same 33 KB rewrite took 94 s on `default` and 107 s on `quick` — output dominates, so `quick` buys nothing on builder turns while `default` thinks first; the builder surface shows its thinking state from the call until the first token, which S11 put at 5 s for a 33 KB app and 70 s for a 51 KB one). Both adapters concatenate `system` + the messages into **one user turn** through ONE shaper (`brains/prompt.ts`, also the budget's measuring stick — AC3); call `sample()` TEXT with `cache: false`; forward `onText` as deltas to `onDelta`; map `truncated: true` → `stopReason: 'max_tokens'` (never a parse strike — lesson 2026-08-12); map every `SampleError` to a named `AdapterError` (`not_granted` / `sampling_disabled` → `CONSENT_DENIED`, retryable false; `rate_limited` → retryable **false** with "back off" copy — the runner must never loop; `prompt_too_large` → a named refusal that names the byte count; `cancelled` → `ABORTED`; `empty_completion` / `invalid_json` / `refused` / `upstream_error` named); **never call `sample` on load** — the first think is the first call. The runtime contract rides inside that user turn exactly as `buildHostSystemPrompt({appRuntime})` assembles it today, after the existing `runtimeContractSchema` validation and size caps (unchanged, pinned by the test that the bytes reaching the fake `sample` equal the playground's assembled system text + separator + wire); the authority downgrade (system slot → user turn, ADR-0018 D3) is disclosed in ADR-0065 and gets its own threat-model delta row in T7 (R-24/R-37 were written for other channels). T4 proves the `complete` adapter, the `window-storage` backend and the chip under the chat harness (in-page fakes on the built html) and leaves the real chat walk owed.
3. **Prompt budget — budget or refuse, never a cut app.** The cap is inclusive at exactly `maxPromptBytes` UTF-8 bytes (S11 arm F: 65,536 accepted; arm G: 65,537 → `prompt_too_large` in 0 ms, no consent, no usage). The measurement is taken on **the identical string the adapter sends** (`brains/prompt.ts` exposes `measurePrompt(system, messages)`; the builder's host arm calls it before `runAgentTurn` — lesson 2026-08-05: a bound re-derived upstream of the sent string is a second bound). Under a pinned `maxPromptBytes`: history is dropped oldest-first, then the docs and schema sections truncate with the existing marker (they are read, not rewritten) — but **the current app html either rides WHOLE or the edit turn is refused** with a named message ("this app is 117 KB; editing inside this artifact fits apps up to ~58 KB — export your file and edit it in the playground"), because S11 arm F showed the failure mode: a chess context cut mid-file plus "write the ENTIRE file" returned a plausible full-length app (ratio 1.01) whose tail the model invented — a silent rewrite of code it never saw, landing as the next version. `appContext.ts` gains only the "html whole or absent" switch; the byte arithmetic lives in the shaper. 4. **`window-storage` backend (A2).** `PersistenceKind` gains `'window-storage'` (append; `DbPersistence` in `driver.ts:24` and both `persistence` getters widen with it; `storageDisclosure`'s switch becomes exhaustive with a `never` arm). The backend stores base64 chunks under **generation-numbered** keys `snug-user/<file>/<gen>/<n>` plus a manifest `snug-user/<file>` carrying the magic, the live generation, the chunk count and sha-256; `save` writes the NEW generation's chunks, flips the manifest, then deletes the old generation (a torn write leaves the previous generation complete — lesson 2026-08-03's A/B discipline); `load` reads the manifest's generation and falls back to the other complete generation; `load` returns `undefined` **only** when `list()` proves the manifest key absent (S10: `get` of a missing key throws a generic message — the message alone is never "fresh"); a manifest whose live generation is incomplete AND no other generation is complete **throws** (`corrupt`, never a pristine file — lesson 2026-08-03/22); `backend.save` call counts are asserted through a real `openUserDb` round trip; the 20 MB text cap refuses with a named error and offers export. Torn-write fixture: a fake `set` that throws on chunk k → the previous bytes still load.
5. **`artifact-html` durable record (A1).** `PersistenceKind` gains `'artifact-html'`. The working copy stays in the probed browser bucket (OPFS → IDB → memory, unchanged); the record wraps it: `load(USERDB_FILE)` is bucket-first and, when the bucket has no file and the page carries a `<script type="text/plain" id="snug-db">` block (manifest line: magic, byte length, sha-256, **a monotonic save counter and an ISO instant**; then the base64), the block's bytes seed the bucket with ONE explicit, counted `bucket.save` at load (only for `USERDB_FILE`, never the legacy name — `userdb.ts:1299`); a block that fails its own sha is `corrupt` and says so. If the bucket has a file AND the block differs, nothing is overwritten: the chip shows the divergence **with direction** ("this browser’s copy is newer than the page’s" / "older", from the counter) and two acts — "keep this browser’s copy" (marks dirty) and "load the page’s copy" (first copies the bucket file to `user.snug.before-load`, then seeds). A bucket file with NO block on the page is simply dirty, never divergence. **"save to this artifact"** is an explicit act on the chip: it fetches the page's **canonical source** with `fetch(location.href, { cache: 'no-store' })` (the hosted viewer's `connect-src 'self'` admits it; the contract forbids serializing the live DOM — `artifact.d.ts:155-159`: `outerHTML` carries the viewer's injected runtime), verifies the fetched text with the shared top-level tokenizer (exactly one inline module script, the `snug-host-build` stamp equal to the DOM's, only `snug-db` / `snug-app-bundle+json` data blocks otherwise) and **refuses the save with a named reason if that check fails — never falls back to `outerHTML`**; then splices the current bytes as base64 into the `snug-db` block (inserting the block before `</body>` when the page has none — the build ships NO placeholder, so `check-host-kit`'s "exactly one inline module script" rule stays true of `dist/`), refuses when the **projected page** (`pageBytes + ⌈userBytes·4/3⌉ + bundleBytes`) would exceed 16 MiB minus a margin (the message names the three parts; export offered), stashes the conflict/result note in `sessionStorage`, and calls `artifact.publish(html)`. `conflict` → the view reloads per contract; the bucket keeps the working copy, and the stashed note renders after reload: "someone published first — your copy is safe here; save again". `too_large` from the runtime is the same named refusal. `not_writer` / `not_granted` / `artifact === null` → read-only: the act is **present until the first refusal** (the contract gives no writability signal before a publish, and Q3 forbids publishing at boot), then hidden, and the chip says "read-only view — export to keep a copy". **The files form is NOT in T4** (review A2: a second durable location boot never reads; every measurement so far says `capability_disabled`) — recorded as a residual in ADR-0065 §2's amendment with the S4(b) re-run as its precondition. Never on a timer, never on `pagehide`. **`artifact-static`:** when `window.claude.use` exists but `sample` AND `artifact` both resolve `null` (the page served top-level on the artifact host — `claude.d.ts:17-20`), the binding is `'artifact-static'`: plain bucket, demo brain, no save act, chip "a copy of the artifact page — nothing saves here; export to keep".

## Decisions & surprises

- **2026-09-05 — the files form is out of T4 (deviates from the parent's D3 "retried once at boot" and from Q3's "tried on the first save").** The contract forbids publishing on load, and a files-form success would create a second durable record the html-block boot never reads (review A2). It stays a residual in ADR-0065 §2 with the S4(b) re-run as its precondition.
- **2026-09-05 — `artifact-html` is a record over the bucket, not a replacement backend.** S4b measured the bucket at 5 ms and the republish at 1.8 s + a reload; a backend whose every debounced `save` republished would reload the view on every keystroke. The bucket is the working copy; the republish is the durable act (Q3).
- **2026-09-05 — the page source for a republish is fetched, never serialized.** `artifact.d.ts:155-159` says so outright (`outerHTML` carries the viewer's injected runtime), and T1's S4b note ("the viewer injects its runtime into a page the page itself published") is the measurement behind it. Verification by the shared tokenizer, refusal on mismatch; the first walk records what is injected.
- **2026-09-05 — S11 measured (probe `38974070-6821-43fd-b0a4-7a98f956aa00`, `results/s11`, run 21:51–22:06Z, 10 calls, 0 db failures).** `limits()` = `{maxPromptBytes: 65536, tools: {maxCount: 16}}` (no `images`). Consent dialog seen on call #1 only (call took 93.4 s including the dialog; first token 4.1 s). Inputs: system (tool-free builder layers + `WEBLLM_BUILD_SUFFIX`) 4,651 B; chess turn 37,736 B; flying-pig turn 56,446 B; trade-copilot turn 122,116 B; fresh build 4,814 B. **A** chess edit, `default` ×2: 93.4 s / 94.6 s, first token 4.1 / 5.8 s, 165 `onText` calls, both complete fenced documents (33,011 / 32,842 B, ratio 1.01), `truncated: false`, tier honoured, a one-line explanation after the fence. **B** same on `quick` ×2: 107.2 / 107.1 s, first token 1.1 / 0.9 s, complete, tier honoured (one reply opened with a sentence before the fence — the extractor's fence rule handles it). **C** flying-pig, `default`: 223.1 s, first token 69.6 s, complete 54,067 B (ratio 1.05), not truncated. **D** fresh pomodoro build: 39.9 s, complete 10,599 B. **E** 122,116 B: `prompt_too_large` "the prompt exceeds the 64 KiB limit", 0 ms, no `onText`, nothing spent. **F** exactly 65,536 B (chess cut with the marker + space padding): accepted, 91.1 s, complete 32,848 B (ratio 1.01 — the cut tail was re-invented, see AC3). **G** 65,537 B: `prompt_too_large`, 0 ms. **H** chess on `complex`: 114.7 s, first token 3.7 s, complete, tier honoured. **Consequences:** builder tier `default` (AC1); budget-or-refuse for the app html (AC3); the output ceiling was not reached at 54 KB and stays an undocumented residual (the ADR keeps the sentence, softened to "not hit up to 54 KB"); every reply is code-fenced, so `extractAppHtml`'s fence path is the normal path; the builder needs its thinking state for 5–70 s before the first token.
- **2026-09-05 — `agent:<lineage>` is prose, not schema.** `install_source` is free TEXT in `snug_apps` (SPEC-1.0 §storage; `userdb-schema.ts:230`); `share:<lineage>` landed the same way (ADR-0063 §5).
