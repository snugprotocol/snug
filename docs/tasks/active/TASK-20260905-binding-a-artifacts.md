## Spec (what & why)

**What.** The host kit (`snug-host.html`, T2) learns to live inside a Claude artifact. Today it boots on the demo brain with the browser bucket; after this task, when `window.claude.use` exists (A1 — Claude Code / Cowork hosted artifacts) the probe pins **`sample`** as the brain and the page's own html republish as the durable record of the user's file; when `window.claude.complete` exists (A2 — claude.ai / Claude Desktop chat artifacts) it pins **`claude-complete`** as the brain and **`window.storage`** as the file's home. Export leaves through the artifact `downloads` seat as **`snug-user.snug.json`** (a wrapper: the `downloads` allowlist has no `.snug`), and the playground learns to import that wrapper everywhere. A **"your file" chip** beside the brain chip says where the file lives, in which host, and what a republish does to it. Apps are **handed in** by the agent as `snug-app-bundle/1` blocks embedded in the page: boot installs a new lineage as an owned, versioned, editable app and applies a changed html as a new version with data kept; `scripts/snug-embed.mjs` merges bundles into a live page mechanically so an edit is a republish, never a second runner. The nested runner stays exactly as it is (S1: `RUNNER_CSP` is enforced inside the artifact's nested frame); the embedder's narrower CDN policy becomes a knowledge-base rule and an embed-time lint.

**Why.** This is the first demonstrable milestone of the program (T2 → **T4** → T6-Claude → owner E2E): a user with only the `snug` skill builds an app and sees it running inside the Claude they already pay for, with their file under their control (export any time) and every invariant where it was — the sandbox (nested, CSP enforced), the credential boundary (no keys exist in the kit), the one file. Nothing here is an MCP server (ADR-0061).

**Measured facts this design stands on (T1, 2026-09-05):** `sample` on `quick`: median 1.2 s, 48/48 legal chess moves, consent exactly once, every `quick` reply code-fenced (so `sample()` TEXT + Snug's graduated parser is the one parse path; `sample.json` unfences but reports neither `truncated` nor `modelTierApplied`); one concatenated user turn ≡ two turns; `limits().maxPromptBytes` = 65,536; the files form of `artifact.publish` is `capability_disabled` in the owner's own view; html republish of 2 MiB = 1.8 s + a view reload, byte-identical after; `localStorage` 5 ms with a 10 GiB quota at the artifact origin; `window.storage` persists across reloads but is **per view** (in-chat and published link hold separate stores); in chat `<a download>` is inert, `navigator.clipboard` blocked, `execCommand('copy')` works; both viewers block jsDelivr `/gh/` and unpkg, allow jsDelivr `/npm/` and cdnjs, and the hosted viewer blocks every CDN stylesheet/font. **S11 (2026-09-05, this task's Gate 2):** the builder's whole-app turn works on `sample` — 8 of 8 calls that reached Claude returned a COMPLETE fenced document (33 KB chess edit ≈ 94 s on `default`, 107 s on `quick`; a 51 KB app came back as a complete 54 KB document in 223 s with a 70 s first token; a fresh 10 KB build in 40 s), `truncated: false` on all eight, every tier honoured, the input cap inclusive at exactly 65,536 UTF-8 bytes, over-cap refused in 0 ms with `prompt_too_large` and no usage. **Unmeasured, owed here:** `window.claude.complete` (latency, JSON, consent, truncation — only detected); `RUNNER_CSP` enforcement inside the CHAT nested runner; the hosted `downloads.save` path; whether a session-side html republish preserves the page's `snug-db` block.

**Acceptance criteria** (each becomes at least one test; the real-runtime rows are journaled walks with the artifact URL):

1. **`sample` brain (A1).** With `window.claude.use` present, the probe pins `{ kind: 'host', label: 'Claude · this artifact’s viewer', streaming: true, tools: false, maxPromptBytes }` (from `sample.limits()`), and `createTurnAdapter`'s `'host'` arm hands back an `AgentAdapter` that: concatenates `system` + the messages into **one user turn** (S3 arm a — the contract has no system slot; ADR-0018's authority downgrade is disclosed in the ADR); calls `sample()` TEXT with `cache: false`, `modelTier: 'quick'` for app envelopes and `'default'` for builder turns (a per-purpose host decision, D15 — never a control; S11 confirmed it: the same 33 KB rewrite took 94 s on `default` and 107 s on `quick` — output dominates, so `quick` buys nothing on builder turns while `default` thinks first; the builder surface shows its thinking state from the call until the first token, which S11 put at 5 s for a 33 KB app and 70 s for a 51 KB one); forwards `onText` as deltas to `onDelta`; maps `truncated: true` → `stopReason: 'max_tokens'` (never a parse strike — lesson 2026-08-12); maps every `SampleError` to a named `AdapterError` (`not_granted` / `sampling_disabled` → `CONSENT_DENIED`, retryable false; `rate_limited` → retryable **false** here with copy "back off" — the runner must never loop; `prompt_too_large` → a named refusal that names the byte count; `cancelled` → `ABORTED`; `empty_completion` / `invalid_json` / `refused` / `upstream_error` named); **never calls `sample` on load** — the first think is the first call (the consent dialog's position is journaled). Negative: the adapter reads no `snug_secrets`, no key, no URL (C1) — pinned by the existing `hostBrain.test.ts` shape plus a byte scan of what reaches the fake `sample`.
2. **`claude-complete` brain (A2).** With only `window.claude.complete`, the probe pins `{ label: 'Claude · this chat', streaming: false, tools: false }`; the adapter sends the same one-turn prompt through `complete(prompt)` and parses the text through the same path; `host-ready.capabilities.streaming` reads `false` in the nested frame (the T2 forward, now exercised); a rejection or a non-string reply is a named error, never a hang.
3. **Prompt budget — budget or refuse, never a cut app.** The cap is inclusive at exactly `maxPromptBytes` UTF-8 bytes (S11 arm F: 65,536 accepted; arm G: 65,537 → `prompt_too_large` in 0 ms, no consent, no usage). Under a pinned `maxPromptBytes` the builder measures `bytes(system + separator + contextBlock + separator + message)`; history is dropped oldest-first, then the docs and schema sections truncate with the existing marker (they are read, not rewritten) — but **the current app html either rides WHOLE or the edit turn is refused** with a named message ("this app is 117 KB; editing inside this artifact fits apps up to ~58 KB — export your file and edit it in the playground"), because S11 arm F showed the failure mode: a chess context cut mid-file plus "write the ENTIRE file" returned a plausible full-length app (ratio 1.01) whose tail the model invented — a silent rewrite of code it never saw, landing as the next version. A 51 KB app fits whole (arm C: 56,446 B in, a complete 54 KB document out). Pinned by tests: a 51 KB app under the cap produces a prompt the fake `sample` accepts with the html intact; a 117 KB app is refused before any call is made (zero `sample` invocations); with no cap the bytes are unchanged (web positive twin, the 140,000-char rule untouched).
4. **`window-storage` backend (A2).** `PersistenceKind` gains `'window-storage'` (append; `never`-arm in `storageDisclosure`). The backend stores base64 chunks under `snug-user/<file>/<n>` plus a manifest `snug-user/<file>` carrying the magic, chunk count and sha-256; `load` returns `undefined` **only** when `list()` proves the manifest key absent (S10: `get` of a missing key throws a generic message — the message alone is never "fresh"); a manifest with a missing or mismatched chunk **throws** (`corrupt`, never a pristine file — lesson 2026-08-03/22); `save` is atomic in the manifest-last sense (chunks, then manifest); `backend.save` call counts are asserted through a real `openUserDb` round trip; the 20 MB text cap refuses with a named error and offers export.
5. **`artifact-html` durable record (A1).** `PersistenceKind` gains `'artifact-html'`. The working copy stays in the probed browser bucket (OPFS → IDB → memory, unchanged); at boot, if the bucket has no file and the page carries a `<script type="text/plain" id="snug-db">` block, the block's bytes seed the bucket (magic-checked; a block that fails its own sha is `corrupt` and says so). If the bucket has a file AND the page block differs, nothing is overwritten: the chip shows the divergence and two acts ("keep this browser’s copy" / "load the page’s copy"), the sync resolver's own shape. **"save to this artifact"** is an explicit act on the chip: it captures the page's pristine source (read before React mounts, never the live DOM), splices the current bytes as base64 into the `snug-db` block, refuses above **8 MiB** of user bytes with export offered, then `artifact.publish(html)`; **the files form (`publish({"data/user.snug": …})`) is tried on the FIRST save act** and used thereafter if it works (no reload), else html — never probed at boot (a publish on load violates the contract). `conflict` → the page reloads per contract; the bucket keeps the working copy, so the note says "someone published first — your copy is safe here; save again". `not_writer` / `not_granted` → read-only: the act is hidden, the chip says "read-only view — export to keep a copy". Never on a timer, never on `pagehide`.
6. **Export.** Where the platform carries the kit's `saveFile` seat, `downloadBlob` (unchanged) hands bytes to it; the kit's seat wraps a user file (SQLite or `SNUGENC1`) as `{"format":"snug-user-file/1","sha256":…,"bytesBase64":…}` named `snug-user.snug.json` and calls `downloads.save`; an app bundle (already JSON) is saved as `<stem>.snug.json`; `declined` is silent, every other code is a named note. In chat (no `downloads`) the seat copies the wrapper text with `execCommand('copy')` and the note says so. `sniffSnugFile` learns `'user-file-wrapper'`; `unwrapUserFile` verifies the sha (mismatch → `corrupt`); `dispatchOpenedSnugFile` and the Settings picker unwrap before the existing user-file path — so the playground and the desktop import a file the kit exported (program AC1's last clause).
7. **"Your file" chip (D8).** Beside the brain chip, on every route, disclosure only, copy pinned per `binding × kind`: `artifact`+`artifact-html`: "in this artifact — Anthropic-hosted; saved when you save it; a republish from Claude Code rewrites it unless the agent merges it; export any time" · `artifact-chat`+`window-storage`: "in this chat’s page storage — this view only; the published link keeps its own; copy to move or keep it" · `file`/`local-host`+`opfs|idb`: the T2 sentence · `memory`: the T2 sentence. Web and desktop render nothing new (positive twin).
8. **Hand-in.** The page may carry `<script type="application/snug-app-bundle+json" data-lineage="<uuid>">` blocks (JSON with every `<` written `<`, so `</script` cannot occur). Boot (after the user db opens) parses each with `parseAppBundle` (strict; a bad block is a named note, never a crash); a **new lineage** installs as an **owned** app with `install_source = 'agent:<lineage>'` (find-or-create; the builder-chat semantics — editable, versioned, no "unowned" branch, no `shared` provenance since Binding A carries no connections, D4); an installed lineage whose bundle id differs lands the html as a **new pinned version** through the bundle update act (data, chat, docs kept; the previous version stays revertable), and a note in the hub says "updated by your agent · v N". Idempotent on bundle id (a reload installs nothing twice). Hostile fixtures: a bundle whose html contains `</script>` and `<!--`; two lineages; a stale `snug-db` block beside them; a block with a lineage that spells `starter:`/`share:` (refused by the UUID rule).
9. **`snug-embed.mjs`.** `node scripts/snug-embed.mjs <live.html> --bundle app.json [--bundle …] [--out file]` merges bundles into a live page by lineage (replace same-lineage, append new), **keeps the `snug-db` block and every block it does not own byte-for-byte**, escapes `<`, refuses a page it cannot parse or a bundle over the schema caps, and **lints the bundle html against the Binding-A CDN rule** (scripts only from `https://cdn.jsdelivr.net/npm/` or `https://cdnjs.cloudflare.com/`; no unpkg, no `/gh/`, no external stylesheets or fonts) — a named warning by default, a refusal with `--strict`. ### Design notes (what the code reading settled)

- **Where the brains live.** `apps/host/src/brains/{prompt,sample,complete,errors}.ts`. `prompt.ts` is the one turn-shaper both use: `system` + `messages` → `[{role:'user', content}]` with the runtime contract ahead of the wire (S3 proved one turn ≡ two). Tool turns cannot occur (`tools: false` → the builder's tool-free arm, T2). `maxOutputTokens` cannot be forwarded (no seat in the contract) — recorded as a residual; `truncated` is the signal.
- **The probe becomes async only where a host answers.** `probeBrain` calls `claude.use('sample')` ONLY when `window.claude.use` is a function (the viewer answers fast; `use` resolves `null` after 10 s where nothing answers, which must never gate a plain page's boot). `null` → the demo brain with the legs recorded (`sample: 'detected-unavailable'`), and the chip says so.
- **Storage is two seams, not one.** A2's `window-storage` IS a `PersistenceBackend` (the file's only home). A1's `artifact-html` is a **record over the probed bucket**: `createArtifactRecord({ bucket, block, publish })` → a `PersistenceBackend` whose `kind` is `'artifact-html'` (the disclosure), whose `load` is bucket-first with block seeding, whose `save` is the bucket's save plus a dirty flag; the **publish** is a separate explicit act the chip calls. `openUserDb`'s debounced `save` count therefore stays exactly the bucket's (asserted).
- **Pristine page source.** `main.tsx` captures `'<!doctype html>\n' + document.documentElement.outerHTML` before `createRoot` (the module script is the only script; the DOM at that instant is the parsed static page). The e2e proves the round trip: capture → splice → serve → boot → same stamp, same blocks, the inliner's refusals still hold (`</script` cannot appear in a base64 block; the bundle blocks are `<`-escaped).
- **Export rides the existing `saveFile` seat** (`downloadBlob` prefers it — W2b item 6), so the playground's export button and the share sheet change nothing; the kit's seat decides wrapper vs bundle by `sniffSnugFile`. Chat's copy path is the same seat with a different implementation (`execCommand('copy')`).
- **Hand-in reuses ADR-0063's install/update acts** with a new `provenance: 'agent'` parameter on `installAppFromBundle` / `updateAppFromBundle` (`agentInstallSource(lineage)`), so DDL replay, docs absent-only, contract-in-the-same-call and the half-made-app rollback are inherited, and `declareSharedConnections` is skipped for `agent` (D4 — a bundle with `connections` under Binding A is a named refusal). The hub's dedup map already keys on `install_source`.
- **One block grammar.** `scripts/lib/page-blocks.mjs` (pure string functions: find/replace/append the `snug-db` block and the bundle blocks, escape/unescape) + `page-blocks.d.mts` (the `release-desktop.d.mts` precedent) — imported by `snug-embed.mjs`, by `apps/host/src/storage/artifactHtml.ts` and `handin.ts` (Vite resolves `.mjs`), and by `check-host-kit.mjs`'s tokenizer tests. `escapeForInlineScript` moves here from `build-starters-pkg.mjs` (which imports it back).
- **Chip copy is derived, never parallel** (ADR-0059): `custodyDisclosure(platform.binding, platform.userdbBackend?.kind, readOnly)` in `platform/copy.ts`, exhaustive `never` arms; the chip reads the platform seats and a small `custodyStore` (dirty / read-only / divergence) the record updates.

## Decisions & surprises

- **2026-09-05 — the files form is probed on the first SAVE act, not at boot (deviates from the parent's D3 "retried once at boot").** The contract forbids publishing on load ("publish only after a viewer acts, never on load"); a files-form probe IS a publish. The first explicit save is the earliest honest moment. ADR-0065 §2 gets a dated amendment.
- **2026-09-05 — `artifact-html` is a record over the bucket, not a replacement backend.** S4b measured the bucket at 5 ms and the republish at 1.8 s + a reload; a backend whose every debounced `save` republished would reload the view on every keystroke. The bucket is the working copy; the republish is the durable act (Q3).
- **2026-09-05 — S11 measured (probe `38974070-6821-43fd-b0a4-7a98f956aa00`, `results/s11`, run 21:51–22:06Z, 10 calls, 0 db failures).** `limits()` = `{maxPromptBytes: 65536, tools: {maxCount: 16}}` (no `images`).
