## Spec (what & why)

Today an app a user built (or installed) lives only in their own `.snug` file. There is no way to hand it to another person — not the code, not the connection shapes it needs, not the wiki the app accumulated while it was built. The only per-app export in the tree (`SHOW_APP_EXPORT`, hidden) is a SQLite data slice byte-indistinguishable from a whole user file; double-clicking it today would offer to **replace** the recipient's entire file (verified: `exportDb.ts:30` emits SQLite magic → `openFile.ts:34,84` confirm-then-replace). That latent data-loss shape is the first thing this task retires.

This task adds **app sharing**: from the app's own header, one share control produces a **standalone app bundle** — the app's current code, its connection requirements *as shapes* (never a credential, never a grant, never the user's LAN address), its registered data schema (structure, no rows), and the wiki docs the app accumulated, each doc individually opt-out with the design docs on by default. Everything personal stays home by construction: app data rows, secrets, version history, chat threads, model pins. The bundle travels two ways: as a **`.snug` attachment** the sharer sends however they like (phase 1 — no server anywhere), or as a **link** (phase 2 — hosted but *blind*: the bundle is AES-256-GCM encrypted in the sharer's browser, the relay stores ciphertext it cannot read, and the key rides only in the URL fragment which never reaches any server). On the receiving side — a person who may never have seen Snug — the bundle appears as a card in a new **"shared with you"** shelf between "your apps" and "starter apps", opens read-only exactly as a starter does (browse the app, read its docs, see what it tells the AI), and installs with the same install act starters use. Install is find-or-create on a share lineage, so a re-share of an improved app is offered as an **update that keeps the recipient's data** (ADR-0045's channel, generalized).

The framing that makes this small: **a shared app is a starter that travels.** The hub already knows how to show, preview, install, declare connections for, seed docs into, and update a starter. This task adds the untrusted-origin version of that path, with the review posture ADR-0016 already specified for it.

### Interview (owner) — ANSWERED 2026-09-04: "go with defaults" (every default below stands)

- **Q1 — the link's host.** The hosted playground has no backend (ADR-0013) and `apps/server` is not deployed anywhere; ADR-0052 rejected a Cloudflare Worker receiver by name. Pick one (full argument in [ADR-0064 draft](../../decisions/0064-blind-share-relay.md)):
  - **A (recommended) — a *blind* relay.** A ~150-line Cloudflare Worker + R2 (`apps/share-relay`, same Cloudflare account as the Pages deploys) storing **ciphertext only**, ≤ 1 MiB per bundle, 30-day TTL, unguessable 128-bit ids, IP rate-limited, no listing, no accounts, no content logs. The key never leaves the link's fragment, so "we collect nothing" survives *in substance* and the falsifiability claim becomes "one blind endpoint, verifiable by reading the Worker". Needs ADR-0064 amending ADR-0013; deployed only on an explicit owner ask; owner operates it. Residual: a 1 MiB encrypted blob drop is a generic anonymous file host for 30 days.
  - **B — self-contained links (zero backend).** The compressed bundle rides in the URL fragment. **Breaks on Telegram (4 096 chars), Discord (2 000), SMS, X, Outlook line-wrapping** — a typical bundle is 15–30 KB of URL. Rejected as primary; possible hidden self-hoster fallback.
  - **C — attachment only at launch; link parked** (ADR-0052's shape). Phase 1 ships either way.
  - **D (reviewer's addition) — the sharer's own sync origin.** Upload the ciphertext to the sharer's configured Dropbox origin (the provider exists) and mint a Dropbox shared link + `#key`. No Snug endpoint, ADR-0013 unamended, works in every messenger. Only sharers with an origin connected can make links, and Dropbox content-link CORS for web recipients needs a 30-minute probe before it can be promised.
  - **Not viable:** running `apps/server` in production for this — a whole authenticated server for one blob store.
- **Q2 — file extension.** `.snug` for bundles too (one brand; the first bytes say what it is — the open path sniffs SQLite / `SNUGENC1` / JSON) vs a distinct `.snugapp`. **Default: `.snug`.**
- **Q3 — update semantics.** Offer "update · keeps your data" when a recipient re-receives a newer bundle of an installed lineage (new pinned version, docs absent-only, declared-only connection refresh) — or only "open installed / install as a copy" at v1? **Default: include the update act** (AC12).
- **Q4 — Settings import.** A third button "add shared app" beside export/import, with BOTH importers sniffing and pointing at each other on a mismatch — or one sniffing importer? **Default: third button + mutual sniff.**
- **Q5 — link lifetime, size, revocation (phase 2).** 30 days / 1 MiB; upload returns a revoke token the sharer's file keeps so the share sheet lists active links with "revoke". **Default: yes** (AC15, AC22).
- **Q6 — the runtime contract (review BLOCKER 1).** A bundle's `contract` is the app's LLM system-slot text (overview, persona, state/response guidance, ≤ 2 560 bytes). ADR-0018 D3 forbids system-slot text arriving on an untrusted channel — `importUserDb` DROPS foreign contracts for exactly this reason. Options: **(a)** drop it at install — the shared app runs on the lean generic layers until its owner re-authors it (a quality regression for every shared AI-driven app, and `needsSynthesizedContract` fires only on the first build); **(b, recommended)** carry it, and make it **reviewed text**: the preview's rail shows "what this app tells the AI" verbatim as plain text, install requires having opened the preview, and ADR-0063 records the ADR-0018 amendment ("a contract may arrive on the share channel only through the preview-then-install act; never through import"). The threat-model delta names "third-party system-slot text" as the residual either way.
- **Q7 — docs defaults (review MAJOR 6).** You asked for docs ON by default. The wiki is the app's *living memory*: `memory` is defined as "durable user preferences you learned" and `vision` as "what the user wants, in their terms"; Telepath/Gmail/Ledger memory pages hold contact names, mail summaries, account names. **Default: per-doc checkboxes with size + first line; `vision`, `requirements`, `plan`, `build-prompt`, `lessons`, `next-tasks` ON; `memory` OFF**, plus the sentence "docs may contain what this app learned about you — glance before you share". Say the word and all seven default ON.

```

        │ download .snug ─────────────────────────┼──►│ double-click │                        └───────┬────────┘
        │ share… (OS sheet / AirDrop)              │   │ or Settings  │                                │ installAppBundle
        └─ copy link: encrypt(key) → relay(id) ────┘   └──────────────┘                        generic starter chain,
                       key stays in the fragment                                               'shared' provenance
```

**Bundle = JSON, `.snug`** (ADR-0063 §2). Strict zod at the boundary (C5), one payload for both transports, first-byte sniff retires the replace-your-file shape.

**Trust** (ADR-0063 §3). The bundle is the untrusted declaration channel ADR-0016 clause 6 named. `'shared'` is a sixth provenance/channel — never `'starter'` reused (trust laundering). Every declaration passes `admitConnectionRequirement({ channel: 'shared' })` at install and again at the db write boundary through the playground's composition-root gate. The HTML is exactly as trusted as an LLM-built app: C2's sandbox is unchanged. The NEW things the threat-model delta must name: a third party authors code that runs in the user's hub (residual: token spend, but only after the explicit "run with AI" / install acts; a connection the user may approve after strong review; mutating connected calls still confirm), and — iff Q6 = b — third-party system-slot text admitted only through the preview-then-install act.

**Inbox** (ADR-0063 §4, revised): memory first; persisted on an explicit act; refuse-not-evict at the cap.

**Read-only preview** rides the starter's route shape; `isUnownedId` for ownership branches, `isSharedId` additionally strips the LLM transport.

**Update** generalizes ADR-0045's act with a per-app `sharedBundle:<appId>` marker, never byte-equality (lesson 2026-08-21).

**Link (phase 2)** = blind relay + `snug://` via the deep-link plugin's seats (Q1).

## Decisions & surprises

- **2026-09-04 — ADR-0013/ADR-0052 are the link path's real constraint, not the tooling.** The playground is static (Pages direct upload; no Worker/KV/R2 anywhere); `apps/server` is never deployed. A blind relay is the only hosted shape that keeps "we collect nothing" true in substance; it still needs its own ADR and an owner call (Q1). The reviewer added option D (sharer's own sync origin).
- **2026-09-04 — the hidden per-app export is a latent data-loss shape** (verified by the reviewer: SQLite magic → confirm-then-replace). Retired by the JSON bundle + sniff; the control is deleted with its tests classified.
- **2026-09-04 — sample data needs no seat; builder-seeded reference rows are a real gap.** Sample mode lives in `app.html`; but LLM-built apps rely on host-applied schema (`schema-apply.md`), and any `INSERT` the builder ran is in the migration log, not the registry — lookup tables arrive empty. v1 states it in the sheet; shipping the migration log is a follow-up opt-in.
- **2026-09-04 — `'shared'` is a new provenance, not `'starter'` reused** (ADR-0016's rejected alternative D one layer down). **And it needs NO schema-version bump** — the plan's v7 was wrong (finding 4): the column is TEXT with write-time enforcement, `linked_device` set the precedent, and a bump would have made every fielded v6 hub refuse the file and thrown sync pulls into `BAD_IMPORT` for users with no shared row at all.
- **2026-09-04 — fresh-context plan review (High tier) — 24 findings, all folded:** BLOCKER 1 (contract on an untrusted channel → Q6); MAJOR 2 (preview ran the LLM transport → stripped + opt-in), 3 (share scan too aggressive → bespoke gate, warn not refuse), 4 (no v7), 5 (update detection via `sharedBundle:<appId>`, not bytes), 6 (docs carry personal data → per-doc toggles, `memory` off, Q7), 7 (DDL: failure = install failure; `CREATE …` grammar; seed rows stated), 8 (test the shipping admission gate), 9 (revoke token/key → `snug_secrets`); MINOR 10–24 (sniff in TS + seat rename; deep link via the plugin's seats; strip fragment + memory-first inbox; AC16 wording; receiver-computed `bundleId`; bare-borrower export; exclude revoked; flush before schema read; unique display name; field bounds; generic install functions; refuse at cap; deleted-test classification + cross-file order test; Q1 option D).
