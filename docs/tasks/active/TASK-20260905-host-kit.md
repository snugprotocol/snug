## Spec (what & why)

**What.** A new app, `apps/host`, built the way `apps/desktop` is built — the playground's own React source aliased in as `@playground`, an entry that runs an asynchronous **probe** and installs a platform object before React boots, its own Vite config — whose build emits **`snug-host.html`**, one self-contained page: hub → run view → a settings subset, the starter shelf with its card metadata inline and **each starter's html, docs and contract loaded on click from the content-pinned `@snugprotocol/starters` package (A3)**, the user database on sql.js with the WASM inlined as bytes, import/export, and **the builder exactly as the playground and the desktop ship it — the `/build` route, the create bar and idea chips, the run rail's chat — running on the pinned host brain (A5)**; **no brain/model/provider/account/sync controls — D15**. The probe decides the binding (`artifact` / `artifact-chat` / `local-host` / `file`), **tries** the storage ladder at runtime (OPFS → IndexedDB → memory) and hands the winner to the playground through the seats that already exist, and pins the brain through a new platform seat that the playground's one brain derivation honours ahead of whatever the user file says — the builder and the apps alike, since both resolve through that derivation. In this task the only brain is the demo brain and the only storage is the browser bucket; the host-specific brains and stores (`sample`, `window.claude.complete`, the html-republish, `window.storage`, the local-host boot config) are the typed seats T3/T4 fill. A root gate, `check-host-kit`, pins the page's size, self-containment and per-commit reproducibility; the kit's own Playwright suite proves the rest on the real file.

**The micro kit is NOT in this task.** The plan review measured the floor: `createRunnerHost` alone bundles to 145 KB under Rollup because `@snugprotocol/protocol`'s zod schemas cannot be shaken (93 KB floor); with S7's 182 KB Chess the widget page would be ~327 KB > 262,144. `snug-host-micro.html` therefore moves whole to T5, together with the diet it needs (a zod-free frame validator entry — a `packages/protocol` change, re-tiered there per SPEC_SYNC) and the pre-compile step it depends on. T2 records the numbers and nothing else.

**Why.** Every binding of the program runs this page: it is what the skill publishes as the `Snug` artifact (T4), what the local host serves is its sibling the ordinary playground (T3), and what the widget carries is its micro form (T5). T1 answered the questions that shape it: the nested runner works inside both artifact viewers, the WASM cannot be fetched there (`connect-src 'self'`), the CDN allowlist is narrower than the runner's, and the durable store is a republish of the page itself — so the kit must be one file, carry its engine as bytes, and know which host it woke up in.

**Acceptance criteria** (each becomes at least one test; "walk" = a journaled manual check where no test can reach):

1. **One file, structurally.** The built `snug-host.html` is the only file in `dist/`; DOM-parsed, it has no `<script src>`, no `<link rel="stylesheet"|"preload"|"modulepreload">`, no `<base>`, no `@import` or `url(http…)` in top-level `<style>`, no favicon link; ≤ 16 MiB (`check-host-kit`, structural — NOT a string sweep: the inlined registries legitimately contain dozens of URLs). The starter loader appends `<script>` elements at RUNTIME (AC14); the built page carries none.
2. **One file, at runtime.** Opened from `file://` with every network request aborted, the kit renders the hub with the starter shelf (cards from inline metadata) and the disclosure names the storage actually in use (memory or IndexedDB — `file://` exposes OPFS but rejects it); a starter card clicked offline shows the named refusal ("starters load from the network"), never a dead control; served over http with OPFS and the starters CDN intercepted (AC14), installing a starter survives a reload (Playwright; the probe matrix in vitest uses fakes that are PRESENT but throw at call time).
3. **Runs, on the pinned brain.** Chess (installed, so the owned path) plays a move against the demo brain inside the kit; the only external requests are the app's React from jsDelivr `/npm/` and the starter's own pinned `@snugprotocol/starters` script (served by the e2e's interception until the package is published — an owner act). A user file imported with `mode:'local'`, `mode:'subscription'`, or a BYOK key STILL runs on the demo brain and the chip still says so (the platform brain seat outranks the file — vitest twins + one e2e import).
4. **Nothing to choose (D15), on the built page and in vitest.** Under the host platform: no brain section, account section, sync-origin picker, Dropbox token field, endpoint-confirm card, identity chip or `ModelSelect` (D15); and — capability truth inside an artifact, not D15 — no connections door, share control, net-error "connect" CTA, chat directive door or "include secrets" export checkbox. **The builder renders under host exactly as under web (positive pins): the `build` nav link + route, the create bar + idea chips, the run rail's chat tab + thread picker; the feedback menu stays (links only, no network).** The `/download` route stays (disclosure) and the three desktop-locked starters keep their badge. Every hidden surface renders under the web platform (positive twins). Asserted in vitest AND on the served + `file://` page.
5. **Disclosure only.** The brain chip renders "demo brain — no host brain wired yet" with no switch links and, under a pinned host brain, that brain's label (T4 supplies the labels); the "your file" card, Settings hero, starter-install title and `ModeCoercionNote` get host variants that never instruct the user to use a hidden control (copy pinned).
6. **Honest flags, read where they exist.** A probe app handed into the kit through the retained "import snug file" input (a Node-built user file carrying an echo app) renders `host-ready.capabilities` into its DOM: `streaming` = the platform brain's declared value (default `true`), `db:true`, `auth:false`, `net:false` (no net handler is supplied under host), `openUrl` as wired; read via `frameLocator`, never the inspector (which renders no frames).
7. **Sandbox unchanged.** The runner's CSP injection and `sandbox="allow-scripts"` are not touched; on the built page the app iframe's `sandbox` attribute equals `allow-scripts` exactly and its `srcdoc` begins with the byte-identical `RUNNER_CSP` meta; the probe app inside the kit attempts a `fetch` and reports an enforced `connect-src` violation (S1's shape). The playground's 14 CSP checks stay as they are (they prove the runner dist; the kit embeds that dist).
8. **Engine from bytes, first.** `wasmBinary` reaches BOTH `initSqlJs` sites (`createDbDriver` and `openUserDb`, which forwards it to its inner driver) and the playground's two callers read it from one platform seat; with both given, `locateWasm` is never called; in the kit no request for `sql-wasm.wasm` is ever made (e2e abort list). Every existing db suite stays green.
9. **No credential at a foreign origin.** Under the host platform the "include secrets" checkbox is hidden and `importUserFile` strips `snug_secrets` before the store adopts the bytes (nothing in the kit can use a credential: `net:false`, `auth:false`) — a byte-scan test over the adopted store; the hand-off to T4 states that every artifact/storage writer sources bytes from the default (stripped) export, never the raw working copy.
10. **Parity.** Screenshots of the kit's hub and run view beside the playground's at the same width are journaled (walk; the e2e captures both).
11. **Reproducible.** Two clean builds at the same commit produce byte-identical files (sha256 compared by `check-host-kit`'s node test); the build stamp is `<package version> <commit sha>[-dirty]`.
12. **Gates.** `check-host-kit` runs in `ci.yml`'s workspace job (after `turbo run test --force`) and in `gate-local`'s workspace leg; the kit's e2e runs in `gate-local`'s e2e leg behind a precondition that names "dist missing" as CANNOT RUN, never a skip; `apps/host/src` is a positive control in `check-sandbox-guard`; `pnpm --filter host test` and the desktop suite are green (the new flags default to "on" by absence).
13. **Docs.** `architecture.md` (a "Host kit" box + dependency-graph row), `code-map.md` rows, `glossary.md` ("host kit", "binding", "probe", "starter source"); the root `dist/` ignore already covers `apps/host/dist` (verified, nothing to add); ADR-0065 §1/§8 carry dated amendments (builder stays; distribution repo).
14. **Starters on demand (A3).** `starter/starterSource.ts` is the ONE playground module owning the four `examples/` globs (a behavior-preserving refactor; the shelf, meta, contract and docs modules read through it); the kit build aliases it to `apps/host/src/starterSource.ts`, whose `list()` returns the twelve cards from inline metadata and whose `load(id)` appends exactly one `<script src="https://cdn.jsdelivr.net/npm/@snugprotocol/starters@<exact version>/<id>.js" integrity="sha384-…" crossorigin="anonymous">`, resolves when the wrapper registers the bundle, and rejects with a named error on load failure or timeout (never hangs). `scripts/build-starters-pkg.mjs` emits the package from `examples/` (`package.json`, one `<id>.js` wrapper per starter carrying html + docs + contract + meta as JSON, `index.json` with the sha384 of every wrapper) and the kit build bakes the version + hash table from `index.json`. Pins: the kit bundle carries no starter html (the built page with the alias is ≥ 800 KB smaller than the same build without it, measured once and pinned as a ceiling), the loader's URL/`integrity`/`crossorigin` shape, the named refusal offline, the wrapper's registration protocol with a hostile fixture (a starter containing `</script>` and `<!--`), and the package build's reproducibility. Publishing `@snugprotocol/starters` is an OWNER ACT.

**Out of scope (owned elsewhere):** the `sample` / `claude-complete` transports and the `artifact-html` / `artifact-db` / `window-storage` backends, the "your file" chip, the app hand-in and `snug-embed` (T4); the local-host launcher, its boot config, the bearer for `local` mode (T3); the micro kit, the `WidgetBridge`, `snug-db`, the pre-compile step and the protocol validator diet (T5); publishing or deploying the kit; the `Snug` artifact recipe and favicon (T4/T6); any `packages/protocol` change; the WebLLM brain (aliased out of the bundle).

## Plan

### Design decisions (Gate 2, grounded in the code; each finding of the 2026-09-05 review is cited by number where it changed the plan)

- **P1 — Structure.** Mirror `apps/desktop`: `apps/host/vite.config.ts` aliases `@playground` → `../playground/src`; `src/main.tsx` awaits the probe, calls `setPlatform(createHostPlatform(result))`, then mounts `<HashRouter><App/></HashRouter>`. One Vite config, one input (`index.html`), `build.rollupOptions.output.inlineDynamicImports: true` (a second input is refused with that flag — review #2; the micro kit's separate config is T5's).
- **P2 — Platform seats, absence = on.** `SnugPlatform` gains: `kind: 'web' | 'desktop' | 'host'`; `binding?: 'artifact' | 'artifact-chat' | 'local-host' | 'file'`; **`brain?: PlatformBrain` = `{ kind: 'demo' } | { kind: 'host'; label: string; adapter: AgentAdapter; streaming: boolean; tools: boolean; maxPromptBytes?: number }`** — the webllm precedent generalised: `resolveBrain(flagOn, webgpu, pinned)` returns the pinned arm AHEAD of the webllm flag and the file's mode/provider/keys (`Brain` gains `{ kind: 'host', … }` and `demo.reason` gains `'host'`); `DirectMode` and `AdapterKind` gain `'host'`; `createTurnAdapter` returns the platform's adapter for `mode:'host'` (no key read, like webllm/local); `resolveAppTransport`, `useBuilderChat` (the builder takes the tool-free arm when `tools` is false — the webllm path, renamed), `resolveActiveBrainFrom` (→ `'host'`) and the chip all take the pinned arm (review #7/#17 — the one derivation, ADR-0059 rule 2; T4 supplies the `sample`/`complete` adapters and honours `maxPromptBytes` in the app-context budget); **`sqlJsWasmBinary?: Uint8Array`** (review #0/#16); the existing `userdbBackend` carries the probe's tried backend (review #1/#15/#30); capability flags `brainSettings?`, `connections?`, `share?`, **`account?`**, **`sync?`** (optional booleans, `undefined` = enabled — `hubAuth?`'s rationale inverted; review #9/#10/#29; NO `builder` and NO `feedback` flag — A5, no consumer), read through one helper `allows(name)`. The host platform sets the four existing booleans explicitly: `subscriptionMode:false, hubSyncOrigin:false, lanHttpPrivate:false, hubAuth:false` (review minor 5), and `ModeCoercionNote` renders nothing under host (its copy names the desktop app and links to the hidden brain section).
- **P3 — Gating sites** (one conditional each on `allows(...)`, every one with a negative + positive twin): `App.tsx` — `/s/:id` (`share`); the `build` NavLink, `/build` route and `FeedbackMenu` are UNGATED (A5 — positive pins); `/download` STAYS (three desktop-locked starter badges and the about card link to it — review #13); `HubView` — unchanged (create bar + chips stay; A5); `SettingsView` — the `brain` Section incl. the endpoint-confirm card (`brainSettings`; F15's `needsConfirm()` is skipped when a platform brain is pinned, with a comment tying the two — review #8), the `account` Section (`account`), `connections` (`connections`), `feedback` (`feedback`), in `DataCard` the sync-origin segment + Dropbox token (`sync`; `initSync()` short-circuits to `none`) and the "include secrets" checkbox (host: hidden — review #21); `RunView`/`RunHeaderActions` — `ModelSelect` (`brainSettings`), connections door + net-error CTA + chat directive door + starter-install disclosure copy (`connections`), share (`share`), **the chat rail stays as on web (A5; positive pin)**, and **no `NetHandler` is supplied when `allows('connections') === false` so `host-ready.net` is `false` structurally (review #4/#11)**; `ConnectionWizardSheet` tests `kind !== 'desktop'` where it tested `=== 'web'`; `BrainChip` — switch links (`brainSettings`), the BYOK honesty hint (host: hidden), the host demo copy; `IdentityChip` already null under `hubAuth` off. `importUserFile` strips `snug_secrets` under host (review #21). Copy pass (review minor 6): every string that instructs the user to use a hidden control (the BYOK hint, "change in settings", `ModeCoercionNote`, the starter-install disclosure) gets a host variant, pinned; nothing else changes copy (A5 — the hub is the playground's).
- **P4 — Engine bytes, end to end.** `packages/db`: `wasmBinary?: ArrayBuffer | Uint8Array` on `CreateDbDriverOptions` AND `OpenUserDbOptions`, forwarded to the inner driver, and at both `initSqlJs` sites `{ wasmBinary }` replaces `{ locateFile }` when present (sql.js 1.14.1's browser bundle honours `Module.wasmBinary`; sql.js memoizes the FIRST `initSqlJs` call page-wide, so the user-db boot — the first caller — must carry the bytes: review #0). The playground's `state/userdb.ts` and `RunView`'s ephemeral driver both read `getPlatform().sqlJsWasmBinary` and pass it beside `locateWasm`. The kit obtains the bytes with Vite's own `?inline` import (`data:application/wasm;base64,…`, prefix stripped, decoded once — review minor 1; no custom plugin); a `data:` URL through `locateFile` is rejected because Emscripten would fetch it and the hosted viewer's `connect-src 'self'` blocks that.
- **P5 — Single file.** A small Vite plugin in `apps/host/` inlines the entry's JS as `<script type="module">` and its CSS as `<style>` into the emitted HTML, deletes the asset files, writes the build stamp, and **refuses** (throws) if the JS contains `</script` or an unclosed `<!--` in script-data terms, or the CSS contains `</style` (review minor 2 — today's safety is esbuild's escaping plus luck). `@mlc-ai/web-llm` is aliased to `src/stubs/webllm.ts` so the 6 MB engine never enters the bundle; **`@playground/starter/starterSource` is aliased to `src/starterSource.ts` so the ≈ 1.04 MB of starter html/docs/contracts never enters it either (A3/AC14) — `import.meta.glob` is build-time and `inlineDynamicImports` would inline every lazy starter chunk, so the exclusion MUST be a build-time alias of the one module that owns the globs, not a runtime seat.** Vite's own emitted `<head>` is enumerated from a real build before the plugin is written. Estimated size ≈ 2.5 MB (≈ 3.5 MB before the starter alias).
- **P6 — Probe.** `apps/host/src/probe.ts`: `decideBinding(env)` is pure and matrix-tested; `probeStorage()` is **asynchronous and tries** each rung (`await navigator.storage.getDirectory()` + a create/write/read round trip → `createOpfsBackend`; else an `indexedDB.open` round trip → `createIdbBackend`; else `createMemoryBackend`) and returns `{ backend, kind }` for the disclosure; `probeBrain()` returns `{ kind: 'demo' }` in T2 and the typed `unavailable` seats for `sample` / `complete` / `local` that T3/T4 replace. Nothing asks the user anything (D15). Provenance for the chip is stamped from the platform brain per turn.
- **P7 — Streaming truth.** `packages/runner`: `RunnerHostOptions.streaming?: boolean` (default `true`) feeds `postHostReady`; **`SnugAppFrame` forwards it** (it enumerates options explicitly — review #18/#28) with a pin in `snug-app-frame.test.tsx`; `RunView` passes `platform.brain.streaming` when a transport brain is pinned. `db`/`openUrl` already follow the seams supplied; `net` follows P3's gate.
- **P8 — Gate.** `scripts/check-host-kit.mjs` (+ `check-host-kit.node-test.mjs`): DOM-parses the built page (a dependency-free tokenizer over the top-level document, never script bodies) and applies AC1's structural rules; size cap; build stamp present; exactly one file in `dist/`; **reproducibility**: builds the kit twice from a clean `dist/` and compares sha256 (review #32). Wired into `ci.yml`'s workspace job after `turbo run test --force` (dist exists — `test` depends on `build`) and into `gate-local`'s workspace leg in the same change (review #25); `UNMAPPED_CI_STEPS` updated if the mapping test asks.
- **P9 — Verification surfaces.** `apps/host/e2e/kit.spec.ts` (own minimal `playwright.config.ts`; a loopback static server over `dist/`; every request aborted except jsDelivr `/npm/`, with `https://cdn.jsdelivr.net/npm/@snugprotocol/starters@*/*.js` INTERCEPTED and served from `dist/starters/` — the package is not published; plus a `file://` run in which a starter click must show the named refusal): AC2/3/4/5/6/7/8/14 + screenshots (AC10). **Hand-in of the probe app (review #12/#19/#27):** a fixture user file built in Node at test time with `@snugprotocol/db` (`openUserDb` over `createMemoryBackend()`, one app row = an echo app that renders `host-ready.capabilities` and attempts a `fetch`, exported as bytes) and fed to Settings' "import snug file" input with `setInputFiles`; capabilities read from the echo app's DOM via `frameLocator`. ## Decisions & surprises

- **2026-09-05 — the WASM cannot ride a `data:` URL.** Emscripten resolves `locateFile` with a fetch; the hosted viewer's `connect-src 'self' …` (T1 S1) would block a `data:` URL. Bytes through `wasmBinary` are the only path — and sql.js memoizes the first `initSqlJs`, so the user-db boot must be the caller that carries them (review #0).
- **2026-09-05 — `inlineDynamicImports` would drag WebLLM in.** `agent/webllm/engine.ts` `import()`s `@mlc-ai/web-llm` lazily; a single-file build inlines every dynamic import, so the engine is aliased to a stub (P5). The same flag refuses a second input, so the micro kit needs its own config — and it left this task anyway.
- **2026-09-05 — `file://` exposes OPFS and rejects it.** Chromium reports `navigator.storage.getDirectory` as a function at `file://` and rejects the call with `SecurityError`; `detectPersistenceBackend` is presence-based and would pick it, and the kit would land on "your Snug file couldn't be read". The probe tries, never detects (review #1/#15/#30).
- **2026-09-05 — the run rail's chat IS the builder.** `RunView`'s default rail tab mounts `useBuilderChat` pinned to the app; hiding `/build` alone would ship a working builder the moment a starter is installed (review #6).
- **2026-09-05 — the file outranks the probe unless a seat says otherwise.** The send path routes on the user file's mode/provider/keys; an imported file would route turns to localhost, Anthropic or `/invoke` with no Settings to change it. Hence the platform `brain` seat honoured by the one derivation (review #7/#17) — also the seat T4 plugs `sample` into.
- **2026-09-05 — the micro kit's floor is 145 KB.** Rollup keeps 93 KB of zod for `@snugprotocol/protocol`; the micro kit and its diet move to T5 (review #3/#22/#23/#33).
- **2026-09-05 — no `platform` seat on `host-ready`.** Apps already degrade on the flags they read; the parent left the seat as a Gate-2 candidate and this plan declines it (no consumer, a High spec change).
- **2026-09-05 — the owner's five points (A1–A5) confirmed; A1 picked.** The builder STAYS (A5: the kit is a clone of the playground / Snug Desktop minus the D15 controls — the `builder` and `feedback` flags are gone, no consumer); starters load on click (A3); the distribution repo is the pick for A1 (a T6/T8 change; parent D6/D7 + ADR-0065 §8 amended). Two mechanism facts found while folding: (1) `import.meta.glob` is BUILD-time and the kit's `inlineDynamicImports` inlines every lazy starter chunk, so a runtime seat cannot keep the starter bytes out of the kit — the exclusion is a build-time alias of the ONE module that owns the globs (`starterSource`), whose kit implementation is the on-demand loader; (2) the platform brain rides the webllm precedent exactly — `DirectMode`/`AdapterKind` gain `'host'`, the adapter comes from the platform, no key is read, F15's endpoint-confirm is skipped — because the builder (`createDirectBuilder`) and the apps (`createDirectAppTransport`) both construct their adapter through `createTurnAdapter`, so one arm there serves both. The `sample` contract's 65,536-byte input cap vs today's 140,000-char edit context is carried as `maxPromptBytes` on the seat for T4.
