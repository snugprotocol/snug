## Spec (what & why)

**What.** A new app, `apps/host`, built the way `apps/desktop` is built — the playground's own React source aliased in as `@playground`, an entry that runs an asynchronous **probe** and installs a platform object before React boots, its own Vite config — whose build emits **`snug-host.html`**, one self-contained page: hub → run view → a settings subset, the twelve starters (three of them desktop-locked, as on the web), the user database on sql.js with the WASM inlined as bytes, import/export; **no builder chat anywhere (the run view's chat rail included), no brain/model/provider/account/sync controls — D15**. The probe decides the binding (`artifact` / `artifact-chat` / `local-host` / `file`), **tries** the storage ladder at runtime (OPFS → IndexedDB → memory) and hands the winner to the playground through the seats that already exist, and pins the brain through a new platform seat that the playground's one brain derivation honours ahead of whatever the user file says. In this task the only brain is the demo brain and the only storage is the browser bucket; the host-specific brains and stores (`sample`, `window.claude.complete`, the html-republish, `window.storage`, the local-host boot config) are the typed seats T3/T4 fill. A root gate, `check-host-kit`, pins the page's size, self-containment and per-commit reproducibility; the kit's own Playwright suite proves the rest on the real file.

**The micro kit is NOT in this task.** The plan review measured the floor: `createRunnerHost` alone bundles to 145 KB under Rollup because `@snugprotocol/protocol`'s zod schemas cannot be shaken (93 KB floor); with S7's 182 KB Chess the widget page would be ~327 KB > 262,144. `snug-host-micro.html` therefore moves whole to T5, together with the diet it needs (a zod-free frame validator entry — a `packages/protocol` change, re-tiered there per SPEC_SYNC) and the pre-compile step it depends on. T2 records the numbers and nothing else.

**Why.** Every binding of the program runs this page: it is what the skill publishes as the `Snug` artifact (T4), what the local host serves is its sibling the ordinary playground (T3), and what the widget carries is its micro form (T5). T1 answered the questions that shape it: the nested runner works inside both artifact viewers, the WASM cannot be fetched there (`connect-src 'self'`), the CDN allowlist is narrower than the runner's, and the durable store is a republish of the page itself — so the kit must be one file, carry its engine as bytes, and know which host it woke up in.

**Acceptance criteria** (each becomes at least one test; "walk" = a journaled manual check where no test can reach):

1. **One file, structurally.** The built `snug-host.html` is the only file in `dist/`; DOM-parsed, it has no `<script src>`, no `<link rel="stylesheet"|"preload"|"modulepreload">`, no `<base>`, no `@import` or `url(http…)` in top-level `<style>`, no favicon link; ≤ 16 MiB (`check-host-kit`, structural — NOT a string sweep: the inlined starters and registries legitimately contain dozens of URLs).
2. **One file, at runtime.** Opened from `file://` with every network request aborted, the kit renders the hub with the starter shelf and the disclosure names the storage actually in use (memory or IndexedDB — `file://` exposes OPFS but rejects it); served over http with OPFS, installing a starter survives a reload (Playwright; the probe matrix in vitest uses fakes that are PRESENT but throw at call time).
3. **Runs, on the pinned brain.** Chess (installed, so the owned path) plays a move against the demo brain inside the kit; the only external requests are the app's React from jsDelivr `/npm/`. A user file imported with `mode:'local'`, `mode:'subscription'`, or a BYOK key STILL runs on the demo brain and the chip still says so (the platform brain seat outranks the file — vitest twins + one e2e import).
4. **Nothing to choose (D15), on the built page and in vitest.** Under the host platform: no `build` nav link or route, no create bar or idea chips, no chat tab or thread picker in the run rail (inspector is the default tab), no brain section, account section, sync-origin picker, Dropbox token field, endpoint-confirm card, feedback section, feedback menu, identity chip, `ModelSelect`, connections door, share control, net-error "connect" CTA, chat directive door, or "include secrets" export checkbox; the `/download` route stays (disclosure) and the three desktop-locked starters keep their badge. Every one of those renders under the web platform (positive twins). Asserted in vitest AND on the served + `file://` page.
5. **Disclosure only.** The brain chip renders "demo brain — no host brain wired yet" with no switch links; the "your file" card, hub empty state, Settings hero, starter-install title and inspector empty copy get host variants that never instruct the user to use a hidden control (copy pinned).
6. **Honest flags, read where they exist.** A probe app handed into the kit through the retained "import snug file" input (a Node-built user file carrying an echo app) renders `host-ready.capabilities` into its DOM: `streaming` = the platform brain's declared value (default `true`), `db:true`, `auth:false`, `net:false` (no net handler is supplied under host), `openUrl` as wired; read via `frameLocator`, never the inspector (which renders no frames).
7. **Sandbox unchanged.** The runner's CSP injection and `sandbox="allow-scripts"` are not touched; on the built page the app iframe's `sandbox` attribute equals `allow-scripts` exactly and its `srcdoc` begins with the byte-identical `RUNNER_CSP` meta; the probe app inside the kit attempts a `fetch` and reports an enforced `connect-src` violation (S1's shape). The playground's 14 CSP checks stay as they are (they prove the runner dist; the kit embeds that dist).
8. **Engine from bytes, first.** `wasmBinary` reaches BOTH `initSqlJs` sites (`createDbDriver` and `openUserDb`, which forwards it to its inner driver) and the playground's two callers read it from one platform seat; with both given, `locateWasm` is never called; in the kit no request for `sql-wasm.wasm` is ever made (e2e abort list). Every existing db suite stays green.
9. **No credential at a foreign origin.** Under the host platform the "include secrets" checkbox is hidden and `importUserFile` strips `snug_secrets` before the store adopts the bytes (nothing in the kit can use a credential: `net:false`, `auth:false`) — a byte-scan test over the adopted store; the hand-off to T4 states that every artifact/storage writer sources bytes from the default (stripped) export, never the raw working copy.
10. **Parity.** Screenshots of the kit's hub and run view beside the playground's at the same width are journaled (walk; the e2e captures both).
11. **Reproducible.** Two clean builds at the same commit produce byte-identical files (sha256 compared by `check-host-kit`'s node test); the build stamp is `<package version> <commit sha>[-dirty]`.
12. **Gates.** `check-host-kit` runs in `ci.yml`'s workspace job (after `turbo run test --force`) and in `gate-local`'s workspace leg; the kit's e2e runs in `gate-local`'s e2e leg behind a precondition that names "dist missing" as CANNOT RUN, never a skip; `apps/host/src` is a positive control in `check-sandbox-guard`; `pnpm --filter host test` and the desktop suite are green (the new flags default to "on" by absence).
13. **Docs.** `architecture.md` (a "Host kit" box + dependency-graph row), `code-map.md` rows, `glossary.md` ("host kit", "binding", "probe"); the root `dist/` ignore already covers `apps/host/dist` (verified, nothing to add); ADR-0065 unchanged.

**Out of scope (owned elsewhere):** the `sample` / `claude-complete` transports and the `artifact-html` / `artifact-db` / `window-storage` backends, the "your file" chip, the app hand-in and `snug-embed` (T4); the local-host launcher, its boot config, the bearer for `local` mode (T3); the micro kit, the `WidgetBridge`, `snug-db`, the pre-compile step and the protocol validator diet (T5); publishing or deploying the kit; the `Snug` artifact recipe and favicon (T4/T6); any `packages/protocol` change; the WebLLM brain (aliased out of the bundle).

### A1 — Repo shape (point 1): the source stays here; the *distribution* becomes a small generated repo — a T6/T8 decision, no T2 impact

- **Facts.** `apps/host` is the playground's own source behind a platform seam (ADR-0021 / D1): it cannot be built outside this monorepo without first publishing the playground as a package. The skill's `references/` are generated from the prompt store (ADR-0004 / D6). Install paths, measured: `claude plugin marketplace add owner/repo` clones the WHOLE marketplace repo (this repo is 77,258 KB server-side and grows with every release; no shallow clone is documented — anthropics/claude-code#40864 is the open request), `claude plugin install` copies out of that clone; Cowork installs through the same marketplaces (or a zip); claude.ai takes a zip only; OpenClaw's git install "expects SKILL.md at the source root"; Hermes installs a repo *path* via skills.sh or a whole-repo tap. A marketplace entry's `source` may point at another repo (`{"source":"github","repo":"…"}`). `snugprotocol/spec` (2,748 KB) already runs the downstream-publication pattern (SPEC_SYNC: never edited directly, pushed from here).
- **Recommendation.** Keep every source of truth in this monorepo; add a generated distribution repo — `snugprotocol/snug-skill`, `SKILL.md` at its root, `.claude-plugin/*` beside it, the kits as ITS Release assets — pushed by a script at release points (an owner act, like the spec push) and never edited directly. D6's committed `skills/snug/` becomes the staging tree that script pushes (still committed, still drift-gated by `check-skill-sync`); D7's manifests are emitted into the dist repo from the same constants module; D11 unchanged except which repo the assets hang off. Alternative kept honest: the monorepo as the marketplace works for Claude Code / Cowork (a 75 MB clone per user) and Hermes, and not for OpenClaw's git install (ClawHub publish would). **Owner decision; lands in T6's Gate 2 either way.**

### A2 — Spec impact (point 2): none to the wire protocol — the kit is a host *implementation*

The protocol defines the app↔host contract; a new host declares what it cannot do through the flags that already exist (`net:false`, `auth:false`, `streaming` truth) — feature detection, never host sniffing — which is why the `platform`/`binding` seat on `host-ready` stays declined (MCP's capability negotiation follows the same principle: `clientInfo` is informational, never normative). Protocol-adjacent items, each owned elsewhere: the non-normative bindings appendix (T7); the embedder-narrowed CDN allowlist inside artifacts → an authoring rule + embed lint (T4) and one appendix sentence that a host MAY narrow the app CDN allowlist (T7); the agent-built provenance literal → a userdb enum append + spec-changelog line, no version bump (T4); the zod-free validator entry → a `packages/protocol` packaging change, spec-sync-tiered, no wire change (T5). Points 3 and 5 add nothing to this list.

### A3 — Starters on demand (point 3): feasible in every binding — but never by fetching GitHub from the page inside an artifact

- **Facts.** The twelve starters are 865,805 B of `app.html` + 11,949 B `starter.json` + 16,329 B runtime contracts + 142,452 B authoring docs ≈ 1.04 MB of the ≈ 3.5 MB kit; the playground pulls them in through four `import.meta.glob`s (`starterApps`, `starterMeta`, `starterRuntimeContract`, `starterDocs`) and installs a clicked starter into the user's file. Inside BOTH artifact viewers `fetch`/XHR to any other origin is blocked (`connect-src 'self'`, T1 S1) and the only dynamic-load channel is a `<script>` from jsDelivr `/npm/` or cdnjs (T1 S2) — the same CDN the apps already load React from.
- **Design.** A `starters` platform seat: `list()` = the inline card metadata (name, version, changelog, badges; ≈ 30 KB stays in the kit), `load(id)` = the starter's html + docs + contract. Web and desktop keep today's globs (absence = today's behavior). The host kit's implementation appends `<script src="https://cdn.jsdelivr.net/npm/@snugprotocol/starters@<exact version>/<id>.js" integrity="sha384-…" crossorigin="anonymous">` — one generated JS wrapper per starter that registers its bundle — so the content is pinned by hash at kit build time (reproducible; ADR-0060's posture; a new starter ships with a kit rebuild, by design). `scripts/build-starters-pkg.mjs` emits the package from `examples/` plus the sha384 manifest the kit build reads. Publishing `@snugprotocol/starters` is an OWNER ACT (the `@snugprotocol` npm scope is already the A2 prerequisite). Offline / `file://`: the cards render and a click names the failure ("starters load from the network") — never a dead control. Binding B (T3, later): the local server fetches from GitHub Releases into a cache directory — the literal "temp location". The installed starter still lives in the user's file exactly as today.
- **Amends.** AC1/AC2 ("one file" = the engine; starters are pinned content), AC3 (the e2e intercepts the CDN URL and serves the locally built package until the publish exists), P5 (the four starter globs are aliased out of the kit bundle), P9, the test plan, `check-host-kit` (the starter `<script>` tags are the ONE allowed external script form — exact host, exact version, `integrity` present). Cost stated plainly: one more package and publish act; a runtime dependency on the CDN the apps already use; no starters offline.

### A5 — The builder stays (point 5 + the clarification): parity by construction, two constraints from the host brain

- **Facts.** The builder (`/build`, the create bar and chips, the run rail's chat) is playground source the kit already aliases in, and it resolves its brain through the same derivation the apps use (`currentBrain()` → `resolveAppTransport` / `useBuilderChat`), so the pinned platform brain (P2) drives it with no builder-specific wiring. Keyless, today's playground builder runs on the demo brain and builds the canned demo app (`agent/demoApp.ts`) — the kit does the same when no host brain exists, disclosed by the chip. The `sample` contract (0.2.41) streams (`onText`), has tiers `quick`/`default`/`complex`, caps INPUT at 65,536 bytes across all turns, and flags `truncated` on the length/time limit with NO documented output ceiling. The builder system prompt is 5,246 B (measured); an edit turn's app context today allows up to 140,000 chars of html + 40,000 of docs/schema/history (`agent/appContext.ts` caps) — far above the cap.
- **Amends.** P3 loses every `builder` gate — **no `builder` flag at all** (no consumer; the rail keeps its chat tab and thread picker, the hub keeps its create bar and chips, the "agent is the builder" copy variants are dropped). P2's `brain` seat gains `maxPromptBytes?: number` — the transport's input cap, honoured by the app-context assembly, whose caps become a budget derived from it (a T4 change over a T2 seat). AC4/AC5 re-worded to D15's controls only (brain section, mode segment, BYOK rows, local URL, default model/provider, `ModelSelect`, account/identity/sign-in, hub-sync origin, Dropbox token, subscription mode, endpoint-confirm card); `connections`, `share`, the net-error CTA and the "include secrets" checkbox stay gated as capability truth (dead inside an artifact — D4, `connect-src`, C1). **T4's FIRST act is an S3-style spike:** ask `sample` (`default`) for a 40 KB app and read `truncated`; if it truncates, the builder continues generation across calls (the page keeps the partial and asks for the rest) rather than promising one-shot builds. `window.claude.complete` (chat) is a single string in, string out, no streaming, unmeasured — the least certain leg; T4 measures before the A2 builder is promised. Cost: every builder turn is viewer-billed after the one consent — disclosed, not hidden.
- **Clarification recorded.** "Clone of Snug Desktop" on Cowork = the same React tree with the desktop's look and flows; the desktop's seat-driven surfaces (LAN, sidecar, helpers, self-update, the file on disk) cannot exist inside an artifact, and connected apps stay out by D4 (approved). The "your file" chip (D8) says where the file actually lives.

## Decisions & surprises

- **2026-09-05 — the WASM cannot ride a `data:` URL.** Emscripten resolves `locateFile` with a fetch; the hosted viewer's `connect-src 'self' …` (T1 S1) would block a `data:` URL. Bytes through `wasmBinary` are the only path — and sql.js memoizes the first `initSqlJs`, so the user-db boot must be the caller that carries them (review #0).
- **2026-09-05 — `inlineDynamicImports` would drag WebLLM in.** `agent/webllm/engine.ts` `import()`s `@mlc-ai/web-llm` lazily; a single-file build inlines every dynamic import, so the engine is aliased to a stub (P5). The same flag refuses a second input, so the micro kit needs its own config — and it left this task anyway.
- **2026-09-05 — `file://` exposes OPFS and rejects it.** Chromium reports `navigator.storage.getDirectory` as a function at `file://` and rejects the call with `SecurityError`; `detectPersistenceBackend` is presence-based and would pick it, and the kit would land on "your Snug file couldn't be read". The probe tries, never detects (review #1/#15/#30).
- **2026-09-05 — the run rail's chat IS the builder.** `RunView`'s default rail tab mounts `useBuilderChat` pinned to the app; hiding `/build` alone would ship a working builder the moment a starter is installed (review #6).
- **2026-09-05 — the file outranks the probe unless a seat says otherwise.** The send path routes on the user file's mode/provider/keys; an imported file would route turns to localhost, Anthropic or `/invoke` with no Settings to change it. Hence the platform `brain` seat honoured by the one derivation (review #7/#17) — also the seat T4 plugs `sample` into.
- **2026-09-05 — the micro kit's floor is 145 KB.** Rollup keeps 93 KB of zod for `@snugprotocol/protocol`; the micro kit and its diet move to T5 (review #3/#22/#23/#33).
- **2026-09-05 — no `platform` seat on `host-ready`.** Apps already degrade on the flags they read; the parent left the seat as a Gate-2 candidate and this plan declines it (no consumer, a High spec change).
