# Lessons — distilled 2026-08-15

Forward-looking rules only, grouped by theme. **The agent reads this when planning (Gate 2).** The full narratives live in git history of this file (pre-distillation) per ADR-0027. Entry dates are preserved for archaeology. Add new rules to the matching section at Gate 6; when a section outgrows a screen, re-distill.

## Tests that can fail

- (2026-08-18) **Replacing a label with an icon silently breaks every locator that queried the label.** Two `e2e/starters.spec.ts` specs find the export control by `getByRole('button', { name: 'export .sqlite' })`; had the words become a bare glyph, both would have broken in a lane **CI does not run** — surfacing much later as a mystery. Before deleting user-visible TEXT, grep the whole repo (e2e included) for that literal: a string on screen is an API for tests, screen readers and docs. Keep it as `aria-label` and pin it; `title` is a tooltip and is NOT an accessible name.
- (2026-08-20) **A green suite proves nothing about a path no test walks.** Renaming `USERDB_FILE` left `packages/db` at 339/339 green, because every production site routed through the constant — while the legacy-fallback path, the thing that decides whether an upgrading user keeps their data, had no test at all. The suite was measuring the rename's *consistency*, not its *safety*. When a change's risk lives in a path that does not exist yet, the green you already have is the least informative signal in the room.
- (2026-08-20) **A new surface that gates the app is a product decision, not a placement detail — and only the assembled product will tell you.** The protection offer shipped as a full-screen gate in front of the hub. 24 of 73 e2e specs then timed out waiting for a starter tile, because a brand-new profile met "protect this file?" and never reached the shelf. The failing tests were the symptom; the defect was asking someone to protect a file before they had seen a single app — valuing something they had not been shown. Prominence that blocks is a modal with extra steps. Run the leg that exercises the ASSEMBLED product before merging anything that adds a screen, not after.
- (2026-08-20) **Run the product before claiming a UI feature works.** The passphrase feature shipped with `ProtectSetupFlow` never rendered and `initProtectOffer` never called: 1341 tests green, the owner launched the app, and nothing ever asked for a passphrase. Then the SAME class bit again one layer down — a wrong passphrase showed no error, because `unlockUserDb` published a transient `'opening'` status and `App.tsx` renders the unlock screen for `'locked'` only, so the screen UNMOUNTED mid-attempt and the failure state died with it. Component tests could see neither: one mounts the component directly, the other mocks the store. For anything a person looks at, one verification must be *the running app* — a browser session or a screenshot — not a suite.
- (2026-08-20) **A test that builds its own wiring cannot detect missing wiring.** `encrypted-sync.test.ts` proved the sync loop seals personal-origin payloads — by passing the sealer in itself. The shipping composition root never passed one, so a protected file synced to the user's own Dropbox as a readable database while every suite stayed green. The test proved a *capability*, and nobody had checked that anything *used* it. For any feature whose value depends on being wired at a composition root, one test must assert against the call the shipping code actually makes.
- (2026-08-20) **Read the exit code, not the summary line.** A root run printed "1348 passed" and exited 1: a new render test's branch booted a real sql.js database, whose wasm is fetched over a `/@fs/` URL that only resolves under a dev server, so it aborted with an ENOENT unrelated to any assertion — vitest failed the RUN without failing a TEST. A green count is not a green suite, and the habit of reading totals is the same habit that lets an unreachable feature ship.
- (2026-08-20) **Count the writes, do not trust the status.** A protected file appeared to save correctly: the API resolved, the status stayed `ready`, the UI looked healthy — and nothing reached disk, because the seal threw inside `persist`'s catch-all, which sets `dirty = true` and retries forever. Fault-tolerant write paths convert defects into silence by design. Asserting a `backend.save` CALL COUNT is what made it visible; asserting the return value never would have.

- (2026-08-18) **When a refactor invalidates a test, migrate the CLAIM — never delete the test.** Moving a control into its own component broke an ordering assertion written as source-string indices inside the old file. The claim was still true, so it was re-asserted across both files and re-expressed as rendered document order (`compareDocumentPosition`), which survives the next refactor because it measures nodes rather than string positions. A test deleted during a refactor is coverage lost with nobody noticing; classify every one as MIGRATED / OBSOLETE / LOST (the 2026-08-10 rule, applied to a component extraction rather than a rebuild).

- (2026-08-20) **A test that compares two spellings of one contract must fail when the contract drifts — check that it does, by breaking it on purpose.** `gate-local`'s AC3 asserts every `ci.yml` step has a local counterpart. Written with substring matching it passed, and a mutation test then showed it was decorative: replacing a local command's operative verb (`gate:release` → `nonexistent`) still "matched" the CI step, because the CI step contained the mutant's prefix. Token-set equality kills the mutant. The general shape — a comparison loose enough to pass is loose enough to pass anything — is why the four mutants (unmapped CI step, dropped local command, empty extractor, always-ok status) are now part of the task's evidence rather than an afterthought.
- (2026-08-20) **A gate whose coverage is user-selectable must report what it did NOT check, or it lies by omission.** Making `gate:local`'s legs opt-in was right for a solo dev's time/assurance trade, but it silently changed what a green means: a 2-minute default run verifies two of six legs. An unqualified "PASS" would be the same false confidence the gate exists to prevent, in a new costume. Hence three states rather than two (PASS / FAIL / **DESELECTED**), a verdict that enumerates the unverified legs, an explicit denial of ci.yml equivalence unless `--all` ran, and that line carried verbatim into the PR body — otherwise `git log` becomes a uniform wall of merges whose real verification varied invisibly.
- (2026-08-20) **Quarantine with `test.fail()`, never `test.skip()`.** Adopting a suite with known reds needs a quarantine, but a skip HIDES the row and rots into permanent suppression. `test.fail()` keeps it running and reporting, and inverts the expectation — so a quarantined row that starts passing FAILS the suite and forces a deliberate lift. Verified by adding a genuinely-passing row to the set and watching it break. Quarantine that cannot expire is deletion with extra steps.
- (2026-08-20) **"Element not found" often names the wrong element.** A Playwright spec failed on `expect(wizard).toBeVisible()` — pointing at the wizard, which was innocent. The real cause was one line earlier: the run surface mounts its connect CTA ~500 ms after the URL settles, so an immediate `.first().click()` resolved against an empty set and nothing ever opened the wizard. It passed alone and failed after its five siblings, which is the signature — a warm page wins the race, a loaded one loses. When an assertion fails on a MISSING element, suspect the step that was supposed to produce it before suspecting the assertion.
- (2026-08-20) **A red gate with no enforcement behind it is worse than no gate.** GitHub Actions was billing-blocked for two weeks and rendered as an ordinary red X — indistinguishable from a real break without opening the check annotation. It also turned out never to have BLOCKED anything (private repo on a free plan: branch protection is 403). So its entire contribution was to train the sole reader to merge past reds, which is precisely what happened, routinely. Check what a failing signal actually enforces before treating it as a safety net — and if it enforces nothing, silence it rather than living beside it.

- (2026-08-19, **amended 2026-08-20**) **Before believing a red, remove the cheapest confound: run it serially.** A playground suite failing a DIFFERENT set each run (14/15/31 observed, all `Test timed out in 5000ms`, all in React-rendering files) was fully green — 1254/1254 — under `--no-file-parallelism`, on clean `main` as well as the feature branch. That one flag converted a fifteen-month-old "flake, name never captured" note into a classified cause (worker contention against a 5 s per-test budget) with a concrete fix. A varying failure SET is the signature: a real break fails the same test every time. Costs one command; the alternative is a genuine red waved through as "just the flake". **The amendment, and it cuts the other way:** on 2026-08-20 the same suite ran green 8/8 in full parallel (5 idle + 3 under deliberate CPU contention, 1303/1303) and the classified cause could not be reproduced at all. The rule that survives is the FIRST half — remove the confound before believing a red — not the diagnosis. A classification built from failures you can no longer produce is a hypothesis, not a finding, and the honest response was to leave `testTimeout`/`maxThreads` untouched: patching an unreproducible symptom yields an edit nobody can verify and permanently blunts the signal that separates contention from a real break. **Capture the failing run before theorising about it.**

- (2026-08-20) **A hardcoded permissive collaborator makes "never consulted" indistinguishable from "consulted and granted".** Every sidecar test passed `confirmGate: { confirm: () => true }`, so a gate the code never called looked exactly like a gate that approved — the suite stayed green through a live confirm-bypass. Make a gate a SPY and assert both that it fired and what it received (the `slot`/`body` a downstream policy decides on), so a call handed nothing to decide with also fails. Same shape as the positive-twin rule: a stub that always says yes vouches for nothing.
- (2026-08-20) **Assert on the FIELD that would carry the leak, not only the one that carries the verdict.** All fifteen `NET_AUTH_FAILED` assertions in `packages/auth` used `toMatchObject({ ok: false, code })` — excellent coverage of the code, and none of them ever read `message`, which is the field that was forwarding a live credential to the iframe and the LLM. When a result object has a machine half and a prose half, the prose half is where secrets ride; a suite that only ever checks the machine half is blind exactly where it matters.
- (2026-08-04) A test never seen to fail tests nothing: mutation-check every guard by reverting the fix and watching red. Be suspicious of first-run passes, assertions behind optional calls (`backend.list?.()`), and subjects only reachable in modes the test never enters.
- (2026-08-20) **Verify a RED by restoring the old state from `HEAD`, not with `git stash` — a stash that silently does not take reports the new tree as green and looks like proof.** Confirming that `bundleTargets.test.ts` failed before the config change, `git stash -q --include-untracked -- <path> 2>/dev/null || git stash push -- <path>` matched nothing usable, the `2>/dev/null` swallowed the reason, and the suite ran against the ALREADY-FIXED config: "11 passed", i.e. exactly the reassuring output a real RED check is supposed to rule out. `git show HEAD:<path> > <path>` for each file, run, then restore — it either produces the old bytes or fails loudly, and it is trivially auditable afterward (`git status` shows the same modified set). Same family as the 2026-08-19 rule above: that one asks whether the test COULD fail on the old commit, this one is about not fooling yourself while answering it. Any verification step whose failure mode is "looks like it worked" needs an affirmative signal, never a silent fallback.
- (2026-08-21) **Mutation-check only state whose correct version is COMMITTED — or restore the mutation by inverse edit, never by `git checkout`.** Verifying the resetToFactory MIN→MAX guard, the mutated file was restored with `git checkout -- <file>` while that same file carried the session's uncommitted implementation; the checkout silently wiped it (recovered only because the edits were still in context). The sibling 2026-08-20 rule ("restore a RED from `HEAD`, not stash") assumes HEAD holds the state you want back — mid-implementation it holds the state you just spent an hour leaving. Commit first, or undo the mutation with the same targeted edit that made it.
- (2026-08-21) **An invariant comment is a claim about a distribution, and the FIRST release outside that distribution turns it into a bug — so re-read the comments a new release SHAPE walks past.** `starterUpdate.ts` documented that deriving an installed version from byte-equality "can only over-offer (a no-op update), never hide one". True, and load-bearing, for every release that had ever existed — all of them changed `app.html`. A **docs-only** release (version bumped, html untouched) is the first that does not, and under it the sentence inverts: identical bytes are now indistinguishable from current, so the offer is HIDDEN from exactly the pre-seeding copies the release exists to reach. The sibling half was the same shape one layer down — `applyStarterUpdate`'s already-current fast path returns before the docs seed, so even a copy that DID see the offer received nothing. Both were found by a fresh-context plan reviewer reading the module against the plan, and neither would have been found by the planned test, which was written to the plan's belief rather than the code's. Before shipping a new release/act/message KIND, grep the modules that consume it for their stated invariants and ask which one this kind is the first to violate; a comment that says "can only" is naming its author's sample, not a theorem.
- (2026-08-21) **When an act chains several writes, a test must wait on the act's COMPLETION SIGNAL, never on its first observable write.** The starter-update component test polled "did the html change?" — the FIRST of four writes — so the assertion ran mid-act and read the settings key before the act wrote it, failing two tests against correct code. The act's callback (`onUpdated`) was the honest condition. Same family as "element not found names the wrong element": the failing assertion pointed at the key write, which was innocent.
- (2026-08-20) **Scope a "this string must not appear" assertion to the construct it governs, or it forbids DOCUMENTING the thing it forbids.** A belt asserting the icon generator no longer emits `icon.ico` matched the whole file, so it failed on the header comment written in the same commit — a comment whose entire job is to tell a post-1.0 reader which line to restore. Narrowed to the `SHIP` array, both survive. The generalization: a source-text assertion is a crude instrument aimed at a precise claim, so bound it to the block that carries the behaviour (a list, a handler registration, a config key), never the file — otherwise the test's own rationale, the ADR citation, and the migration note all become violations, and the next person deletes the comment rather than the capability.

- (2026-08-19) **A test that would pass if your change were never made is not coverage — check that property explicitly.** The plan's regression test for "the Spotify pin gains an eighth scope" reused the existing scope-drift fixture, which stages whenever the registry pins ANYTHING; it would have passed verbatim against the unfixed registry. The fix was a fixture frozen at the exact OLD seven-scope consent, which fails with `'none' != 'staged'` until the scope lands — plus a reorder guard, so it cannot pass for the wrong reason either (ADR-0028's comparison is set-based, so a pure reorder must stage nothing). For every regression test ask: what would this do on the commit BEFORE the fix? If the answer is "pass", it pins someone else's behaviour, not yours.

- (2026-08-04) Assert the requirement's OUTCOME in one sentence, never a correlating proxy — if the broken and fixed artifacts both pass, the test measured nothing. Earned twice: hub "reachability" passed with the forked-app bug restored; icon "centred" passed on a 61% logo when the ask was full-bleed.
- (2026-08-08) Mutate the rule AND its call site: deleting the Settings revoke button's call left every test green because the rule was only ever invoked directly. "Logic is correct" and "logic runs" are separate claims.
- (2026-08-17) When a PERMANENT failure and a NORMAL wait render identically, the ambiguity IS the defect — not the failure. A half-linked WhatsApp session showed "history is still syncing" forever; the wedge was already detectable on disk and already auto-cleared on re-pair, so all that was missing was SAYING so. Whenever a screen says "still working", ask what state would make that sentence a lie the user cannot see through, then detect that state and name it in the copy.
- (2026-08-17) Assert the COUNT/state the feature promises, not the shape around it: an emoji-frequency regex that let pictographs repeat inside one token made '😂😂' a single unheard-of emoji, and only a test asserting `{emoji:'😂', count:3}` could see it. Shape assertions pass while the number is wrong.
- (2026-08-13) A refusal's test input must pass every SIBLING refusal and fail only the one under test — `runLanPairing`'s approved-status check survived deletion because hostless fixtures never reached it. When a mutation stays green, suspect the fixture before the mutation.
- (2026-08-08) When a test seam short-circuits production wiring, at least one test runs with the seam OFF — every suite injected `__setDeclarationManifestsForTests`, so a misspelled `import.meta.glob` kept 477 tests green with the feature inert for real users. Mutation-check the wiring, not just the logic.
- (2026-08-13) A fence that restates its data cannot test it: drive the value through the code that CONSUMES it, with fixtures hostile to the mechanism — `hue.pairing.secretPath` was compared to a retyped copy of itself (green against a path no real bridge answers); URL-safe hex keys made four C1 scrub tests decorative.
- (2026-08-11) Test matrices must repeat an operation KIND (write/write exposes what write/read hides — `sqlite3_changes()` deltas); a guard comparing two values from the SAME function verifies agreement, not correctness; neutralize the delimiter PRIMITIVE, not one spelling — the attacker picks the spelling.
- (2026-08-13) Verify a timing fix by measuring failure RATE before/after, and check the ENCLOSING budget — a 10s `vi.waitFor` inside the 5s default test timeout is dead code. Intermittent + every-added-log-makes-it-pass = scheduler/ordering bug, not slowness.
- (2026-08-13) A mutation that stays green is evidence, not a dead end — ask what its survival proves (a microtask drain can't advance real timers → the chain awaits real async). Once an environmental failure reproduces deterministically, re-run the whole file under that condition.
- (2026-08-10) When a rebuild deletes a surface, classify every deleted test: MIGRATED (cite the new assertion), OBSOLETE (prove the code is gone), or LOST — the v2 wizard rebuild orphaned 14 shipped behaviors including `isConnectionRepairableNetError`'s allowlist. A net test-count drop is a prompt to audit, never an explanation.
- (2026-08-04) Test doubles wrapping one-shot resources (streams, iterators, FormData) must be factories — one mocked SSE `Response` served to two turns yields a silent empty second turn.
- (2026-08-17) **A feature is not done when its parts pass — it is done when someone walks it.** Eight seam defects shipped past a fully green tree (23/23 tasks, cargo, the macOS gate) in ONE feature, each hidden behind the last; all eight were found by clicking the real flow. Deep write-up: `docs/solutions/2026-08-17-eight-seam-defects-in-one-feature.md`.
- (2026-08-17) **Every injected dependency is an untested wire.** If every test supplies `sidecarFetch`/`SidecarState`/a store, nothing has tested that PRODUCTION supplies it — `SidecarState` was never `.manage()`d and the commands failed at the IPC boundary while their unit tests, both handler registrations, and the C2 gate all stayed green (an unregistered command is unreachable from everywhere, so the refusal check passed for the wrong reason).
- (2026-08-17) Assert STATE and STRUCTURE, not return values and copy: a test asserting `completeDeviceLink`'s returned token passed while nothing stored it, and its replacement asserting the absence of the string "Helper access token" passed while that exact box was on screen (the phrase was the field LABEL; the heading differs). Assert the step the machine is in and the elements rendered — neither can be satisfied by the wrong screen.
- (2026-08-05) Test at the altitude where the DECISION is made, not where the effect lands — AC12 asserted `cache_control` at the adapter while callers cached the wrong turns in both directions (ADR-0012). Per-request switches belong on the call; the test belongs on the caller.

## Trusting a green run

- (2026-08-19) **A harness failing before it writes results is an ENVIRONMENT verdict, not a red suite.** `pnpm --filter desktop gate` exited 0 with "FATAL: shell process exited before writing results" because a `snug-desktop` left over from an interrupted run still held the single-instance lock — the new shell was killed on launch, so ZERO checks ran. Read as "the gate is red" it would have blocked a correct branch; the same shape as the billing-blocked CI above (no steps executed, rendered as failure). The distinguishing question is always *did the checks RUN?* — a harness that produced no verdicts proves nothing in either direction. This one names its own fix in the failure text (`ps aux | grep "[s]nug-desktop"`, kill the stale PID, re-run); keep that property when writing any harness that can be defeated by leftover state.
- (2026-08-13) A lane's green is a sample of a different distribution; the integrating claim is the forced ROOT run (`turbo run test --force`, showing `Cached: 0 cached`) — repeated, because the catches came on the fourth and tenth runs.
- (2026-08-10) The turbo cache replays stale greens, and dependents resolve workspace packages via `dist/` — after any mutation, re-run with `--force`; mutate `src/` and rebuild (or `dist/` deliberately, then restore) or you are proving nothing.
- (2026-08-11) Run turbo from the REPO ROOT — inside a package dir it silently scopes to that package's graph (a 19-task run became 4). Every package's `test` script is tsc-gated now; keep that uniform, and when enabling a type gate read the whole backlog — 2 of 40 hidden errors were assertions voided behind `as` casts.
- (2026-08-06) A suite is proven only when shown to RUN: watch for "no tests"/"failed to load", and verify loadability in isolation on a cold `.vite` cache — warm sibling resolvers let a phantom `zod` import pass every batch run. Every runtime import needs a dep in that package's own package.json; fix by removing the import, not adding the dep.
- (2026-08-10) An empty grep on a file you expect hits in needs a second tool (`grep -a`, ripgrep, Python) — one NUL byte made grep silently print nothing and "confirm" a deletion. No output is a possible tool failure, never evidence of absence.

## Real browsers & rendered surfaces

- (2026-08-22) **An href assertion proves a link EXISTS; only a hit-test proves anyone can click it.** The desktop-only badge became a `<Link to="/download">` (ADR-0047) and its jsdom test pinned tag + href — while every real pointer click landed on the tile's flex-stretched card button, which covered the absolutely-positioned badge in hit-testing (both z-auto; the button is the LATER sibling). The tag looked clickable, hover worked, and the link was dead for weeks. jsdom cannot see this — `elementFromPoint` and paint order live only in a real browser — so any interactive element that OVERLAPS another control needs a Playwright click-through spec (Playwright clicks by coordinates with hit-target checking, so occlusion reds it; `e2e/desktop-badge.spec.ts`, mutation-verified). Found by a browser walk, not a suite.
- (2026-08-22) **A className with no CSS rule fails as silent layout jank, and nothing checks the binding.** `className="row"` was used in 8 places (vault setup/unlock, wizard) while no stylesheet defined `.row` — the intended `.field-row` existed the whole time — so password inputs and their "show" buttons collided; every suite was green because class→rule resolution is asserted by nothing. When layout misbehaves, grep the stylesheet for the class BEFORE debugging flex; after fixing, ban the dead class with a source scan (`unstyledRowClass.test.ts`) so it cannot creep back.

- (2026-08-19) **A bridge error is an OBJECT, so `result.error || 'fallback'` renders the literal text "[object Object]".** Six call sites in one starter had it. The app recovered from a refused sync exactly as designed and then described the failure uselessly — replacing the one thing the user needs (what happened, and whether retrying helps) with noise, at the moment they are wondering whether their data is safe. A unit test of the formatter would not have caught it, because the defect was in the CALL SITES: the guard that works is a source sweep asserting no `\w+\.error ||` survives in authored code. Two corollaries. First, a demo harness must reproduce the contract's GUARANTEES, not just its happy path — a stub that ignored `snug:net-request` left the app hung on a spinner and nearly sent me hunting a timeout bug in shipping code, when the real host always posts a terminal frame. Second, when a scripted multi-anchor edit asserts and one anchor misses, it can write NOTHING while looking like it worked; I then tested a binary without my change and diagnosed a phantom. Apply such edits one anchor at a time, or make the failure loud.

- (2026-08-19) **"Does it survive a relaunch?" is its own verification step, and no suite performs it.** The Gmail starter fetched a mailbox and kept every message in React state — no `useAppDB` call anywhere — so closing the app threw the whole sync away and the next launch showed the demo again. The shape validator, the extracted-core suite and a full browser pass were all green, because none of them RELOADS the frame. On a platform whose premise is a user-owned portable file (ADR-0007), any app that fetches must be watched across a close, with a harness whose storage outlives the iframe. Two follow-on rules the same bug taught: derive "is this the demo?" from ROW PROVENANCE (Ledger's `sample` column) rather than a session phase, because a phase starts fresh on every launch and a row does not; and never commit a zero-result sync — a throttled or refused fetch returning nothing would delete the real mailbox out of the user's file and revert them to sample data permanently.

- (2026-08-19) **A typo'd property name is `undefined`, not an error — so "the app never boots" can pass every gate.** The Gmail starter's readiness check read `app.ready` where `useSnugApp` returns `isReady`, and it sat on its loading skeleton forever. Nothing failed: the shelf validator checks SHAPE (single file, hooks byte-identity, announce fields), and an extracted-core suite evaluates the pure region by design and never renders. Both gates were honestly green about what they measure, and neither measures "does the first screen appear". Every starter needs one real-browser boot against a stub host before it ships — the cheapest possible check, and the only one that covers the failure a user meets first. Sibling apps are the reference for host-facing property names; read one rather than recalling the hook's shape.

- (2026-08-18) **An emoji is not an icon: it ignores `currentColor` and cannot be themed.** A `🔌` glyph rendered as a faint monochrome outline that read as *disabled* beside its neighbours, and would not have restyled with light/dark — while a geometric glyph (`⚯`, matching the rail tabs' existing `✎ ◍ ✧ ⧉`) inherits the button's colour and hover state. **Both versions passed every test**; only the screenshot showed it. When a change is "just an icon swap", the rendered pixel is the only verification that means anything — and check the codebase's existing glyph vocabulary before inventing a second one.

- (2026-08-19) **"Fixed on disk" and "fixed for the user" are different claims — verify which one you are making.** A Ledger layout fix was correct in `examples/ledger/app.html`, screenshotted, and covered by tests; the owner re-reported it unchanged. Installing a starter COPIES its html into the user's library (`RunView.tsx:410`) and the run path reads that snapshot forever (`:457`), so the fix could never reach an installed copy — and neither exit worked (`delete` cascades irreversibly to the app's data/chat; "reset to factory" restores the pinned v1 of the INSTALL, i.e. the same stale bytes). **The owner's screenshot proved it before any code was read**: it showed a `dashed` border, and the new CSS contains that word only inside a comment. When a verified fix is reported as still broken, diff the artifact the user is RUNNING against the one you edited before re-opening the diagnosis — and for any content that is copied at install/import time, name the update path in the same change that ships the content.

- (2026-08-17) A rebuild the SHELF cannot show is a rebuild the owner reads as "it did not land": the starter tile derives its label from the FOLDER (`folder.replace(/-/g,' ')`), so Telepath still read "whatsapp" — and four other renamed starters read as their folders too. Whenever an artifact is renamed, grep for every surface that derives a user-visible string from its identity key; the identity must stay the key, and the label becomes its own declared field.

- (2026-08-15) A mocked persistence/bridge layer accepts strings a real engine refuses — Standup's `DEFERRABLE` column name (SQLite reserved word) passed every mocked-bridge check and failed only under real sql.js in a real host ("storage hiccup" on screen). An app's DDL must execute against the real engine once before it ships, and the real-browser pass is where that happens; screen the identifier list against the engine's reserved words when authoring generated schemas.
- (2026-08-14) Geometry defects ("one char per line", "overlaps", "cut off") close only by measuring the rendered box in a real browser — `getBoundingClientRect()` ratios in Playwright; jsdom rects are 0×0 and stylesheet-text assertions pass on broken layouts. When a repro fails, suspect the ELEMENT (`.llm-summary`, not `.llm-block`) before the mechanism.
- (2026-08-06) A sandbox/CSP flag disables whole DOM behaviors, not just channels — C2's `allow-scripts` blocks form submission before `submit` dispatches, so `<form onSubmit>` apps were jsdom-green and browser-dead. Enumerate what a flag disables; encode each item as a validator lint plus one real-browser probe per flow.
- (2026-07-31) Assert the enforcement SIGNAL, never the API return value — Chromium's `sendBeacon` returns true even when `connect-src` blocks the send; use `securitypolicyviolation` events and absence of network effect.
- (2026-08-07) Never let CSS generated content carry a fact a checker must verify — a counter on an unnumbered h2 shifted every section number, invisible to source greps AND PDF text extraction. Numbers go in literal text; budget one visual pass over rendered pages.
- (2026-08-06) Probe browser capabilities on a real origin, never `about:blank` (not a secure context — `navigator.gpu` absent there); demand the working handle (adapter/device, not the API object), and vary channel × headedness before believing an absence.
- (2026-08-03) OPFS persistence-across-reload claims need `launchPersistentContext` with a disk-backed profile, a bytes-on-disk wait plus settle beat before navigating — ephemeral-context OPFS dies across hard navigations, and `page.route` stalls vite module loading.

## Sandbox, credentials & cross-package seams (C1/C2)

- (2026-08-20) **A security predicate that re-spells a grammar it does not own diverges on exactly the inputs the grammar was written to handle — and the failure direction is silent no-scrub, not refusal.** The provider lane's hand-rolled `snug-connection://` regex missed `SNUG-CONNECTION://` and whitespace-padded spellings that the executor (case-insensitive scheme, trim + `\t\n\r` strip BEFORE parsing) happily served — raw sidecar bodies into the model context, green suite, because tests only drove the canonical spelling. Classify by CALLING the canonical parser with the owner's own normalization, share the row predicate with the sibling lane, and test the non-canonical spellings the owner accepts.
- (2026-08-20) **A scrub that rewrites the receiver's structure breaks the contract it rides on — exempt structure explicitly and pin each carve-out with REAL shapes.** The dialable-digit rule rewrote ~35% of real `crypto.randomUUID()` requestIds to `[number]` (silent echo-correlation break the suite missed because its fixture was `'req-1'`), and case-insensitive matching would let a contact saved as "Home" destroy a `home` schema property plus its `required` entry. Ids now pass verbatim and schema keys stay untouched — each carve-out a DISCLOSED residual channel, each pinned by a test built from real id/schema shapes. When redacting data someone downstream must parse, enumerate the structural fields first.
- (2026-08-20) **Module-global session state outlives the store it describes; enumerate the swap/wipe seams and reset at every one.** The harvest's in-memory Set survived DB import and connection revoke, so one user file's contacts could re-persist into another file, and a deliberate db-level PII wipe was silently undone by the next poll's write-behind. Any module-level cache derived from a swappable store needs a production reset called at every seam that swaps or wipes that store (here: import, pull-merge, restore, revoke, deleteApp), the seam list in the module doc, and a test that a wiped value stays wiped.

- (2026-08-21) **A permission scoped to a WINDOW says nothing about the FRAMES inside it — so a new IPC command's danger is bounded by the invoke-key gate, and the only proof of that is a per-command keyless probe.** Adding `tauri-plugin-updater` puts `download_and_install` — arbitrary binary installation as the user, strictly worse than anything the shell had — one reachable IPC call away from every sandboxed app iframe. The tempting reasoning is "the capability is scoped to the main window, so iframes are excluded", and it is wrong twice: capabilities are per-window and the main window IS the webview containing the iframes, and registration is per-command so a family-level check cannot see a command added to the wrong handler list (`gate/ipc.ts`'s own amendment-16 doctrine, written for exactly this). Each new command therefore earns its own keyless srcdoc probe plus the positive twin proving the main frame CAN dispatch — a refusal check over an unregistered command vouches for nothing. Two design notes the shape produced: a probe for `plugin:process|restart` announces its own failure loudly (a dispatched restart kills the gate mid-run, which IS the correct verdict), and a `download_and_install` probe uses a nonexistent resource id so a dispatched call errors rather than installs.
- (2026-08-17) A refusal that is TOTAL refuses your own callers too: `/pair/*` was correctly barred from apps through the only command that existed, so the wizard could never pair either. When adding a guard, name the surface that legitimately needs the guarded thing and test that it still works — and split by COMMAND identity, not a `{wizard:true}` parameter, because a parameter is a claim the caller makes and an app can make any claim.
- (2026-08-17) When a host→app push channel is hard to make safe, push the INVALIDATION, not the data: `hostEvent` frames ride the ordinary 256 KB class and the runner's `post()` drops an oversized frame SILENTLY, and they carry no `instanceId` for a hand-rolled app listener to check — so content batches could vanish undetectably AND a stale sender was indistinguishable. Forwarding `{jid, kind, ts}` doorbells fixed both: the frame cannot outgrow its class, and a stale hint costs one redundant GOVERNED refetch instead of injecting state (ADR-0034).
- (2026-08-17) Every negative reachability check owes a POSITIVE twin: `ipc-sidecar-fetch-refused` passed for weeks while the command was unregistered — an unreachable-from-everywhere command satisfies an unreachability check perfectly. Pair each "X cannot reach Y" with "the legitimate caller still can", or the refusal check vouches for nothing.
- (2026-08-17) A locally-spawned helper is reached by a PURPOSE-BUILT command over a unix socket, never by widening the host ceiling: the ceiling is host-granular (`isHostAllowed` drops the port) and `CONNECTION_HOST_RULE` is LDH-only, so `127.0.0.1:8787` is unstorable and bare `127.0.0.1` would grant every loopback service on the machine. Its symbolic host is an IDENTITY for the ceiling, so the executor must ROUTE on it rather than dial it (ADR-0032).

- (2026-08-20) **An allowlist of SHAPES is not an allowlist of VALUES, and the difference is a credential leak.** Bounding a provider's error body to "a named field of a recognized envelope, capped at 160 chars" reads like a guard and is not one: shape recognition chooses which FIELD is forwarded and never vouches for what that field CONTAINS — so `{"error_description":"bad token rt-…"}` is forwarded verbatim, through the field a reader most wants. It also defeats the tempting narrower fix ("only forward recognized JSON fields"), because that IS the recognized field. Only a value scrub, against a candidate set the seat can actually name, bounds content. When a bound is proposed, ask which of volume / shape / content it constrains, and say so in the comment — the first cut of this fix called itself an allowlist that "fails closed" and was believed.
- (2026-08-20) **Scrub on both sides of any step that DECODES, or the scrub ran on the wrong side of it.** `JSON.parse` decodes `\u` escapes and it runs INSIDE the extractor, after the caller's scrub — so an escaped echo defeated exact-substring matching on the raw text and reconstituted the secret character-for-character in the extracted field, on BOTH seats that call it. This is not the documented re-encoding boundary (base64/hex arriving in a different form, which no substring matcher can catch): the value arrives in the SAME form after a decode we perform ourselves. Fix it in the decoding function, not at each call site — the decode is that function's own act, and a caller that scrubbed correctly on the way in should not have to know what happens downstream.
- (2026-08-20) **A comment asserting an ordering IS a claim, and reviewers will believe it instead of re-deriving it.** The sidecar branch sat 28 lines above the mutating-confirm gate under a comment reading "the mutating-confirm gate has answered" — so every WhatsApp send reached the helper with credentials injected and no confirmation, voiding ADR-0033's standing-approval governance for the exact connection class that ADR exists to govern. Prose that states what has *already run* is the cheapest thing in a file to falsify and the most expensive to disbelieve; when a branch's safety depends on position, pin the position with a test rather than a sentence.
- (2026-08-15) Re-pointing an existing delivery surface at a NEW READER re-opens every scrub decision made for the old one — the executor's body scrub deliberately let a device echo its own LAN address because delivery ended inside the sandboxed iframe; LLM-bound delivery exports the same bytes to a third-party API. When a consumer class changes (app→LLM, UI→log, local→synced), re-derive what the scrub protects per reader, and put the new reader's scrub at the new reader's altitude.

- (2026-08-18) **Pin the host you PROBED, not the brand's pretty alias — and a moved pin owes a walk of every consumer.** SimpleFIN's `bridge.simplefin.org` is a 302 alias of the real serving host `beta-bridge.simplefin.org`; the CORS probes ran against beta while the registry pinned the alias, so every REAL token refused at the ceiling gate on the owner's first walk. A "VERIFIED by live probe" comment must name the exact host the probe hit (`curl -sI` the apex first — a 302 IS the answer). And when a registry host moves, enumerate the consumers that memorized the old one: the drift migration's gate was host-blind (fields/seats/scopes only — approved rows could never heal), and the installed app's HTML had the host baked in (installed starters never receive rebuilds — apps should address `snug-connection://<slot>` and never name a host they didn't need to know).

- (2026-08-18) **A bound the code arms must NAME ITSELF when it fires — and be sized against the slowest legitimate call, measured.** The executor's 15 s wall clock predated any slow provider; SimpleFIN's first 13-month pull legitimately outlives it, and the abort surfaced as the transport's own noise ("Request canceled", tauri's Rust error) pointing nowhere near the cause. - (2026-08-12) A guard expressed as a request OPTION (`redirect`, `signal`, TLS flags) is voided by a new transport by default — tauri's shim never reads `init.redirect`, silently disabling `NET_REDIRECT_BLOCKED` on desktop and forwarding injected credentials through redirects. Read the transport's option-parsing source; test that the option ARRIVES. A seam guarantees shape, never semantics.
- (2026-08-13) When a lane spans two packages, assert the seam's IDENTITY from the integrating side (`platform.lanFetch toBe lanFetch`) and mutate the seam — deleting the wiring left both packages' suites green, twice, by construction: one owns the implementation, the other owns a stub, nothing owns the wire.
- (2026-08-13) A new capability/placement seat rides EVERY surface the existing seat rides — schema, lint, admission, executor, scrub, REVIEW COPY, migration — or the task file says why not. `queryTemplate` shipped past the wizard's review screen: a seat that skips consent is admitted for free (ADR-0017's price).
- (2026-08-12) A guard that both REFUSES and REWRITES drives both halves from one resolution — Guard 2b's accept-list was widened while `applyRegistryValues` still rewrote the user's chosen option back to the default. Assert the PERSISTED shape, never "not refused"; and a plan's "no changes to X needed" is a claim to trace, not a scope note.
- (2026-08-15) A change GATE and its disclosure SURFACE must share one comparison semantics, derived from what the value MEANS — the scope-drift digest compared ordered arrays while the diff screen rendered set membership, so a reordered-but-equal list staged an approval whose every rendered line read "unchanged", and approving the invisible diff destroyed a working connection's tokens. Ask "is this value a set or a sequence?" once, and derive both seats from the answer (RFC 6749 scopes are a set).
- (2026-08-15) A destructive act paired with a state transition runs BEFORE the transition when the pre-state is the recoverable one — token invalidation after `reapproveConnection` meant a mid-write throw stranded a promoted row whose drift migration would answer 'none' forever; inverted, a throw leaves the old requirement plus the staged diff, and the next wizard open heals it. Pin the ordering with a call-order spy, not a comment.
- (2026-08-11) Where an approval gate's whole signal is one number, REFUSE the operation classes the number cannot describe — `sqlite3_changes()` is 0 for all DDL, so `DROP TABLE` previewed as "0 rows"; it is also sticky, so attach it by operation kind. And absence of local state is never consent: trust comes from a provenance-bearing caller (`trustedOrigin`), default untrusted.
- (2026-08-06) When a security guard blocks your test fixture (SSRF guard vs a 127.0.0.1 stub), the guard is working — never loosen it or add a bypass; make the fixture look like what the guard should allow (`stub.snug.test` via host-resolver-rules), scoped so the allowance cannot leak. `Failed to fetch` is usually CORS, not TLS.
- (2026-08-14) A "does X reference Y" check over template data must match the reference TOKEN in the value grammar (`{{...field...}}`), never a substring over serialized structure — header NAME `hue-application-key` satisfied a substring check for field `application_key` (ADR-0025 verify probe).
- (2026-07-31) Port the hardening, not the bugs: carry the DB invariants + host-freeze from the hardened source system and the PKCE/refresh/scrubbing from the original; strictness is never a flag (C1).
- (2026-07-31) One contract must never live in two artifacts by convention — inject from one source or byte-compare in CI; for CI-only artifacts no local suite executes (`gate/run-gate.mjs`), DERIVE the value by parsing the source of truth and pin the derivation with a fast local test. - (2026-08-18) **A new writer of a state re-opens every consumer that assumed the old starting state.** ADR-0037's autostart+boot-resume made "helper already linked" the COMMON state at wizard-open — and the same branch's new QR poll only knew "no code yet", so it spun its full deadline against a healthy helper and told the user to restart (which re-linked the helper and reproduced it forever). ## Diagnosis & stream forensics

- (2026-08-17) **Reproduce the failure before fixing it.** Two consecutive misdiagnoses of one symptom (an old Node on the GUI PATH; a stale binary) were both REAL problems that were not the reported one — each inferred from plausible evidence and shipped without confirmation, costing the owner three attempts at the same button. When a symptom persists after a fix, the first question is "did my fix actually run", answered by observing, not reasoning.
- (2026-08-17) Before asking "what could cause this?", ask "what would I READ to settle it?" — three wrong theories (stale `dist`, an install-source redirect, a stale binary) died in seconds against `~/Snug/user.sqlite`, the producing function, and `creds.json`. Enumerate the artifacts that hold the answer (the DB, the state file on disk, the function that produces the value, the live process's own reply) and read them FIRST; a plausible cause you can name is not evidence, and acting on one spends the user's attempts, not yours. This is the reproduce-first rule applied one step earlier.
- (2026-08-18) **A false positive in a detector that triggers a DESTRUCTIVE remedy is worse than no detector.** A "half-linked session" check read `creds.registered !== true` as broken; in baileys@7.0.0-rc14 that flag is set in exactly ONE place (the phone-code path), so every QR-paired session — the only kind this helper makes — reads false forever. The app told the owner to re-link, re-linking WIPED the working session, and the loop repeated twice before I checked the library. Before wiring a detector to anything that deletes, resets or re-prompts: grep the producing library for every site that WRITES the field, and test the predicate against a real healthy artifact, not only against the broken shape you imagined.
- (2026-08-18) Detect on the MATERIAL a state needs, not on a flag that happens to correlate: "can this session resume?" is answered by `account` + a non-empty `signalIdentities` (what pairing actually writes), which is flow-agnostic — the `registered` flag was a phone-code artifact that said nothing about QR sessions at all.
- (2026-08-18) Every spawn owes a REAP, and the reap needs a caller: `sidecar_ctl("stop")` was implemented, tested and reachable — with zero callers and no exit hook — so quitting the shell orphaned the helper, the next launch spawned a rival against the same session store, and two writers wedged the link. The symptom ("it loses my connection across restarts") pointed at credential persistence, which was blameless. When a child process outlives its parent, suspect the missing lifecycle half before the data layer — and pin the hook at the source level, because a hook nobody calls is the untested wire in its purest form.
- (2026-08-19) **An exit hook only covers the exits that run it — the child must also be able to outlive nothing.** The lesson above was fixed by giving the reap a caller, and the wedge came back anyway: `shutdown()` runs on a CLEAN quit, while a crash, `kill -9`, or a `tauri dev` rebuild runs nothing, so the helper was orphaned exactly as before and the next launch's rival produced a permanent `conflict type=replaced` loop. A supervised child needs a lifecycle answer from BOTH ends — the parent reaps on exit, AND the child dies when its parent does (watch for a CHANGED ppid, not `ppid === 1`: a Linux subreaper adopts orphans to some other pid). The corollary that made this task bigger than one file: a fix living only in the child cannot retire the orphans that older builds already leaked, so the parent also needs to reap a process it did not spawn — and that path must verify the target's command line, never trust the pid alone, because pids are recycled and a fix that kills a stranger is worse than the bug.
- (2026-08-17) Ask what SURVIVES: a restart (the sidecar token was `createMemoryStore` in production, so every helper restart invalidated the host's stored copy) and an interruption (a flow that died mid-link left `registered:false` + `me` on disk and wedged every retry, because nothing ever cleared it). Any durable state owes an answer to both.
- (2026-08-18) **A separately-installed artifact is a SECOND deploy target: rebuilding the repo updates nothing it runs.** The sidecar helper is copied to `~/Snug/helpers` by `install:helper`, and two full hardware walks ran against a pre-task build — empty store, "syncing 0%" forever — while every suite in the repo was green against the new code. A running process is a THIRD target: it keeps the code it loaded at spawn, surviving any reinstall until respawned. When deploying a change, enumerate every copy of the code that exists (repo, installed artifact, live process) and verify each moved; a version stamp checked by the spawner is the durable fix (filed in next-steps).
- (2026-08-18) **Classify failures before charging them to a retry budget: a throttle is evidence about the MOMENT, a refusal is evidence about the TARGET.** Meta's `rate-overlimit` (287 hits in one evening) consumed the per-group retry budgets of perfectly loadable rosters and permanently wrote them off, while `item-not-found`/`forbidden` — definitive answers — were being retried five times each, learning nothing. Throttles now pause the WHOLE sweep on an escalating cooldown and charge nobody; definitive refusals write off after one attempt. Two corollaries earned the hard way: a guard tuned to one cadence becomes a bug when the cadence changes (a 20 s stall detector hid the pill inside every backoff gap the new retries were DESIGNED to have); and a failing-only steady state that persists nothing is undiagnosable from disk — aggregate failure CLASSES into the durable artifact, because that is what turned "no new names, no idea why" into three named causes in one read.
- (2026-08-18) **An alias mapping needs value propagation in BOTH directions, or one-way resolution leaves known data unreachable.** Push names learned from group rows land under the sender's LID spelling; the DM with the same person is keyed by phone number; `resolveIdentity` maps LID→phone only — so the directory KNEW the name and the chat list still rendered a bare +number. When two spellings identify one entity, recording the pairing must also copy every value already held under either spelling to both (or lookups must consult a reverse index); test with the value under each spelling and the lookup from the other.
- (2026-08-18) **A flush hooked on process death is only as real as the signal the reaper actually sends.** `process.once('exit', flush)` shipped with a comment claiming "the reap is SIGTERM → clean exit" — but the shell reaped with Rust `Child::kill`, which is SIGKILL, and no handler of any kind runs under SIGKILL. Before claiming an exit-path handler runs, read the reaper's send (`kill()`? which signal? which platform?) and pin it with a test whose child can only produce the observed artifact FROM the handler (a marker file written inside the TERM trap — a SIGKILL-only reap can never fake it).

- (2026-08-14) One symptom can have several independent producers: when a symptom rides shared state, grep the FLAG for every writer before claiming a fix — the pending-ticker had three producers and was "fixed" wrongly twice. State which producers you closed and which you did not.
- (2026-08-12) Diagnose "nothing happens" from the user's first visible surface inward, never from the component nearest the feature — the Coinbase CTA died at `openConnectionWizardForApp`'s zero-row guard, a layer above both diagnoses. An error state is not surfaced until something RENDERS it; grep for the subscriber.
- (2026-08-12) A causal chain or ranked hypothesis is fiction until the suspect input runs through the real code — a 3-line probe of `balancedObjects` refuted the #1 theory before any repro, and recon killed a "replayed conversation" mechanism a fix would have been built on. Pin every refutation as a characterization test so the dead theory cannot be re-inherited.
- (2026-08-05) A state variable's meaning is relative to its reader: when repointing a surface at existing state (`steps` → live status line), re-ask what the state means at start/mid/end/error/abort, and prefer the signal whose name matches the new question (`busy`). One test must drive real state through a full turn.
- (2026-08-05) Replacing a bound means re-deriving it: enumerate every retained field and every event that can GROW an existing record — the byte budget's size function omitted fields (off by 166,000×) and its keep-the-newest escape hatch exempted the one entry that kept growing. One adversarial test per growth path.
- (2026-08-12) When a stream looks truncated but `stop_reason` says finished, compare `usage.output_tokens` to delivered chars and look for tail-references-to-missing-head — a big gap convicts DELIVERY, and no parser change may ever make corrupt bytes "parse".
- (2026-08-12) To clear or convict a framing layer, replay a real captured stream through the real code split at EVERY byte boundary and assert byte-identical assembly; keep the suite as a tripwire — if it ever reds, your layer has ACQUIRED the bug (P0, not flake).

## Agents, reviews & process memory

- (2026-08-21) **A control that exists in one seat and not its sibling is the highest-yield thing to look for, and the codebase usually already explains why the control is needed.** The pre-launch audit's four security fixes were all this one shape: the percent-encoded scrub candidate existed in `connected-fetch.ts` under a comment spelling out exactly why raw-only misses base64 credentials, and `oauth-service.ts` never inherited it; the confirm URL was rendered by the chat-lane card and not by the modal; the per-command IPC probe covered `sidecar_fetch` and not the strictly more dangerous `sidecar_wizard_fetch`. In each case the *reasoning* was already written down — nobody had re-asked "which other seat has this shape?". That question costs one grep and it found what four parallel adversarial lanes were dispatched to find. Ask it whenever a control is added, and again before any launch.
- (2026-08-21) **A mechanical check is evidence only for the claim its MECHANISM supports — and the gap between the two is invisible precisely because the check is green.** Two of the eight pre-launch findings were defects in checks, not code. `check-threat-model.mjs` was cited in the threat model as the guard that keeps the delta ledger honest, while its only count assertion was `actual.size >= 8` — a floor that passes at twelve, never reads the §1 prose, and was therefore structurally incapable of catching the "eight deltas vs twelve rows" drift it was being credited with catching. The OAuth error-echo tests were cited as the guard against credential-bearing error bodies, while every fixture token was `[A-Za-z0-9-]`, for which `encodeURIComponent` is the identity — so the encoded-spelling leak was *unrepresentable* in that suite and the tests passed whether or not the defense existed. Both extend the 2026-08-20 "state what the check does NOT prove" rule one step: also ask whether the fixture can EXPRESS the failure, because a test whose inputs cannot exhibit the bug is not weak coverage, it is zero coverage wearing a green tick.
- (2026-08-21) **A guard written as a list of forbidden secrets publishes them; hash the list and recover the sample rather than naming it.** The pre-flip scan found the repo's most damaging leak in the file whose job was preventing leaks — a test carrying the real ancestor-system codenames as plaintext, annotated as "ancestor codenames", i.e. the single most rewarding file in the tree for anyone curious about provenance. Hashing the tokens keeps every property that matters (runs everywhere, no fixture, still fails on a real regression, still names the offending file) and loses only the ability to print the matched token. Two corollaries the fix earned: the planted-token test must RECOVER its sample by brute force over the hash set rather than hardcoding one, or the file still contains one forbidden string and the scrub gate can never reach zero; and a "must be zero" gate whose term list includes ordinary English (`feat` matched 322 lines) or the owner's own public byline can only ever be waved through — which is how the plaintext leak sat unnoticed under 353 false positives.
- (2026-08-21) **A threat model's own scope note is a debt, and the next pass inherits it silently unless someone reads it.** v2 stated plainly that its adversarial pass covered only the four new surfaces and that "the rest of this document is v1's, re-checked mechanically but not re-attacked". Nothing was hidden — and a launch review that simply updated v2 would still have shipped v1's audit as current, because the limitation lived in a header paragraph nobody re-reads. Treat every "what this version did not do" note as an open work item with an owner, not as disclosure that discharges itself; the honest sentence is what makes the debt findable, but only if the next pass is briefed to go looking for it.

- (2026-08-20) **A staged-but-never-pushed downstream branch is drift no changelog can see.** The edition-1 whitepaper sat 13 days as a local `docs/whitepaper-v0.1` branch in the spec clone: the spec-changelog tracks PUSHES, so its flow never saw the branch, and the v0.3 publication would have silently orphaned it had the owner not said "check for pending branches". Before any downstream publication, `git fetch --all && git branch -a -v` in the downstream clone and DISPOSITION every unmerged branch — land it (rebase keeps one-commit-per-task history linear), or delete it with a recorded reason. Staging without the push ask parks the artifact in the one place no invariant checks.

- (2026-08-21) **A plan review's value concentrates in the findings that say "this cannot work", not the ones that say "this could be better" — and those come from reading the CODE the plan names, not the plan.** Twenty-one findings survived adversarial refutation on the hardening plan (0 refuted, which is itself unusual and probably says the refuters were too easily satisfied). Of the twenty-one, two were blockers, and both were of one kind: the plan asserted a delivery mechanism ("bump the version and installed copies take the docs via the existing update channel") that the existing code could not perform, in two independent places. The other nineteen improved the work; those two were the difference between shipping an item and shipping the appearance of one. The distinguishing feature is what the reviewer read: the blockers came from opening `starterUpdate.ts` and tracing the offer and apply paths against the plan's sentence, while the improvements came from reading the plan closely. **So brief the reviewer to verify the plan's mechanism claims against the named files first, and treat "the plan says X will happen — does the code that must do X actually do it?" as the highest-yield question available at Gate 2.** A plan is a claim about a codebase; only the codebase can refute it.
- (2026-08-20) **The plan review and the diff review catch DISJOINT defect classes — run both on High tier, and expect the second to contradict the first.** The fresh-context PLAN review found design bypasses (a well-formed `responseSchema` as an in-band smuggling channel; a whole second lane with no app-message wire); the eight-angle DIFF review found implementation divergences the plan could not contain (a re-spelled grammar, UUID mangling, an approved-only predicate that unbound every imported file) — and one diff finding ("wipe on import") was correctly resolved AGAINST the reviewer because a sibling finding showed the import path needs the directory. - (2026-08-18) **Never `git add -A` on a branch you did not cut from a clean tree.** A hotfix branch was cut off a `main` carrying the owner's UNCOMMITTED work for another task; the blanket add swept 31 files and five commits' worth of a per-app-model-selector feature into a squash merge titled for a WhatsApp bug. Nothing was lost (the diff against its own branch was empty and its tests passed), but the attribution is now unrewritable without force-pushing shared history. `git status` BEFORE the first add, and stage explicitly when it is not empty — the cost is asymmetric: seconds to check, permanent to misrecord.
- (2026-08-18) **Urgency is the condition the gates exist for, not an exemption from them.** A shipped bug that was actively destroying the owner's data got fixed, verified and merged with no task file and no done-index entry — Gate 1 skipped precisely when the change most needed a record. Write the task file first even when the fix is obvious; it takes a minute and it is the only thing that survives the session.

- (2026-08-12) Any agent that WRITES gets `isolation: "worktree"` — file-disjoint lanes still share the git index (raced commits, a stash displacing in-flight work), and mutating reviewers in a shared tree measure each other's breakage. Concurrency without isolation is only safe for read-only reviewers; otherwise serialize commits through the orchestrator.
- (2026-08-13) Re-derive consequential agent claims from primary sources before acting on or repeating them — a platform-blocking verdict was confirmed link-by-link in the pinned crates first; a reported "production typo" was another reviewer's live mutation. The more concrete the claim, the more tempting to skip exactly the check that would expose it.
- (2026-08-19) **Propose into a codebase's stated doctrine, not past it — the file usually says no in a comment you have not read yet.** A plan proposed adding an `'attention'` member to `ConnectionWizardStep`; `ConnectionWizardSheet.tsx:1842` carries a block titled "WHY NOT NEW STEPS" rejecting exactly that, and the fresh-context review traced three concrete breakages it would have caused (`showDiff` is step-keyed and would go false; `nextStep` early-returns `'done'` for LAN rows ABOVE its switch, so a LAN row with a live failure would skip review; three unproven-row catch-alls key on `step !== 'review'` and would all fire underneath the new screen). The correct shape — a DERIVED gate — was the one the file already used four times. Before extending an enum or state machine, grep its own module for the rationale comments; a codebase that solved this problem before wrote down why.

- (2026-08-20) **A mechanical check earns exactly the claim its mechanism supports — write down what it does NOT prove, in the document that leans on it.** Hash-pinning eight source documents proves none of them MOVED beneath the consolidation; it says nothing about whether their residuals were CARRIED into it. The checker was green while three were missing, and the Gate-5 reviewer found them by reading the deltas — the thing the check exists to force, and cannot perform. State the limit beside the mechanism, or the green becomes evidence for a claim nobody verified.
- (2026-08-20) **A fresh-context reviewer runs against the tree it can see, so a mid-edit working tree produces confident findings about code that no longer exists.** One review reported the branch red and the harness broken, having sampled between a red test and its fix, then compared against a journal line from an earlier commit; probing the harness directly (a deliberately failing test) showed it reporting the failure correctly. Commit to a coherent state before dispatching reviewers — and when a finding contradicts something you can measure, measure it before accepting or dismissing it. The same review's other five findings were all real.
- (2026-08-15) A comment's claim about ANOTHER surface is a pointer to verify, never evidence — ADR-0028's whole "consent is visible" justification rested on a protocol comment saying "`scopes` is what the review renders" while no renderer existed (the fresh-context plan review's blocker). Before citing "X renders/enforces/strips Y", grep for the consumer; a doc-comment can describe an intention nobody built.
- (2026-08-08) Pair every finder with an independent refuter that defaults-to-refuted and must produce a runnable probe, not an argument — 4 of 10 review findings died, each a would-be "fix" to correct code.
- (2026-07-31) Every High/Medium merge gets a fresh-context adversarial review that RUNS probes against the constraint surfaces — pre-merge reviews caught a C1 credential leak via `responseSchema` and a meta-CSP bypass that the authors' green suites missed.
- (2026-08-08) Design review and implementation review find disjoint defect classes — five design reviews bought zero protection against a call-site default mismatch and a missing test. Budget both for High-tier surfaces; "the design was reviewed hard" is zero evidence about the code.
- (2026-08-10) Multi-phase work ends with a WHOLE-SURFACE review tracing one datum end to end, asking at every handoff what the receiver trusts that the sender never guaranteed — two lints disagreeing about "declared" fields was invisible to eleven green per-phase reviews.
- (2026-08-12) A consumer's first act is verifying the producer's work EXISTS in the shared substrate (commits present, symbols grep-able), never trusting the handed-in summary; an empty fan-out result is a tool-failure hypothesis before a no-findings conclusion. Budget one integration probe across independently-green components — the first real boot is a test.
- (2026-08-15) A dependent package's green suite vouches for the producer's last BUILD, not its source: apps resolve `@snugprotocol/*` through `dist/` (package.json `main`), so after editing a package's src, rebuild it BEFORE trusting any dependent's local vitest run — playground ran 103/103 "green" against a two-day-stale auth build while its own fixtures contradicted the new registry. Root `turbo run test --force` rebuilds via the task graph; bare `vitest` in an app does not.
- (2026-08-08) Repeating a journaled mistake means the journal entry is the defect: rewrite it as a procedure change that makes the error unreachable ("commit before any mutation cycle"), never as a caution to remember. "Be careful about X" is not a fix.
- (2026-07-31) Verify any public-facing name (package, command, protocol message) against GitHub/npm/web in the session it is proposed — twenty "obviously free" candidates were all taken.
- (2026-08-07) A document derived from a spec is checked by diffing SETS and MODALITY, not token presence — `MALFORMED` "appeared" while the claim around it overclaimed the spec, and internal C1/C2 doctrine was silently promoted to protocol requirement. Grep the published source for each MUST/never/always before shipping it.

## Storage, config & mechanical edits

- (2026-08-20) **`z.toJSONSchema` drops `superRefine` silently, so an exported schema of a refined contract is always WEAKER than the contract — publish the gap or don't publish.** The net-request export cannot express "no body on GET/HEAD" or the credential-header refusal; a connection-requirement export could express neither the lanHost XOR nor the kind coherence arms. Two rules (ADR-0044): state the gap in the artifact's own home (Appendix C + the SOURCES comment both say "a validator passing the schema has not validated the frame"), and pin the property that DID survive in both directions (strict files must carry `additionalProperties: false`, tolerant files must never) — a one-direction pin lets the next regeneration flip it without a red.

- (2026-08-18) **Putting a per-entity row in a SHARED key/value namespace buys "no migration" and owes a cascade.** `appModel:<appId>` in `snug_settings` skipped a schema bump entirely (ADR-0036 D2) — but `snug_settings` is not app-keyed, so `deleteApp` cannot sweep it by `app_id` and a missed key becomes a silent orphan that later applies to a REUSED id. Whenever a namespaced key is chosen over a column, name the delete path in the same change and mutation-check it. Prefer an EQUALITY delete over a `LIKE` prefix when there is exactly one row per entity: no metacharacter escaping, and no over-match against a sibling id.
- (2026-08-18) **Inheriting a default must be an ABSENCE, not a copy.** Storing no row means an un-picked entity FOLLOWS later changes to the global default, and "pinned" stays distinguishable from "inherited" both on screen and in the file. Copying the default in at first open freezes every entity at whatever the default happened to be that day, and the two states become indistinguishable forever after. Clearing a pick must therefore DELETE the row, not write an empty string — an empty-string row hydrates back as a falsy pick that different readers disagree about.

- (2026-08-03) Never `INSERT OR REPLACE`/upsert into a table you did not define without verifying the uniqueness constraint the conflict clause needs (`sqlite_sequence` has none; UPDATE-then-INSERT-if-zero is safe) — and restoration tests must exercise state that DIVERGES from what the system would re-derive (deleted-max rows), never the coincidentally-equal state.
- (2026-08-03) Durable browser-storage writes go to a NEW fixed-name file (A/B slots + pointer); reads are direct fixed-name lookups with magic checks and brief retries — OPFS teardown truncates in-place writes, and sql.js accepts zero bytes as a fresh DB, so an empty/magic-less read of a file that should exist is CORRUPT (quarantine), never "fresh".
- (2026-08-02) Config readers treat `''` as unset (`||` or trim-check) for any env var with a fallback — `SNUG_MODEL=` present-but-empty defeats `??`; env templates comment optional vars out rather than leaving them empty.
- (2026-08-17) An identifier that LOOKS like a number is not one: WhatsApp addresses people by LID (`123456@lid`, an internal id) as well as by phone jid, and rendering the LID's digits as "+123456" produced confident, wrong phone numbers — worse than a blank, because a plausible value invites trust. Render a formatted identifier ONLY for the address space that defines that format, and resolve the alias (Baileys ships `lidPnMappings` + `lid-mapping.update` for exactly this) before deciding two spellings are two people.
- (2026-08-17) A FAILURE is not a FACT, and caching it as one turns a hiccup into a permanent defect: avatar lookups cached "could not fetch" in the same slot as "has no picture", so one bad moment meant no profile pictures until the process restarted. Cache the negative only when the source states it (a clean "none") — never when the attempt merely failed.
- (2026-08-17) Read the dependency's own `.d.ts` before designing around a field you remember: Baileys reports `unreadCount` ONLY as a sync snapshot and never increments it live (it ships `shouldIncrementChatUnread` precisely because consumers must count for themselves), and `downloadMediaMessage` takes an optional `reuploadRequest` context without which every expired media link silently fails. Both would have shipped as "works in fresh fixtures, broken in real use".
- (2026-08-21) **A glob pattern written in prose inside a block comment can END the comment** — `examples/*/app.html` contains `*/`, so the doc comment terminated mid-sentence and esbuild failed the whole module on the next word. The failure surfaces as a baffling parse error lines below the cause. Spell glob patterns out in words inside `/* … */` comments (or use line comments); the codebase's existing modules already do this, which is why the pattern only ever appears in code strings.
- (2026-08-21) **Inside a template literal, a backtick in a COMMENT closes the string — the sibling of the glob rule above, one delimiter over.** Adding a probe to `gate/ipc.ts` meant writing a comment inside the giant `PROBE_HTML` backtick template; the comment referred to a command name in backticks, which terminated the literal and produced `Expected ";" but found "sidecar_fetch"` — a parse error naming a token two lines from the real cause. The general rule covers both: **prose written inside a delimited region must not contain that region's terminator**, and the terminator is easy to type by habit because the surrounding file uses it for markup everywhere else. When editing inside a template literal, drop the backticks from prose (write the name plainly) rather than escaping them.
- (2026-08-22) **An interrupted build-tool cache write is a THIRD state — neither fresh nor stale — and its symptoms point at your code, not the cache.** A killed Vite dev server left `node_modules/.vite/` holding only `deps_temp_*` (never promoted to `deps/`), so every pre-bundled dep answered `504 Outdated Optimize Dep` and the visible failure was "Failed to fetch dynamically imported module: RunView.tsx" — reading as an app defect, blamed on the newest edit. Compounding signature: THREE orphaned vite instances on 5173/5174/5175 from successive half-killed sessions, the oldest serving a module graph from before a starter was deleted, so "removed starter still shows" and "apps won't open" were ONE environmental cause. Remedy: kill the strays (verify by command line first), delete the app's `node_modules/.vite`, restart. Procedure change so it stays unreachable (per the 2026-08-08 journal rule): root `pnpm dev` (`scripts/dev.mjs`) runs the server+playground pair with SIGTERM teardown of both. Sibling mask, same session: a guard test validating sidebar slugs against DISK plus a STALE `dist/` stayed green while the site errored at runtime — a guard over a derived artifact needs a freshness tripwire (dist mtime vs newest source) or it vouches for an old build forever.
- (2026-08-21) **A derived cache stamped before a schema existed replays entries WITHOUT that schema's defaults — and a filter on a defaulted field then drops everything, far from the cause.** Astro's content-layer cache (`node_modules/.astro/data-store.json`) was populated before `content.config.ts` gave the docs collection its schema; Starlight then filtered `getCollection('docs', data.draft === false)` — a field whose `false` comes from a schema DEFAULT — so every entry vanished and the build failed with "sidebar slug does not exist", while `astro dev` (which re-syncs) was fully green. The dev-green/build-red split plus an error naming data you can SEE exists is the signature; the fix is deleting the derived cache whenever the config that stamps it changes. General shape: any pipeline that persists validated entries must be re-run when the validator gains defaults, because `undefined !== false` silently un-matches every strict-equality filter downstream.
- (2026-08-21) **"Newest file by mtime" selects the build system's INTERMEDIATE, not its product.** `stage-local-desktop` picked `rw.76850.Snug_0.1.0_aarch64.dmg` — create-dmg's read-write scratch image, written milliseconds after the shippable `bundle/dmg/*.dmg` — and would have served users an unconverted image. Recency is not identity: when harvesting an artifact from another tool's output tree, filter by the artifact's naming grammar (here: exclude the documented `rw.` prefix) before ranking by time, and read one real output tree before writing the glob.
- (2026-08-14) A scripted extract-helper replacement must exclude (or run before inserting) the helper's own definition — the replace rewrote the helper's body into self-recursion. A sudden wide failure wave after a "safe" mechanical edit is the suite catching exactly this.
- (2026-08-14) An anchored Edit that consumes a heading must re-emit it verbatim, and append-only files get a headings-only grep afterward — a spec-changelog insert silently orphaned the prior entry's body under the new heading.

## Security features that can lose data

- (2026-08-20) **A recovery path a session cannot reproduce is a recovery path that silently disappears.** The first `SNUGENC1` implementation rebuilt the container from "the secrets this session holds" on every write. A session unlocked with the passphrase alone cannot produce the Recovery Key, so every save quietly dropped the recovery slot — discoverable only on the day the user forgot their passphrase and reached for the key we told them to keep. Re-seal into the EXISTING container (same header, same slots, fresh nonce) instead of rebuilding it. Generally: when a secret grants access, ask what a session that holds only *one* of the accepted secrets will write back.
- (2026-08-20) **Keep "wrong secret" and "damaged file" distinguishable, or you will tell users a frightening lie.** Both fail the same AEAD unwrap, so the naive implementation reports one for the other. Telling someone their passphrase is wrong about a file that is actually damaged sends them hunting for a secret that was never the problem; telling them a file is damaged when they merely mistyped invites them to destroy it. An unkeyed header checksum separates the cases — it does not need to resist an attacker (AAD does that), it only needs to pick the honest sentence.
- (2026-08-21) **When a signature covers one artifact in a multi-artifact flow, say which one — the unsigned half is where the attack moves, and it is usually the half the user reads.** Tauri's updater verifies minisign over the downloaded ARTIFACT; `latest.json` — version, date, notes, and the asset URL — is trusted on TLS to the host alone. It is easy to write "updates are signed" and believe the channel is closed; what is actually closed is *binary substitution*, while *the update prompt* stays fully attacker-authorable by anyone who takes the publishing account. That inverts the design question from "can they install something" (no) to "what can they make the user do" (anything the dialog can say) — which is why the fetched notes render as plain text with no linkification, the version is syntax-gated, and the UX offers no button pointing anywhere but the flow itself. **Name the covered artifact in the ADR and the threat model, then design the UX for a hostile version of every field the signature does not reach.** Generalizes beyond updaters: any flow where a signed payload travels with an unsigned manifest, receipt, or description.
- (2026-08-21) **An erasure needs a WRITE TOMBSTONE: enumerate every writer that can run AFTER the wipe, silence them first, and test by invoking the real registered handler.** The Telepath deep delete wiped the helper's auth store — and the shell's reap is TERM-first precisely so the process-exit flush RUNS, which would have re-written the thread cache into the wiped directory (a `creds.update` from logout teardown re-writes `creds.json` the same way). The fix is a `forgotten` flag checked by every writer, set before the wipe. Two test traps the first cut fell into: letting timers elapse never reaches an `'exit'` handler — grab the listener `process.listeners('exit')` gained and CALL it — and a mutation check proved the debounce-only version vouched for nothing. Related but distinct from the 2026-08-18 flush-signal lesson (is the handler ever RUN?): this one is about a handler that runs and must now say nothing.
- (2026-08-21) **An equivalence test over ONE derived subset does not force the sibling hand-written table — a wizard-only route changes the app subset NOT AT ALL.** Adding `POST /session/forget` to the sidecar contract left the Rust/TS route equivalence green whether or not anyone touched the hand-written `WIZARD_ROUTES`, because that test compares only `APP_ROUTES` and the `/session/` prefix excludes the new route from the derived app subset — a forgotten Rust entry ships the feature dead at runtime with every suite green. When a contract has N restatements, each needs its OWN equivalence pin (the wizard table is now pinned equal to the FULL contract), plus one positive admission test per new entry.
- (2026-08-20) **Renaming a file the product looks for is a data-loss operation until proven otherwise.** The new name is absent, the open path takes its "no file yet" branch, and the user gets a pristine empty database over intact-but-unreferenced data — no crash, no error, no clue. Every derived name moves with it: the sync sidecar (orphaning it manufactured a phantom "divergence" whose obvious resolution discards local work) and the remote sync path (a fallback that reads the old path but writes the new one hands a foreign revision to a conditional write and wedges sync permanently). Read-and-adopt-forward; never rename, copy or delete the user's only copy.
