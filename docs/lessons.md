# Lessons — distilled 2026-08-15

Forward-looking rules only, grouped by theme. **The agent reads this when planning (Gate 2).** The full narratives live in git history of this file (pre-distillation) per ADR-0027. Entry dates are preserved for archaeology. Add new rules to the matching section at Gate 6; when a section outgrows a screen, re-distill.

## Tests that can fail

- (2026-08-24) **A matcher's subject is the TOKEN its extractor hands over, not the source text you picture — and a tripwire left permanently red is training, not protection.** The centralization lint had been red since PR #125 on a legal string that says "the version **you are** running": `PROMPT_MARKER` matched `/You are/i`, the one marker in its set that occurs in ordinary English. Two rules fell out. **First**, fix the MARKER, not the flagged prose, when the prose is innocent — the alternative (a path exemption for `src/legal/`) buys exactly one fix and creates an unlinted region, while the EULA string itself is byte-pinned to a shipped DMG resource and could not be reworded cheaply anyway. **Second, and the near-miss worth the entry:** the obvious anchor `(?:^|\n)\s*You are` clears the false positive and reads correct — but the lint's own `TEMPLATE_LITERAL` extracts literals WITH their surrounding backticks, so `` `You are Snug…` `` carries its marker at index 1, neither at `^` nor after a newline. That version would have traded a false POSITIVE for a false NEGATIVE on the single most natural spelling of a system prompt, and the repo-wide test would have stayed green while the tripwire quietly stopped tripping. Caught only by running positive twins against the real extractor's output BEFORE the plan was written; pinned afterwards by a mutation that reds exactly one row (the repo-wide lint stays green under it, which is why the row has to exist). Anchoring is a claim about where the subject STARTS — when an extractor wraps, trims, or joins its input, that claim is about the wrapper, not the text.

- (2026-08-24) **A committed config file is only a contract if the platform's parser accepts it — run the parser before pinning the bytes.** The web-deploy plan committed a Pages `_redirects` rule (`https://www.… /* → https://… 301`) and byte-pinned it in a test. Wrangler's parser rejects host-bearing sources and SKIPS the line with a warning, so the test would have stayed green forever while `www` never redirected — the 2026-08-20 decorative-test shape, one layer down: the contract wasn't loose, it was void. The fresh-context reviewer found it by reading wrangler's `parseRedirects`, not the docs. Same session, same class: `pnpm exec wrangler --version` prints a bare `4.125.0`, while the interactive banner reads `wrangler 4.110.0` — a regex written from the banner refused the real output on the first smoke run. Pin CLI/config parsers to a CAPTURED sample of the real output (and keep the sample in the test), and for a platform-consumed file, execute the platform's own parser on it once before trusting a byte-pin.
- (2026-08-24) **A deploy target's "production" is whatever the platform says it is — find the one field it keys on and test the mutant that flips it.** Cloudflare Pages decides production purely by `branch === production_branch`; a `--preview` flag that passed `--branch <current>` would have deployed PRODUCTION from `main` while every repo check was green. Likewise turbo restores cached `dist/**` over stale files and never hashes gitignored inputs, so the script's own named fix ("delete `local-artifacts/` and rebuild") could not work without `rm -rf dist` + `--force`. Before shipping a release script, list every input the platform reads that the repo does NOT control (branch name, cached outputs, gitignored env files, zone-level settings) and give each a refusal with a passing twin.
- (2026-08-23) **A disclosure is checked against the code's automatic egress, not its feature list.** The first privacy draft called the update check "the desktop app's only automatic outbound request" — true of the features, false of the code: `sidecar::autostart_if_linked` reconnects a linked WhatsApp helper on every launch, and the Dropbox origin re-pushes the full file on an interval. Before writing any "what leaves your device" sentence, grep the launch path (`lib.rs` setup, `App.tsx`'s boot effect, every `setInterval`) for outbound calls and name each one; a fresh-context reviewer found this, the author did not. Same class for absolute negatives: "no analytics" became "no analytics script" because the zone owner still sees aggregates — write what the code can vouch for, never the rounder claim.
- (2026-08-22) **A drop-in replacement is only pinned for the value shapes you thought to enumerate — derive the cases from the ORIGINAL'S TYPE, not from your mental model of the data.** `createFileAuthState` was tested both directions against the real `useMultiFileAuthState` as oracle, 11 green, and still shipped a data-destroyer: its salvage guard accepted only objects, while `SignalDataTypeMap['lid-mapping']` is `string` — 1,644 bare-scalar files in the live session that the new reader would have quarantined as corrupt on first read, wiping the LID↔phone directory (the very thing whose absence once produced confident wrong phone numbers). The oracle tests could not catch it because *both* implementations were only ever handed objects. When replacing a library component, open its type map / interface and write one round-trip case per declared variant; a compatibility suite that picks its own inputs proves compatibility only on those inputs. Corollary for reviews: this was found by an angle that read the library's `Types/` rather than the diff — point at least one reviewer at what the code must INTEROPERATE with, not just at what changed.
- (2026-08-22) **A repair guard whose expected set contains an entry its remedy cannot create is permanently firing — and other tests quietly come to depend on its side effect.** `healMissingTables` compared `sqlite_master` against ALL of `USERDB_TABLES`, which still names the v5-dropped `snug_auth_specs`; since the replayed DDL deliberately cannot recreate it, every open of a healthy post-v5 file "healed" and spuriously persisted — a defect that shipped invisibly because its symptom is an extra save nobody watches. Found only when the 1.0 spec audit compared the guard's mechanism to the spec's sentence about it. Two rules: derive a guard's expected set from the SAME source as its remedy (here: parse the DDL, don't restate the table map), and after fixing any always-on defect, treat every NEW red in the suite as a test that may have been RIDING the defect — the legacy-adoption compose test had passed for weeks only because the spurious dirty performed its adoption write; its claim was preserved by giving it the write the spec actually requires, not by reverting the fix.

- (2026-08-22) **A selector that appears only in NEGATIVE assertions is not evidence the selector exists — and it breeds.** The gmail dual-mode e2e was written around `run-connect` because an existing spec used it; that existing use was `toHaveCount(0)`, which a never-rendered testid satisfies forever (the real CTA is `net-auth-cta`). The copied test could only time out — a journey "pinned" by a selector nothing renders. Before reusing any identifier harvested from a `toHaveCount(0)` / `not.toContain` / `.not` assertion, grep the SOURCE tree for a renderer; a negative assertion proves absence of the string, including the absence that comes from a typo or a rename, and every copy inherits the vacuity while looking like reuse of proven vocabulary.
- (2026-08-18) **Replacing a label with an icon silently breaks every locator that queried the label.** Two `e2e/starters.spec.ts` specs find the export control by `getByRole('button', { name: 'export .sqlite' })`; had the words become a bare glyph, both would have broken in a lane **CI does not run** — surfacing much later as a mystery. Before deleting user-visible TEXT, grep the whole repo (e2e included) for that literal: a string on screen is an API for tests, screen readers and docs. Keep it as `aria-label` and pin it; `title` is a tooltip and is NOT an accessible name.
- (2026-08-20) **A green suite proves nothing about a path no test walks.** Renaming `USERDB_FILE` left `packages/db` at 339/339 green, because every production site routed through the constant — while the legacy-fallback path, the thing that decides whether an upgrading user keeps their data, had no test at all. The suite was measuring the rename's *consistency*, not its *safety*. When a change's risk lives in a path that does not exist yet, the green you already have is the least informative signal in the room.
- (2026-08-20) **A new surface that gates the app is a product decision, not a placement detail — and only the assembled product will tell you.** The protection offer shipped as a full-screen gate in front of the hub. 24 of 73 e2e specs then timed out waiting for a starter tile, because a brand-new profile met "protect this file?" and never reached the shelf. The failing tests were the symptom; the defect was asking someone to protect a file before they had seen a single app — valuing something they had not been shown. Prominence that blocks is a modal with extra steps. Run the leg that exercises the ASSEMBLED product before merging anything that adds a screen, not after.
- (2026-08-20) **Run the product before claiming a UI feature works.** The passphrase feature shipped with `ProtectSetupFlow` never rendered and `initProtectOffer` never called: 1341 tests green, the owner launched the app, and nothing ever asked for a passphrase. Then the SAME class bit again one layer down — a wrong passphrase showed no error, because `unlockUserDb` published a transient `'opening'` status and `App.tsx` renders the unlock screen for `'locked'` only, so the screen UNMOUNTED mid-attempt and the failure state died with it. Component tests could see neither: one mounts the component directly, the other mocks the store. For anything a person looks at, one verification must be *the running app* — a browser session or a screenshot — not a suite.
- (2026-08-20) **A test that builds its own wiring cannot detect missing wiring.** `encrypted-sync.test.ts` proved the sync loop seals personal-origin payloads — by passing the sealer in itself. The shipping composition root never passed one, so a protected file synced to the user's own Dropbox as a readable database while every suite stayed green. The test proved a *capability*, and nobody had checked that anything *used* it. For any feature whose value depends on being wired at a composition root, one test must assert against the call the shipping code actually makes.
- (2026-08-20) **Read the exit code, not the summary line.** A root run printed "1348 passed" and exited 1: a new render test's branch booted a real sql.js database, whose wasm is fetched over a `/@fs/` URL that only resolves under a dev server, so it aborted with an ENOENT unrelated to any assertion — vitest failed the RUN without failing a TEST. A green count is not a green suite, and the habit of reading totals is the same habit that lets an unreachable feature ship.
- (2026-08-20) **Count the writes, do not trust the status.** A protected file appeared to save correctly: the API resolved, the status stayed `ready`, the UI looked healthy — and nothing reached disk, because the seal threw inside `persist`'s catch-all, which sets `dirty = true` and retries forever. Fault-tolerant write paths convert defects into silence by design. Asserting a `backend.save` CALL COUNT is what made it visible; asserting the return value never would have.

- (2026-08-18) **When a refactor invalidates a test, migrate the CLAIM — never delete the test.** Moving a control into its own component broke an ordering assertion written as source-string indices inside the old file. The claim was still true, so it was re-asserted across both files and re-expressed as rendered document order (`compareDocumentPosition`), which survives the next refactor because it measures nodes rather than string positions. A test deleted during a refactor is coverage lost with nobody noticing; classify every one as MIGRATED / OBSOLETE / LOST (the 2026-08-10 rule, applied to a component extraction rather than a rebuild).

- (2026-08-20) **A test that compares two spellings of one contract must fail when the contract drifts — check that it does, by breaking it on purpose.** `gate-local`'s AC3 asserts every `ci.yml` step has a local counterpart. Written with substring matching it passed, and a mutation test then showed it was decorative: replacing a local command's operative verb (`gate:release` → `nonexistent`) still "matched" the CI step, because the CI step contained the mutant's prefix. Token-set equality kills the mutant. The general shape — a comparison loose enough to pass is loose enough to pass anything — is why the four mutants (unmapped CI step, dropped local command, empty extractor, always-ok status) are now part of the task's evidence rather than an afterthought.
- (2026-08-20) **A gate whose coverage is user-selectable must report what it did NOT check, or it lies by omission.** Making `gate:local`'s legs opt-in was right for a solo dev's time/assurance trade, but it silently changed what a green means: a 2-minute default run verifies two of six legs. An unqualified "PASS" would be the same false confidence the gate exists to prevent, in a new costume. Hence three states rather than two (PASS / FAIL / **DESELECTED**), a verdict that enumerates the unverified legs, an explicit denial of ci.yml equivalence unless `--all` ran, and that line carried verbatim into the PR body — otherwise `git log` becomes a uniform wall of merges whose real verification varied invisibly.
- (2026-08-20) **Quarantine with `test.fail()`, never `test.skip()`.** Adopting a suite with known reds needs a quarantine, but a skip HIDES the row and rots into permanent suppression. `test.fail()` keeps it running and reporting, and inverts the expectation — so a quarantined row that starts passing FAILS the suite and forces a deliberate lift. Verified by adding a genuinely-passing row to the set and watching it break. Quarantine that cannot expire is deletion with extra steps.
- (2026-08-20) **"Element not found" often names the wrong element.** A Playwright spec failed on `expect(wizard).toBeVisible()` — pointing at the wizard, which was innocent. The real cause was one line earlier: the run surface mounts its connect CTA ~500 ms after the URL settles, so an immediate `.first().click()` resolved against an empty set and nothing ever opened the wizard. It passed alone and failed after its five siblings, which is the signature — a warm page wins the race, a loaded one loses. When an assertion fails on a MISSING element, suspect the step that was supposed to produce it before suspecting the assertion.
- (2026-08-20) **A red gate with no enforcement behind it is worse than no gate.** GitHub Actions was billing-blocked for two weeks and rendered as an ordinary red X — indistinguishable from a real break without opening the check annotation. It also turned out never to have BLOCKED anything (private repo on a free plan: branch protection is 403). So its entire contribution was to train the sole reader to merge past reds, which is precisely what happened, routinely. Check what a failing signal actually enforces before treating it as a safety net — and if it enforces nothing, silence it rather than living beside it.

- (2026-08-19, **amended 2026-08-20**) **Before believing a red, remove the cheapest confound: run it serially.** A playground suite failing a DIFFERENT set each run (14/15/31 observed, all `Test timed out in 5000ms`, all in React-rendering files) was fully green — 1254/1254 — under `--no-file-parallelism`, on clean `main` as well as the feature branch. That one flag converted a fifteen-month-old "flake, name never captured" note into a classified cause (worker contention against a 5 s per-test budget) with a concrete fix. A varying failure SET is the signature: a real break fails the same test every time. Costs one command; the alternative is a genuine red waved through as "just the flake". **The amendment, and it cuts the other way:** on 2026-08-20 the same suite ran green 8/8 in full parallel (5 idle + 3 under deliberate CPU contention, 1303/1303) and the classified cause could not be reproduced at all. The rule that survives is the FIRST half — remove the confound before believing a red — not the diagnosis. A classification built from failures you can no longer produce is a hypothesis, not a finding, and the honest response was to leave `testTimeout`/`maxThreads` untouched: patching an unreproducible symptom yields an edit nobody can verify and permanently blunts the signal that separates contention from a real break. **Capture the failing run before theorising about it.**

- (2026-08-20) **A hardcoded permissive collaborator makes "never consulted" indistinguishable from "consulted and granted".** Every sidecar test passed `confirmGate: { confirm: () => true }`, so a gate the code never called looked exactly like a gate that approved — the suite stayed green through a live confirm-bypass. Make a gate a SPY and assert both that it fired and what it received (the `slot`/`body` a downstream policy decides on), so a call handed nothing to decide with also fails. Same shape as the positive-twin rule: a stub that always says yes vouches for nothing.
- (2026-08-20) **Assert on the FIELD that would carry the leak, not only the one that carries the verdict.** All fifteen `NET_AUTH_FAILED` assertions in `packages/auth` used `toMatchObject({ ok: false, code })` — excellent coverage of the code, and none of them ever read `message`, which is the field that was forwarding a live credential to the iframe and the LLM. When a result object has a machine half and a prose half, the prose half is where secrets ride; a suite that only ever checks the machine half is blind exactly where it matters.
- (2026-08-04) A test never seen to fail tests nothing: mutation-check every guard by reverting the fix and watching red. Be suspicious of first-run passes, assertions behind optional calls (`backend.list?.()`), and subjects only reachable in modes the test never enters.
- (2026-08-20) **Verify a RED by restoring the old state from `HEAD`, not with `git stash` — a stash that silently does not take reports the new tree as green and looks like proof.** Confirming that `bundleTargets.test.ts` failed before the config change, `git stash -q --include-untracked -- <path> 2>/dev/null || git stash push -- <path>` matched nothing usable, the `2>/dev/null` swallowed the reason, and the suite ran against the ALREADY-FIXED config: "11 passed", i.e. exactly the reassuring output a real RED check is supposed to rule out. `git show HEAD:<path> > <path>` for each file, run, then restore — it either produces the old bytes or fails loudly, and it is trivially auditable afterward (`git status` shows the same modified set). Same family as the 2026-08-19 rule above: that one asks whether the test COULD fail on the old commit, this one is about not fooling yourself while answering it. Any verification step whose failure mode is "looks like it worked" needs an affirmative signal, never a silent fallback.
- (2026-08-21) **Mutation-check only state whose correct version is COMMITTED — or restore the mutation by inverse edit, never by `git checkout`.** Verifying the resetToFactory MIN→MAX guard, the mutated file was restored with `git checkout -- <file>` while that same file carried the session's uncommitted implementation; the checkout silently wiped it (recovered only because the edits were still in context). The sibling 2026-08-20 rule ("restore a RED from `HEAD`, not stash") assumes HEAD holds the state you want back — mid-implementation it holds the state you just spent an hour leaving. Commit first, or undo the mutation with the same targeted edit that made it.
- (2026-08-21) **An invariant comment is a claim about a distribution, and the FIRST release outside that distribution turns it into a bug — so re-read the comments a new release SHAPE walks past.** `starterUpdate.ts` documented that deriving an installed version from byte-equality "can only over-offer (a no-op update), never hide one". True, and load-bearing, for every release that had ever existed — all of them changed `app.html`. A **docs-only** release (version bumped, html untouched) is the first that does not, and under it the sentence inverts: identical bytes are now indistinguishable from current, so the offer is HIDDEN from exactly the pre-seeding copies the release exists to reach. The sibling half was the same shape one layer down — `applyStarterUpdate`'s already-current fast path returns before the docs seed, so even a copy that DID see the offer received nothing. Both were found by a fresh-context plan reviewer reading the module against the plan, and neither would have been found by the planned test, which was written to the plan's belief rather than the code's. Before shipping a new release/act/message KIND, grep the modules that consume it for their stated invariants and ask which one this kind is the first to violate; a comment that says "can only" is naming its author's sample, not a theorem.
- (2026-08-21) **When an act chains several writes, a test must wait on the act's COMPLETION SIGNAL, never on its first observable write.** The starter-update component test polled "did the html change?" — the FIRST of four writes — so the assertion ran mid-act and read the settings key before the act wrote it, failing two tests against correct code. The act's callback (`onUpdated`) was the honest condition. Same family as "element not found names the wrong element": the failing assertion pointed at the key write, which was innocent.
- (2026-08-20) **Scope a "this string must not appear" assertion to the construct it governs, or it forbids DOCUMENTING the thing it forbids.** A belt asserting the icon generator no longer emits `icon.ico` matched the whole file, so it failed on the header comment written in the same commit — a comment whose entire job is to tell a post-1.0 reader which line to restore. Narrowed to the `SHIP` array, both survive. The generalization: a source-text assertion is a crude instrument aimed at a precise claim, so bound it to the block that carries the behaviour (a list, a handler registration, a config key), never the file — otherwise the test's own rationale, the ADR citation, and the migration note all become violations, and the next person deletes the comment rather than the capability.

- (2026-08-19) **A test that would pass if your change were never made is not coverage — check that property explicitly.** The plan's regression test for "the Spotify pin gains an eighth scope" reused the existing scope-drift fixture, which stages whenever the registry pins ANYTHING; it would have passed verbatim against the unfixed registry. The fix was a fixture frozen at the exact OLD seven-scope consent, which fails with `'none' != 'staged'` until the scope lands — plus a reorder guard, so it cannot pass for the wrong reason either (ADR-0028's comparison is set-based, so a pure reorder must stage nothing). For every regression test ask: what would this do on the commit BEFORE the fix? If the answer is "pass", it pins someone else's behaviour, not yours.

- (2026-08-04) Assert the requirement's OUTCOME in one sentence, never a correlating proxy — if the broken and fixed artifacts both pass, the test measured nothing. Earned twice: hub "reachability" passed with the forked-app bug restored; icon "centred" passed on a 61% logo when the ask was full-bleed.
- (2026-08-08) Mutate the rule AND its call site: deleting the Settings revoke button's call left every test green because the rule was only ever invoked directly. "Logic is correct" and "logic runs" are separate claims.
- (2026-08-17) When a PERMANENT failure and a NORMAL wait render identically, the ambiguity IS the defect — not the failure. A half-linked WhatsApp session showed "history is still syncing" forever; the wedge was already detectable on disk and already auto-cleared on re-pair, so all that was missing was SAYING so. Whenever a screen says "still working", ask what state would make that sentence a lie the user cannot see through, then detect that state and name it in the copy.
- (2026-08-17) Assert the COUNT/state the feature promises, not the shape around it: an emoji-frequency regex that let pictographs repeat inside one token made '😂😂' a single unheard-of emoji, and only a test asserting `{emoji:'😂', count:3}` could see it. Shape assertions pass while the number is wrong.
- (2026-08-13) A refusal's test input must pass every SIBLING refusal and fail only the one under test — `runLanPairing`'s approved-status check survived deletion because hostless fixtures never reached it. When a mutation stays green, suspect the fixture before the mutation.
- (2026-08-08) When a test seam short-circuits production wiring, at least one test runs with the seam OFF — every suite injected `__setDeclarationManifestsForTests`, so a misspelled `import.meta.glob` kept 477 tests green with the feature inert for real users. Mutation-check the wiring, not just the logic.
- (2026-08-13) A fence that restates its data cannot test it: drive the value through the code that CONSUMES it, with fixtures hostile to the mechanism — `hue.pairing.secretPath` was compared to a retyped copy of itself (green against a path no real bridge answers); URL-safe hex keys made four C1 scrub tests decorative.
- (2026-08-11) Test matrices must repeat an operation KIND (write/write exposes what write/read hides — `sqlite3_changes()` deltas); a guard comparing two values from the SAME function verifies agreement, not correctness; neutralize the delimiter PRIMITIVE, not one spelling — the attacker picks the spelling.
- (2026-08-13) Verify a timing fix by measuring failure RATE before/after, and check the ENCLOSING budget — a 10s `vi.waitFor` inside the 5s default test timeout is dead code. Intermittent + every-added-log-makes-it-pass = scheduler/ordering bug, not slowness.
- (2026-08-13) A mutation that stays green is evidence, not a dead end — ask what its survival proves (a microtask drain can't advance real timers → the chain awaits real async). Once an environmental failure reproduces deterministically, re-run the whole file under that condition.
- (2026-08-10) When a rebuild deletes a surface, classify every deleted test: MIGRATED (cite the new assertion), OBSOLETE (prove the code is gone), or LOST — the v2 wizard rebuild orphaned 14 shipped behaviors including `isConnectionRepairableNetError`'s allowlist. A net test-count drop is a prompt to audit, never an explanation.
- (2026-08-04) Test doubles wrapping one-shot resources (streams, iterators, FormData) must be factories — one mocked SSE `Response` served to two turns yields a silent empty second turn.
- (2026-08-17) **A feature is not done when its parts pass — it is done when someone walks it.** Eight seam defects shipped past a fully green tree (23/23 tasks, cargo, the macOS gate) in ONE feature, each hidden behind the last; all eight were found by clicking the real flow. Deep write-up: `docs/solutions/2026-08-17-eight-seam-defects-in-one-feature.md`.
- (2026-08-17) **Every injected dependency is an untested wire.** If every test supplies `sidecarFetch`/`SidecarState`/a store, nothing has tested that PRODUCTION supplies it — `SidecarState` was never `.manage()`d and the commands failed at the IPC boundary while their unit tests, both handler registrations, and the C2 gate all stayed green (an unregistered command is unreachable from everywhere, so the refusal check passed for the wrong reason).
- (2026-08-17) Assert STATE and STRUCTURE, not return values and copy: a test asserting `completeDeviceLink`'s returned token passed while nothing stored it, and its replacement asserting the absence of the string "Helper access token" passed while that exact box was on screen (the phrase was the field LABEL; the heading differs). Assert the step the machine is in and the elements rendered — neither can be satisfied by the wrong screen.
- (2026-08-05) Test at the altitude where the DECISION is made, not where the effect lands — AC12 asserted `cache_control` at the adapter while callers cached the wrong turns in both directions (ADR-0012). Per-request switches belong on the call; the test belongs on the caller.

## Trusting a green run

- (2026-09-03) **A suite can fail with every test green — an unhandled error after teardown fails the RUN, and the only honest fix may ship without a regression test.** CI went red on `Tests 1744 passed` + `Errors 1 error`: an async handler's `setInstalling(false)` landed after vitest tore jsdom down, so React read `window` and threw. Two rules came out of it. **First, separate "my change broke it" from "it is flaky" with evidence, not instinct** — the decisive datum was not the local re-runs (2 clean on the branch, 3 clean on `main`, both inconclusive because the bug needs the slow runner) but the CI history: the SAME branch with the SAME test files had passed twice and failed once on a docs+CSS commit. Same code, different outcome ⇒ environment, not diff. **Second, a regression test that passes with the fix REMOVED is worse than none** — four framings were tried (unmount mid-flight; delete `globalThis.window`; gate the last await via `vi.mock` so the chain is genuinely parked; the same with the view left mounted) and every one passed against the mutant, because the released continuation is still queued when the test ends (a probe inside `finally` never printed). The guard shipped with the gap NAMED in the journal instead of a green test that asserts nothing. Mutation-check every regression test you write for a race — the mutant run IS the evidence the test is real.
- (2026-08-25) **A tool's success message is not evidence its output exists — check for the artifact.** `qlmanage -t` printed "produced one thumbnail" and "Done producing thumbnails", exited **non-zero**, and wrote **nothing**: it is a thumbnailer whose reassuring stdout is decoupled from both its exit code and its filesystem effect. Wrapping it in a `try/catch` on the exit code would have been wrong in both directions. The general form of the family this file keeps re-learning: **after any subprocess that is supposed to produce a file, stat the file and read its bytes** — and prefer a tool whose job is the output you need (a renderer) over one that produces something similar as a side effect (a previewer). Corollary that paid off here: the generator re-reads each PNG's IHDR header after writing, so a converter that silently produces the wrong geometry fails the run instead of shipping a bad asset.
- (2026-08-24) **A `0` out of `grep -c` is evidence only if the command feeding it RAN — a broken invocation prints the same confident zero as a clean check.** Verifying the first production deploy, `R="--resolve a --resolve b"` in a plain shell variable made curl reject the whole string as one unknown option; the failures piped into `grep -c cdn-cgi` and every ADR-0013 posture check printed **`0`** — the pass value. This is the decorative-test shape (2026-08-20) reproduced inside a VERIFICATION command, where it is worse: the deploy checklist is the last gate before the public sees the bytes. Use an array for multi-flag curl (`R=(--resolve …)`; `curl "${R[@]}"`), and **before trusting a batch of piped checks, run one of them bare and look at its output** — a checker whose input never arrived cannot fail.
- (2026-08-24) **Ask the platform for the SETTING, not the symptom — an absent symptom can mean the surface was never exercised.** The `cdn-cgi` grep in the deploy runbook returned 0 on both origins and "proved" ADR-0013's no-injection claim, while zone-level **Email Address Obfuscation was `on`** the whole time: the apex was not yet serving the site, so nothing had a chance to be rewritten. The API read (`/zones/{z}/settings/{s}` → `off` ×5, `/bot_management` → `fight_mode: false`) is the falsifiable check the ADR actually promises; the response grep is a corroborator. **When a doctrine says "falsifiable by reading the config", read the config** — a clean response body from a surface under construction proves nothing.
- (2026-08-24) **A cloud resource's `status` field lags what its edge is already doing — verify by fetching, not by polling status.** Both Cloudflare Pages custom domains served **200** for minutes while the API still reported `status: pending` with `verification_data: "CNAME record not set"`, and a transient **522** cleared on its own. Related, same session: the runbook's claim that Cloudflare auto-creates custom-domain CNAMEs when the zone is on the same account is **false** — the domains stall at `pending` forever until the records are added by hand. **For any managed resource, make the acceptance test the behaviour you actually want (an HTTP 200 from the real host), and treat provider status fields as hints.**

- (2026-08-24) **Deleting something OUTSIDE the repo invalidates caches INSIDE it — turbo cannot know, so force the rebuild before believing the green.** After removing a stray `~/node_modules` that had been shadowing workspace resolution, root `pnpm test` exited 0 with 25/25 and the run was meaningless: `test` `dependsOn: ["build"]`, and `desktop#build` was replayed from a cache entry produced while the stray tree still existed. `turbo run test --force` failed instantly on `Cannot find module 'zod'`. Turbo hashes the inputs it can see, all of them inside the repo, so a change to module RESOLUTION is invisible to it BY CONSTRUCTION — this is not a stale-cache bug to be fixed, it is the boundary of what the cache can express. The 2026-08-10 rule ("the turbo cache replays stale greens") one level up: there a stale OUTPUT was served as fresh, here a stale PASS was. Any change to the environment a build resolves against — a deleted hoisted tree, a package-manager switch, a Node major, a moved global store — makes every cached build in the repo a lie until re-run with `--force`.
- (2026-08-24) **An ambient dependency is invisible until you remove what was satisfying it, and the gate that should catch it may be cached past.** `apps/playground` imported `zod` and declared it nowhere, resolving up into a directory belonging to no project; it would have broken on the next clean clone or any CI runner without a home-level tree, and it broke here only because a cleanup deleted the crutch. When a change's whole PURPOSE is to remove an ambient fallback, "the suite still passes" is not the verification — "the suite still passes with every cache cold" is, because the ambient thing was by definition never among the repo's hashed inputs. Corollary for cleanups: the breakage a removal causes is evidence the removal was right, and belongs in the same branch rather than a follow-up.

- (2026-08-24) **`Shell cwd was reset` is a harness landmine for background gates: a run that can't find the script exits 1 with ZERO checks executed — an environment verdict wearing a red.** Gate run 3 of the web-deploy close "failed" with `Cannot find module …/scripts/gate-local.mjs` because the tool shell's cwd had silently reverted to the parent directory between calls; read as a red it would have blocked a correct branch (the 2026-08-19 rule: did the checks RUN?). Invoke background gates by absolute path. Two other gate facts from the same session, both queued in next-steps: the db crypto suites time out at 5000 ms under full-workspace parallel load (2-in-2 loaded runs red on a DIFFERENT set each time, 0-in-3 isolated, 0-in-1 quiet — a rate, per the 2026-08-22 rule, not a verdict on the branch); and `gate:local`'s workspace leg mirrors ci.yml, which means it runs only three of the seven root `check-*` seats — root `pnpm test` is the evidence for a `scripts/` change until the leg is widened.
- (2026-08-23) **A dev script consumed on fresh clones is only proven on a fresh clone — months of green on maintainer machines proved nothing, because stale `dist/` output was silently satisfying a dependency the script never built.** Root `pnpm dev` built only the bare `server` package; its tsc needs every workspace dep's `.d.ts` and the playground's vite resolves deps' `dist/index.js`, so the quickstart's one command died with 21 module-not-found errors on the very first cold clone ever attempted (AC3, written 2026-08-05, executed 2026-08-23 — the run cost ~3 minutes and caught what would have been every HN visitor's first experience). Two rules: any entrypoint advertised to newcomers gets one scripted cold-clone run before the claim ships, and a workspace-package filter in a build step should name the dependency CLOSURE (`server...`, `playground^...`), not the package — the bare name is exactly the spelling that works on dirty trees and only dirty trees.
- (2026-08-23) **Under squash merges, git's own merged-branch answers are wrong in BOTH directions — judge a branch against the merged-PR ledger, not ancestry.** `git branch --no-merged main` listed 36 branches as unmerged when all but four were squash-merged leftovers (their commits are never ancestors of main), and `git merge-tree` false-positived the other way on post-merge doc-cleanup (an old branch "re-adds" the task file main later deleted). The test that held: match each branch name against `gh pr list --state merged` head names, then hand-triage only the leftovers — which is exactly where the two deliberately-parked branches (instagram, AL-09) surfaced, protected from deletion by their `next-steps`/memory entries rather than by anything git could see. Corollary: record tip SHAs in the task file BEFORE deleting; recovery intent must not depend on reflog luck.

- (2026-08-22) **Diagnose a flake from its failure TEXT, and measure a flake fix as a RATE — an isolated green cannot tell "fixed" from "got lucky".** The playground flake carried a two-year-old classification ("file parallelism; raise `testTimeout`, cap `maxThreads`") that had never been tested against the actual failure output. Applying it moved the rate not at all (2-in-6 → 2-in-8), which is the only reason it was caught as wrong; capturing the failure text instead named the real cause in one run — two tests synchronizing on a fixed wall-clock sleep rather than on the condition they assert, so load merely set the odds. Three rules fell out. **Never keep a config change that did not move the measured rate**: it reads as a fix that holds and stops the next person from looking. **A wait condition must cover every assertion that follows it** — the first fix waited for three backoff sleeps in a test that asserts four, and took the failure rate to 9-in-10, worse than the bug. **State flake claims as rates over ≥6 runs, before and after**; the same 1-in-3 flake produced three consecutive passes on one branch and a failure on another, which nearly convinced me a branch touching zero files in that package was at fault.

- (2026-08-22) **A pipeline's exit code is its LAST command's — `pnpm test | tail` reports `tail`'s 0 whatever the suite did.** The 1.0 close ran the root gate twice through `| tail -N` in a background shell and both "completed (exit code 0)" notifications were vacuous: the harness reports the PIPELINE's code, and `tail` always exits 0. Caught only because the "read the exit code, not the summary" habit asked *whose* exit code this was. When capturing a gate through any pipe, `set -o pipefail` first and print `$?` yourself — or drop the pipe and read the file. The 2026-08-20 rule one level up: a green you didn't trace to the failing-capable process is not a green.

- (2026-08-19) **A harness failing before it writes results is an ENVIRONMENT verdict, not a red suite.** `pnpm --filter desktop gate` exited 0 with "FATAL: shell process exited before writing results" because a `snug-desktop` left over from an interrupted run still held the single-instance lock — the new shell was killed on launch, so ZERO checks ran. Read as "the gate is red" it would have blocked a correct branch; the same shape as the billing-blocked CI above (no steps executed, rendered as failure). The distinguishing question is always *did the checks RUN?* — a harness that produced no verdicts proves nothing in either direction. This one names its own fix in the failure text (`ps aux | grep "[s]nug-desktop"`, kill the stale PID, re-run); keep that property when writing any harness that can be defeated by leftover state.
- (2026-08-13) A lane's green is a sample of a different distribution; the integrating claim is the forced ROOT run (`turbo run test --force`, showing `Cached: 0 cached`) — repeated, because the catches came on the fourth and tenth runs.
- (2026-08-10) The turbo cache replays stale greens, and dependents resolve workspace packages via `dist/` — after any mutation, re-run with `--force`; mutate `src/` and rebuild (or `dist/` deliberately, then restore) or you are proving nothing.
- (2026-08-11) Run turbo from the REPO ROOT — inside a package dir it silently scopes to that package's graph (a 19-task run became 4). Every package's `test` script is tsc-gated now; keep that uniform, and when enabling a type gate read the whole backlog — 2 of 40 hidden errors were assertions voided behind `as` casts.
- (2026-08-06) A suite is proven only when shown to RUN: watch for "no tests"/"failed to load", and verify loadability in isolation on a cold `.vite` cache — warm sibling resolvers let a phantom `zod` import pass every batch run. Every runtime import needs a dep in that package's own package.json; fix by removing the import, not adding the dep. **(amended 2026-08-24)** "Remove the import" was the remedy for a PHANTOM import — one nothing used. When the import is real, the same rule's other half is the fix: `apps/playground` imports `zod` for `chatCardSchema`, the strict re-validation that makes a crafted card row render NO card (ADR-0031 §3), so it was declared (`zod: ^4`, matching protocol/server) rather than deleted. Check which kind you have before applying the remedy — and when an undeclared import turns out to be real, verify the version you PIN matches the one that was ambiently resolving (this one silently moved 3.25.76 → 4.4.3 under a security boundary; the two APIs used exist in both, and the 21 card tests were re-run to prove it).
- (2026-08-10) An empty grep on a file you expect hits in needs a second tool (`grep -a`, ripgrep, Python) — one NUL byte made grep silently print nothing and "confirm" a deletion. No output is a possible tool failure, never evidence of absence.

## Real browsers & rendered surfaces

- (2026-09-04) **A component that PORTALS to `<body>` is not inside the container you mounted it in — query the document, or every assertion times out looking at an empty div.** The share sheet rides `ConfirmOverlay` (portaled for the header's `backdrop-filter`, lesson 2026-08-26); its first test queried `container.querySelector` and waited 5 s for a sheet that was fully rendered two nodes over. Same rule for anything opened from the run header. Pair: run vitest from the PACKAGE directory — `npx vitest run --root apps/playground` from the repo root reports `Denied ID …sql-wasm.wasm?url` for every test that touches the user DB, which reads as a broken import chain and is only a cwd.

- (2026-09-03) **"It shrinks" names a symptom, not an axis — measure the box in a real browser before choosing what to fix.** The composer "shrank on the first keystroke". The plausible story (autogrow writing a too-small `scrollHeight` back) got a floor, a unit test modelling the numbers, and a green suite — and the owner reported it still broken. A Playwright probe showed the height never moved; the WIDTH did: the build column had become a grid item, and a grid item with auto margins is fit-content sized, so it followed its widest child and collapsed when the suggestion chips hid. One `width: 100%` fixed it. Two rules: a layout report earns a geometry measurement (`boundingBox()` before/after) before any code, and a jsdom test that models the numbers you ASSUMED can only confirm the assumption — the static-stylesheet probe in both engines was the evidence. (TASK-20260903, AC11.)
- (2026-09-03) **Work the user is allowed to walk away from must not be owned by the component that started it — and an unmount cleanup that cancels work turns every route change into a cancel.** `useBuilderChat` kept the whole turn in component state and aborted it on unmount under a rule that read as hygiene ("never leave a request running headless"); React Router unmounts the view on every navigation, so a 30-minute build died on a click of the nav, and StrictMode's simulated unmount made the hub→build handoff a dev-only heisenbug that sat in next-steps for a month. The fix is structural, not a flag: own long-running work in a module store keyed by its subject (here the thread), let views subscribe and unsubscribe freely, and make the only cancel the user's explicit one plus the store's swap seams (lesson 2026-08-20). Two tells that a cleanup is really a cancel: its test asserts `signal.aborted === true` after `unmount()`, and the product has a nav bar. (TASK-20260903-build-thread-continuity, ADR-0062.)

- (2026-08-25) **A framework's `<head>` is not in your source, and reading the source to decide what it emits will plan the wrong change.** The task plan asserted the Starlight docs shell emitted "no OG tags at all" — defensible from the source, where `MarketingLayout.astro` held the repo's ONLY `og:`-emitting line. The built pages said otherwise: Starlight generates `og:title`, `og:type`, `og:url`, `og:locale`, `og:description`, `og:site_name` **and** `twitter:card=summary_large_image` from a data array in `utils/head.ts`, and omits exactly one tag — `og:image`. The real defect was therefore sharper than the plan's (22 pages advertising a large-image card pointing at nothing), and the planned fix — a Head override emitting the full set — **would have shipped duplicate meta on all 22**. One `grep` over `dist/` before writing the component cost nothing and changed the design. The sibling trap in the same file: the two shells emit *different markup for the same tag* (`<meta ...>` from Astro pages, `<meta .../>` from Starlight), so a matcher written against one shell half-passes silently on the other. **Before overriding any framework's head/meta/layout slot, enumerate what it ALREADY emits from the built output, then add only the difference** — and when a fix spans two shells, check the markup shape of both. (This entry is the 2026-08-23 source-vs-dist rule landing on a plan written *after* reading that rule; the general form was known, the instance still got missed.)
- (2026-08-25) **SVG text neither wraps nor shrinks to fit — an overlong line renders off-canvas silently, and every automated check still passes.** A generated banner's headline ran "…connects agents to apps." past the right edge; the geometry assertion (PNG IHDR bytes), the file-size check and the byte-level verification all passed, because the canvas WAS the requested size and the overflow is just ink outside it. The only detector was looking at the image. Two rules: **set generated-image text as explicit, measured lines rather than one line trusted to be short enough**, and **view every generated image at the size it will actually be displayed** (this one is authored at 1280px and rendered at 800px in a README). A dimension check proves the frame, never the composition.
- (2026-08-24) **A grep that does not model the REAL markup is not a search, and reporting its miss as "it's already correct" is worse than not looking.** The owner reported the landing hero reading "in**one** portable file"; I grepped the source, found `in one` two words, grepped the live page for `in <strong>`, found nothing, and told them the text was fine. Both greps were wrong for the same reason: the source has `in` and `<strong>` on ADJACENT LINES (a newline Astro then eats), and the served html carries `in<strong class="astro-lcdefpme">` — the class attribute Astro injects defeated the pattern. The meta-description matched cleanly and made the false negative look corroborated. **Search the SERVED bytes for the defect SHAPE (`[A-Za-z]<strong`), not the prose you expect to find**, and when a user reports something visible on a page they are looking at, their screenshot outranks your grep — ask where, don't conclude "already correct". Scanning by shape then found THREE instances where one was reported.
- (2026-08-24, third recurrence 2026-08-26 — now GUARDED BY A TEST) **Astro 7 deletes the whitespace between a text run and an adjacent inline element — a source line ending in a word followed by `<strong>`/`<a>`/`<code>`/`<em>` on the next line ships as one joined word.** The 2026-08-24 output-diffing rule pinned this for `</a><a>` adjacency and it still shipped at a `<strong>` boundary on the live landing page; the rule was then rewritten as the general class — and on 2026-08-26 a NEW page shipped **three** more (`hasno network`, `bytheir assistant`, `passphraseand the recovery key`) in its first build, written by an author who had read this entry. **Three strikes is the finding: a prose rule cannot hold this line, because the source reads correctly, no ordinary test asserts inter-element spacing, and the only human detector is someone reading the rendered page closely enough to notice a missing space.** It is now a test — `architecturePage.test.ts` → *rendered prose — no lost spaces at inline-tag boundaries* — scanning the BUILT html of every marketing page for `\w(</?(b|i|em|strong|code|small|abbr)[^>]*>)+\w`. Two scoping notes that cost a false-positive pass each: exclude `<a>` and `<span>` (adjacent nav/footer links are separate flex items and correctly carry no whitespace), and exclude `<script|style|svg>` bodies. Fixes are `{' '}` or the line-break-inside-the-tag form (`<code\n>text</code>`). **Corollary, the reusable half:** when the same defect class returns a third time, stop restating the rule and spend the same effort on a detector — and note that this bug is invisible to a screenshot review at a glance, which is why it survived one.

- (2026-08-26) **`display:none` at a breakpoint with nothing in its place is an AMPUTATION, and no test in the repo could see it.** The marketing header hid every non-CTA link below 560px — Docs, Spec and Playground were simply unreachable on a phone for the whole public life of the site, found by the owner opening it on a phone, not by the suite. The class is broader than one nav: a responsive rule that REMOVES a destination is only safe if something else provides it at that width, and that is a structural claim a test can make cheaply — assert the set of hrefs reachable in the mobile disclosure EQUALS the set in the desktop row (`marketingNav.test.ts`), so hiding a link without rehoming it goes red. Write it as the negative first: it must fail against the pre-fix layout, or it is asserting the fix rather than the requirement. Two companions from the same fix: state the breakpoint ONCE as a custom property and give the two rules complementary bounds (`min-width:N` / `max-width:N-0.02`) so no width shows both navs or neither — a bare `max-width:N`+`min-width:N` pair both match at exactly N; and prefer a native `<details>` disclosure over a JS panel when every item is a real navigation, since it brings keyboard and AT semantics with zero script and cannot be left stale-open.
- (2026-08-23) **The band BETWEEN breakpoints is a device class, and nobody's suite lives there.** The run view's either/or swap was e2e-proven at 375px and the desktop split at 1280px — while a phone in LANDSCAPE (~850px) and an iPad in portrait (768–834px) sat between the 760px mobile block and the desktop layout, getting a 340px rail beside a squeezed app on glass. Found only by the owner's hand (the walk the 2026-08-21 notes predicted). When behavior keys on a width breakpoint, put one test IN each band including between existing breakpoints — and when the breakpoint lives in two files that cannot import each other (matchMedia + CSS), byte-pin the literal pair (`mobileThinkBreakpoint.test.ts`; the releaseChannel/tauri.conf precedent).
- (2026-08-23) **An equal-specificity media-query rule placed EARLIER in the file loses to a later base rule — and the failure is invisible until geometry is measured.** A ≤760px `display:none` for the header feedback trigger sat mid-file; the component's base `display:inline-block` sat in an appended block 700 lines later and won the cascade. Every unit test passed; the mobile e2e's overflow assertion (50px of horizontal scroll) was the only detector. Co-locate a component's responsive rules with its base rules (or out-specify deliberately, with a comment naming the cascade fight) — and treat "no horizontal scroll at 375px" as a standing tripwire, since it catches whole families of these.
- (2026-08-23) **A claim about RENDERED output cannot be proven by grepping source — sweep the build.** "Every external link opens in a new tab" looked true in `src/`: all four playground anchors carried `target="_blank"`. The built site had ~50 same-tab external anchors from layers no source grep sees — Starlight's stock SocialIcons component and remark's Markdown autolinks. The dist-side sweep (regex over `dist/**/*.html`) found them in one pass; the durable guard is then two-layered: a source-scan test for hand-written anchors PLUS pins on the framework wirings (the rehype plugin config, the component override) whose deletion would silently revert the framework-rendered half.

- (2026-08-22) **Chrome's print pipeline applies WHOLE-DOCUMENT shrink-to-fit when any single element overflows the printable width — every font scales (×0.91 observed), the page count drops, and nothing errors or warns.** Adding a fourth cell to the whitepaper's cover-meta grid silently rescaled all 33 pages into 29; text, figures and checker all stayed complete and green, so the only tell was the page count. The trap and its fix live in the whitepaper README.

- (2026-08-22) **An href assertion proves a link EXISTS; only a hit-test proves anyone can click it.** The desktop-only badge became a `<Link to="/download">` (ADR-0047) and its jsdom test pinned tag + href — while every real pointer click landed on the tile's flex-stretched card button, which covered the absolutely-positioned badge in hit-testing (both z-auto; the button is the LATER sibling). The tag looked clickable, hover worked, and the link was dead for weeks. jsdom cannot see this — `elementFromPoint` and paint order live only in a real browser — so any interactive element that OVERLAPS another control needs a Playwright click-through spec (Playwright clicks by coordinates with hit-target checking, so occlusion reds it; `e2e/desktop-badge.spec.ts`, mutation-verified). - (2026-08-22) **A className with no CSS rule fails as silent layout jank, and nothing checks the binding.** `className="row"` was used in 8 places (vault setup/unlock, wizard) while no stylesheet defined `.row` — the intended `.field-row` existed the whole time — so password inputs and their "show" buttons collided; every suite was green because class→rule resolution is asserted by nothing. - (2026-08-19) **A bridge error is an OBJECT, so `result.error || 'fallback'` renders the literal text "[object Object]".** Six call sites in one starter had it. The app recovered from a refused sync exactly as designed and then described the failure uselessly — replacing the one thing the user needs (what happened, and whether retrying helps) with noise, at the moment they are wondering whether their data is safe. A unit test of the formatter would not have caught it, because the defect was in the CALL SITES: the guard that works is a source sweep asserting no `\w+\.error ||` survives in authored code. Two corollaries. First, a demo harness must reproduce the contract's GUARANTEES, not just its happy path — a stub that ignored `snug:net-request` left the app hung on a spinner and nearly sent me hunting a timeout bug in shipping code, when the real host always posts a terminal frame. Second, when a scripted multi-anchor edit asserts and one anchor misses, it can write NOTHING while looking like it worked; I then tested a binary without my change and diagnosed a phantom. - (2026-08-19) **"Does it survive a relaunch?" is its own verification step, and no suite performs it.** The Gmail starter fetched a mailbox and kept every message in React state — no `useAppDB` call anywhere — so closing the app threw the whole sync away and the next launch showed the demo again. - (2026-08-18) **An emoji is not an icon: it ignores `currentColor` and cannot be themed.** A `🔌` glyph rendered as a faint monochrome outline that read as *disabled* beside its neighbours, and would not have restyled with light/dark — while a geometric glyph (`⚯`, matching the rail tabs' existing `✎ ◍ ✧ ⧉`) inherits the button's colour and hover state. **Both versions passed every test**; only the screenshot showed it. - (2026-08-17) A rebuild the SHELF cannot show is a rebuild the owner reads as "it did not land": the starter tile derives its label from the FOLDER (`folder.replace(/-/g,' ')`), so Telepath still read "whatsapp" — and four other renamed starters read as their folders too. - (2026-08-14) Geometry defects ("one char per line", "overlaps", "cut off") close only by measuring the rendered box in a real browser — `getBoundingClientRect()` ratios in Playwright; jsdom rects are 0×0 and stylesheet-text assertions pass on broken layouts. - (2026-08-06) A sandbox/CSP flag disables whole DOM behaviors, not just channels — C2's `allow-scripts` blocks form submission before `submit` dispatches, so `<form onSubmit>` apps were jsdom-green and browser-dead. - (2026-08-21) **A permission scoped to a WINDOW says nothing about the FRAMES inside it — so a new IPC command's danger is bounded by the invoke-key gate, and the only proof of that is a per-command keyless probe.** Adding `tauri-plugin-updater` puts `download_and_install` — arbitrary binary installation as the user, strictly worse than anything the shell had — one reachable IPC call away from every sandboxed app iframe. ## Diagnosis & stream forensics

- (2026-08-23) **A dev server that starts cleanly but 404s `/index.html` is probably serving the wrong ROOT — read the process's argv before its config.** "Playground starts but doesn't load" was vite launched as `pnpm dev # localhost:5173`: zsh does not treat mid-line `#` as a comment in interactive shells (that needs `setopt interactive_comments`), so vite received `#` as its root-directory argument and served a nonexistent folder — healthy process, 404 on everything. `ps -o command` showed the stray args in one look; the same branch booted perfectly under a clean invocation. Reproduce on YOUR OWN instance before diagnosing the code: two processes from one tree behaving differently indicts the invocations, not the tree.

- (2026-08-17) **Reproduce the failure before fixing it.** Two consecutive misdiagnoses of one symptom (an old Node on the GUI PATH; a stale binary) were both REAL problems that were not the reported one — each inferred from plausible evidence and shipped without confirmation, costing the owner three attempts at the same button. When a symptom persists after a fix, the first question is "did my fix actually run", answered by observing, not reasoning.
- (2026-08-17) Before asking "what could cause this?", ask "what would I READ to settle it?" — three wrong theories (stale `dist`, an install-source redirect, a stale binary) died in seconds against `~/Snug/user.sqlite`, the producing function, and `creds.json`. Enumerate the artifacts that hold the answer (the DB, the state file on disk, the function that produces the value, the live process's own reply) and read them FIRST; a plausible cause you can name is not evidence, and acting on one spends the user's attempts, not yours. This is the reproduce-first rule applied one step earlier.
- (2026-08-22) **A reader that swallows a parse error reports corruption as ABSENCE — and the error message downstream then names the wrong fault.** Baileys logged `failed to find key "AAAAAK7c"` for a key file that EXISTED: its `readData` catches `JSON.parse` failures and returns null, so a torn write (file ending in a stray `"}` — the library writes in place, not temp+rename) surfaced hundreds of lines away as a missing-key park that re-fired every server resync, forever. The wording sent diagnosis toward key delivery; one `cat` of the named file settled it in seconds ("what would I READ to settle it?" — the file the error names is artifact number one). Two generalizable halves: any `catch { return null }` around deserialization converts every corruption into the semantics of "never existed", inheriting whatever remedy absence gets (here: wait for a phone that will never re-send); and any state a library writes in place is one kill away from that path. The fix is the thread-cache discipline applied to the library's storage seam: atomic writes, salvage the parseable prefix, quarantine — never delete — the rest. And when you write the replacement, keep "absent" meaning ENOENT and nothing else: the first cut caught every read error alike, so a transient EACCES at boot would have minted fresh credentials that the next save wrote over a working session — the same conflation, rebuilt in the fix.
- (2026-08-18) **A false positive in a detector that triggers a DESTRUCTIVE remedy is worse than no detector.** A "half-linked session" check read `creds.registered !== true` as broken; in baileys@7.0.0-rc14 that flag is set in exactly ONE place (the phone-code path), so every QR-paired session — the only kind this helper makes — reads false forever. The app told the owner to re-link, re-linking WIPED the working session, and the loop repeated twice before I checked the library. Before wiring a detector to anything that deletes, resets or re-prompts: grep the producing library for every site that WRITES the field, and test the predicate against a real healthy artifact, not only against the broken shape you imagined.
- (2026-08-18) Detect on the MATERIAL a state needs, not on a flag that happens to correlate: "can this session resume?" is answered by `account` + a non-empty `signalIdentities` (what pairing actually writes), which is flow-agnostic — the `registered` flag was a phone-code artifact that said nothing about QR sessions at all.
- (2026-08-18) Every spawn owes a REAP, and the reap needs a caller: `sidecar_ctl("stop")` was implemented, tested and reachable — with zero callers and no exit hook — so quitting the shell orphaned the helper, the next launch spawned a rival against the same session store, and two writers wedged the link. The symptom ("it loses my connection across restarts") pointed at credential persistence, which was blameless. When a child process outlives its parent, suspect the missing lifecycle half before the data layer — and pin the hook at the source level, because a hook nobody calls is the untested wire in its purest form.
- (2026-08-19) **An exit hook only covers the exits that run it — the child must also be able to outlive nothing.** The lesson above was fixed by giving the reap a caller, and the wedge came back anyway: `shutdown()` runs on a CLEAN quit, while a crash, `kill -9`, or a `tauri dev` rebuild runs nothing, so the helper was orphaned exactly as before and the next launch's rival produced a permanent `conflict type=replaced` loop. A supervised child needs a lifecycle answer from BOTH ends — the parent reaps on exit, AND the child dies when its parent does (watch for a CHANGED ppid, not `ppid === 1`: a Linux subreaper adopts orphans to some other pid). The corollary that made this task bigger than one file: a fix living only in the child cannot retire the orphans that older builds already leaked, so the parent also needs to reap a process it did not spawn — and that path must verify the target's command line, never trust the pid alone, because pids are recycled and a fix that kills a stranger is worse than the bug.
- (2026-08-17) Ask what SURVIVES: a restart (the sidecar token was `createMemoryStore` in production, so every helper restart invalidated the host's stored copy) and an interruption (a flow that died mid-link left `registered:false` + `me` on disk and wedged every retry, because nothing ever cleared it). Any durable state owes an answer to both.
- (2026-08-18) **A separately-installed artifact is a SECOND deploy target: rebuilding the repo updates nothing it runs.** The sidecar helper is copied to `~/Snug/helpers` by `install:helper`, and two full hardware walks ran against a pre-task build — empty store, "syncing 0%" forever — while every suite in the repo was green against the new code. A running process is a THIRD target: it keeps the code it loaded at spawn, surviving any reinstall until respawned. When deploying a change, enumerate every copy of the code that exists (repo, installed artifact, live process) and verify each moved; a version stamp checked by the spawner is the durable fix (filed in next-steps).
- (2026-08-18) **Classify failures before charging them to a retry budget: a throttle is evidence about the MOMENT, a refusal is evidence about the TARGET.** Meta's `rate-overlimit` (287 hits in one evening) consumed the per-group retry budgets of perfectly loadable rosters and permanently wrote them off, while `item-not-found`/`forbidden` — definitive answers — were being retried five times each, learning nothing. Throttles now pause the WHOLE sweep on an escalating cooldown and charge nobody; definitive refusals write off after one attempt. Two corollaries earned the hard way: a guard tuned to one cadence becomes a bug when the cadence changes (a 20 s stall detector hid the pill inside every backoff gap the new retries were DESIGNED to have); and a failing-only steady state that persists nothing is undiagnosable from disk — aggregate failure CLASSES into the durable artifact, because that is what turned "no new names, no idea why" into three named causes in one read.
- (2026-08-18) **An alias mapping needs value propagation in BOTH directions, or one-way resolution leaves known data unreachable.** Push names learned from group rows land under the sender's LID spelling; the DM with the same person is keyed by phone number; `resolveIdentity` maps LID→phone only — so the directory KNEW the name and the chat list still rendered a bare +number. When two spellings identify one entity, recording the pairing must also copy every value already held under either spelling to both (or lookups must consult a reverse index); test with the value under each spelling and the lookup from the other.
- (2026-08-18) **A flush hooked on process death is only as real as the signal the reaper actually sends.** `process.once('exit', flush)` shipped with a comment claiming "the reap is SIGTERM → clean exit" — but the shell reaped with Rust `Child::kill`, which is SIGKILL, and no handler of any kind runs under SIGKILL. Before claiming an exit-path handler runs, read the reaper's send (`kill()`? which signal? which platform?) and pin it with a test whose child can only produce the observed artifact FROM the handler (a marker file written inside the TERM trap — a SIGKILL-only reap can never fake it).

- (2026-08-14) One symptom can have several independent producers: when a symptom rides shared state, grep the FLAG for every writer before claiming a fix — the pending-ticker had three producers and was "fixed" wrongly twice. State which producers you closed and which you did not.
- (2026-08-12) Diagnose "nothing happens" from the user's first visible surface inward, never from the component nearest the feature — the Coinbase CTA died at `openConnectionWizardForApp`'s zero-row guard, a layer above both diagnoses. An error state is not surfaced until something RENDERS it; grep for the subscriber.
- (2026-08-12) A causal chain or ranked hypothesis is fiction until the suspect input runs through the real code — a 3-line probe of `balancedObjects` refuted the #1 theory before any repro, and recon killed a "replayed conversation" mechanism a fix would have been built on. Pin every refutation as a characterization test so the dead theory cannot be re-inherited.
- (2026-08-05) A state variable's meaning is relative to its reader: when repointing a surface at existing state (`steps` → live status line), re-ask what the state means at start/mid/end/error/abort, and prefer the signal whose name matches the new question (`busy`). One test must drive real state through a full turn.
- (2026-08-05) Replacing a bound means re-deriving it: enumerate every retained field and every event that can GROW an existing record — the byte budget's size function omitted fields (off by 166,000×) and its keep-the-newest escape hatch exempted the one entry that kept growing. One adversarial test per growth path.
- (2026-08-12) When a stream looks truncated but `stop_reason` says finished, compare `usage.output_tokens` to delivered chars and look for tail-references-to-missing-head — a big gap convicts DELIVERY, and no parser change may ever make corrupt bytes "parse".
- (2026-08-12) To clear or convict a framing layer, replay a real captured stream through the real code split at EVERY byte boundary and assert byte-identical assembly; keep the suite as a tripwire — if it ever reds, your layer has ACQUIRED the bug (P0, not flake).

## Agents, reviews & process memory

- (2026-08-26) **A task that closes ANOTHER task's numbered finding must strike it where the finding lives, not only journal its own work — an un-struck "we have an interoperability bug" outlives the bug and becomes the public record.** The 2026-08-21 security review listed seven numbered findings in `next-steps.md`; `a40302e` fixed two of them the next day (the `SNUGENC1` slot-stride in the normative spec, the always-firing `healMissingTables`) and journaled the fixes under its own task. Four days later an outside read of the backlog concluded that the published 1.0 container layout disagreed with the reference code — false since before the spec was published, but the only place an outsider could check said otherwise. For a project whose credibility rests on publishing its defects, a stale open defect is worse than the defect was. At Gate 6, grep `next-steps.md` for the mechanism you just fixed (function name, section number), and strike the entry in place with the closing commit; the same rule applies to the threat model's dated premises ("CI has not run since…") — add a dated errata line the moment the premise flips.

- (2026-08-26) **A "the ONE derivation" claim is only as true as the list of override layers it models — enumerate every seat that can re-route the value per context before wiring a global surface to it.** TASK-20260826's brain chip consumed the extracted adapter-routing derivation (`adapterKindFor`) and its module comment claimed the global route "is the only route that can land on the demo brain while a real brain is configured." The claim was false twice over, found by the review pass, not the author: the send path layers a FRESH-THREAD provider pick (`useBuilderChat.ts` `freshPick`) and a PER-APP provider pin (`builder.ts` `appProviderPinFor`) on top of the global stores, so the chip could say "demo brain — nothing is called" while a turn went to OpenAI with a real key, and say "claude" while a pinned-but-keyless app ran the mock script. The derivation itself never drifted — the SURFACE was wired to a prefix of its real inputs. Rule: before a status surface claims to mirror a routing decision, grep every construction site of the routed thing for context-dependent overrides (`?? provider`, `pinFor(...)`, per-send re-resolution) and either feed each into the surface's derivation or write the exclusion down as a known lie with its interim disclosure named. Corollary: per-turn row provenance (stamped at the send from the actual config) survives all of this, which is why the tag was right in every state the chip got wrong — stamp at the decision, and ambient surfaces become an optimization over provenance rather than the only truth.
- (2026-08-22) **Before adding a variant to a discriminated set, name the discriminator — a variant sharing the discriminant value is invisible to every consumer, and the type's own comments usually say so.** The gmail web flow was planned as a `WellKnownAuthOption`; options are matched BY KIND (`matchedRegistryOption`: "kind is the honest handle"), and a web flow shares `oauth2_auth_code` with its entry — so the fresh-context plan review traced four blockers from that one fact (invisible to option matching → desktop runs loopback against a web client mid-flow; `?? entry` posture fallback makes "no desktop transport" unrepresentable; persisted fields/registration seats break auto-select-without-persisting; `authOptions` seeds the surface-blind chat choice card). The cheap pre-check that would have caught it at planning: for the set you are extending, write down what distinguishes members TODAY and whether your new member differs on that axis — if it does not, you are not adding a variant, you are redesigning the discriminator (the right answer was a different seat entirely). Companion to the 2026-08-19 propose-into-doctrine rule: this is the version where the doctrine lives in the sibling type's comment, not the file you are editing.
- (2026-08-21) **A control that exists in one seat and not its sibling is the highest-yield thing to look for, and the codebase usually already explains why the control is needed.** The pre-launch audit's four security fixes were all this one shape: the percent-encoded scrub candidate existed in `connected-fetch.ts` under a comment spelling out exactly why raw-only misses base64 credentials, and `oauth-service.ts` never inherited it; the confirm URL was rendered by the chat-lane card and not by the modal; the per-command IPC probe covered `sidecar_fetch` and not the strictly more dangerous `sidecar_wizard_fetch`. In each case the *reasoning* was already written down — nobody had re-asked "which other seat has this shape?". That question costs one grep and it found what four parallel adversarial lanes were dispatched to find. Ask it whenever a control is added, and again before any launch.
- (2026-08-21) **A mechanical check is evidence only for the claim its MECHANISM supports — and the gap between the two is invisible precisely because the check is green.** Two of the eight pre-launch findings were defects in checks, not code. `check-threat-model.mjs` was cited in the threat model as the guard that keeps the delta ledger honest, while its only count assertion was `actual.size >= 8` — a floor that passes at twelve, never reads the §1 prose, and was therefore structurally incapable of catching the "eight deltas vs twelve rows" drift it was being credited with catching. The OAuth error-echo tests were cited as the guard against credential-bearing error bodies, while every fixture token was `[A-Za-z0-9-]`, for which `encodeURIComponent` is the identity — so the encoded-spelling leak was *unrepresentable* in that suite and the tests passed whether or not the defense existed. Both extend the 2026-08-20 "state what the check does NOT prove" rule one step: also ask whether the fixture can EXPRESS the failure, because a test whose inputs cannot exhibit the bug is not weak coverage, it is zero coverage wearing a green tick.
- (2026-08-21) **A guard written as a list of forbidden secrets publishes them; hash the list and recover the sample rather than naming it.** The pre-flip scan found the repo's most damaging leak in the file whose job was preventing leaks — a test carrying the real ancestor-system codenames as plaintext, annotated as "ancestor codenames", i.e. the single most rewarding file in the tree for anyone curious about provenance. Hashing the tokens keeps every property that matters (runs everywhere, no fixture, still fails on a real regression, still names the offending file) and loses only the ability to print the matched token. Two corollaries the fix earned: the planted-token test must RECOVER its sample by brute force over the hash set rather than hardcoding one, or the file still contains one forbidden string and the scrub gate can never reach zero; and a "must be zero" gate whose term list includes ordinary English (`feat` matched 322 lines) or the owner's own public byline can only ever be waved through — which is how the plaintext leak sat unnoticed under 353 false positives.
- (2026-08-21) **A threat model's own scope note is a debt, and the next pass inherits it silently unless someone reads it.** v2 stated plainly that its adversarial pass covered only the four new surfaces and that "the rest of this document is v1's, re-checked mechanically but not re-attacked". Nothing was hidden — and a launch review that simply updated v2 would still have shipped v1's audit as current, because the limitation lived in a header paragraph nobody re-reads. Treat every "what this version did not do" note as an open work item with an owner, not as disclosure that discharges itself; the honest sentence is what makes the debt findable, but only if the next pass is briefed to go looking for it.

- (2026-08-20) **A staged-but-never-pushed downstream branch is drift no changelog can see.** The edition-1 whitepaper sat 13 days as a local `docs/whitepaper-v0.1` branch in the spec clone: the spec-changelog tracks PUSHES, so its flow never saw the branch, and the v0.3 publication would have silently orphaned it had the owner not said "check for pending branches". Before any downstream publication, `git fetch --all && git branch -a -v` in the downstream clone and DISPOSITION every unmerged branch — land it (rebase keeps one-commit-per-task history linear), or delete it with a recorded reason. Staging without the push ask parks the artifact in the one place no invariant checks.

- (2026-08-21) **A plan review's value concentrates in the findings that say "this cannot work", not the ones that say "this could be better" — and those come from reading the CODE the plan names, not the plan.** Twenty-one findings survived adversarial refutation on the hardening plan (0 refuted, which is itself unusual and probably says the refuters were too easily satisfied). Of the twenty-one, two were blockers, and both were of one kind: the plan asserted a delivery mechanism ("bump the version and installed copies take the docs via the existing update channel") that the existing code could not perform, in two independent places. The other nineteen improved the work; those two were the difference between shipping an item and shipping the appearance of one. The distinguishing feature is what the reviewer read: the blockers came from opening `starterUpdate.ts` and tracing the offer and apply paths against the plan's sentence, while the improvements came from reading the plan closely. **So brief the reviewer to verify the plan's mechanism claims against the named files first, and treat "the plan says X will happen — does the code that must do X actually do it?" as the highest-yield question available at Gate 2.** A plan is a claim about a codebase; only the codebase can refute it.
- (2026-08-20) **The plan review and the diff review catch DISJOINT defect classes — run both on High tier, and expect the second to contradict the first.** The fresh-context PLAN review found design bypasses (a well-formed `responseSchema` as an in-band smuggling channel; a whole second lane with no app-message wire); the eight-angle DIFF review found implementation divergences the plan could not contain (a re-spelled grammar, UUID mangling, an approved-only predicate that unbound every imported file) — and one diff finding ("wipe on import") was correctly resolved AGAINST the reviewer because a sibling finding showed the import path needs the directory. Review findings are inputs to a decision, not a checklist; record the consciously-rejected ones with their rationale in the task file.

- (2026-08-18) **Never `git add -A` on a branch you did not cut from a clean tree.** A hotfix branch was cut off a `main` carrying the owner's UNCOMMITTED work for another task; the blanket add swept 31 files and five commits' worth of a per-app-model-selector feature into a squash merge titled for a WhatsApp bug. Nothing was lost (the diff against its own branch was empty and its tests passed), but the attribution is now unrewritable without force-pushing shared history. `git status` BEFORE the first add, and stage explicitly when it is not empty — the cost is asymmetric: seconds to check, permanent to misrecord.
- (2026-08-18) **Urgency is the condition the gates exist for, not an exemption from them.** A shipped bug that was actively destroying the owner's data got fixed, verified and merged with no task file and no done-index entry — Gate 1 skipped precisely when the change most needed a record. Write the task file first even when the fix is obvious; it takes a minute and it is the only thing that survives the session.

- (2026-08-12) Any agent that WRITES gets `isolation: "worktree"` — file-disjoint lanes still share the git index (raced commits, a stash displacing in-flight work), and mutating reviewers in a shared tree measure each other's breakage. Concurrency without isolation is only safe for read-only reviewers; otherwise serialize commits through the orchestrator.
- (2026-08-13) Re-derive consequential agent claims from primary sources before acting on or repeating them — a platform-blocking verdict was confirmed link-by-link in the pinned crates first; a reported "production typo" was another reviewer's live mutation. The more concrete the claim, the more tempting to skip exactly the check that would expose it.
- (2026-08-19) **Propose into a codebase's stated doctrine, not past it — the file usually says no in a comment you have not read yet.** A plan proposed adding an `'attention'` member to `ConnectionWizardStep`; `ConnectionWizardSheet.tsx:1842` carries a block titled "WHY NOT NEW STEPS" rejecting exactly that, and the fresh-context review traced three concrete breakages it would have caused (`showDiff` is step-keyed and would go false; `nextStep` early-returns `'done'` for LAN rows ABOVE its switch, so a LAN row with a live failure would skip review; three unproven-row catch-alls key on `step !== 'review'` and would all fire underneath the new screen). The correct shape — a DERIVED gate — was the one the file already used four times. Before extending an enum or state machine, grep its own module for the rationale comments; a codebase that solved this problem before wrote down why.

- (2026-08-20) **A mechanical check earns exactly the claim its mechanism supports — write down what it does NOT prove, in the document that leans on it.** Hash-pinning eight source documents proves none of them MOVED beneath the consolidation; it says nothing about whether their residuals were CARRIED into it. The checker was green while three were missing, and the Gate-5 reviewer found them by reading the deltas — the thing the check exists to force, and cannot perform. State the limit beside the mechanism, or the green becomes evidence for a claim nobody verified.
- (2026-08-20) **A fresh-context reviewer runs against the tree it can see, so a mid-edit working tree produces confident findings about code that no longer exists.** One review reported the branch red and the harness broken, having sampled between a red test and its fix, then compared against a journal line from an earlier commit; probing the harness directly (a deliberately failing test) showed it reporting the failure correctly. Commit to a coherent state before dispatching reviewers — and when a finding contradicts something you can measure, measure it before accepting or dismissing it. The same review's other five findings were all real.
- (2026-08-15) A comment's claim about ANOTHER surface is a pointer to verify, never evidence — ADR-0028's whole "consent is visible" justification rested on a protocol comment saying "`scopes` is what the review renders" while no renderer existed (the fresh-context plan review's blocker). Before citing "X renders/enforces/strips Y", grep for the consumer; a doc-comment can describe an intention nobody built.
- (2026-08-08) Pair every finder with an independent refuter that defaults-to-refuted and must produce a runnable probe, not an argument — 4 of 10 review findings died, each a would-be "fix" to correct code.
- (2026-07-31) Every High/Medium merge gets a fresh-context adversarial review that RUNS probes against the constraint surfaces — pre-merge reviews caught a C1 credential leak via `responseSchema` and a meta-CSP bypass that the authors' green suites missed.
- (2026-08-08) Design review and implementation review find disjoint defect classes — five design reviews bought zero protection against a call-site default mismatch and a missing test. Budget both for High-tier surfaces; "the design was reviewed hard" is zero evidence about the code.
- (2026-08-10) Multi-phase work ends with a WHOLE-SURFACE review tracing one datum end to end, asking at every handoff what the receiver trusts that the sender never guaranteed — two lints disagreeing about "declared" fields was invisible to eleven green per-phase reviews.
- (2026-08-12) A consumer's first act is verifying the producer's work EXISTS in the shared substrate (commits present, symbols grep-able), never trusting the handed-in summary; an empty fan-out result is a tool-failure hypothesis before a no-findings conclusion. Budget one integration probe across independently-green components — the first real boot is a test.
- (2026-08-15) A dependent package's green suite vouches for the producer's last BUILD, not its source: apps resolve `@snugprotocol/*` through `dist/` (package.json `main`), so after editing a package's src, rebuild it BEFORE trusting any dependent's local vitest run — playground ran 103/103 "green" against a two-day-stale auth build while its own fixtures contradicted the new registry. Root `turbo run test --force` rebuilds via the task graph; bare `vitest` in an app does not.
- (2026-08-08) Repeating a journaled mistake means the journal entry is the defect: rewrite it as a procedure change that makes the error unreachable ("commit before any mutation cycle"), never as a caution to remember. "Be careful about X" is not a fix.
- (2026-07-31) Verify any public-facing name (package, command, protocol message) against GitHub/npm/web in the session it is proposed — twenty "obviously free" candidates were all taken.
- (2026-08-07) A document derived from a spec is checked by diffing SETS and MODALITY, not token presence — `MALFORMED` "appeared" while the claim around it overclaimed the spec, and internal C1/C2 doctrine was silently promoted to protocol requirement. Grep the published source for each MUST/never/always before shipping it.

- **A dependency advisory's severity is not its reachability — classify against the surfaces you actually ship.** The 36 alerts that opened the flip-public triage were 11 advisories multiply counted per manifest; the three *criticals* were vitest's UI-server RCE, and `@vitest/ui` is not installed anywhere in the workspace. A static Astro site runs no request-path code, so its SSR-XSS advisories are build-time only. Read `pnpm why`/the config before arguing about a CVSS score. (ADR-0056, TASK-20260824)
- **`pnpm.overrides` with a `>=` target resolves to the newest MAJOR, not the nearest patch.** `"nanoid@<3.3.18": ">=3.3.18"` silently installed nanoid **6.0.1** — three majors up and ESM-only, into a tree whose Astro config carried a nanoid ESM-interop workaround. Pin the line you mean: `"^3.3.18"`. Verify what an override actually resolved to (`grep nanoid@ pnpm-lock.yaml`) rather than trusting that it "applied".
- **Node resolution walks ABOVE the repo — a stray `node_modules` in `$HOME` can shadow a workspace package.** Astro 7 imports `parseCookie` from `cookie@2`; `/Users/<user>/node_modules/cookie@0.5.0` won the lookup from `apps/website`, and the build failed with "does not provide an export named `parseCookie`" while the correct 2.0.1 sat linked in the store. Diagnose with `createRequire(cwd).resolve('<pkg>')` — it prints the winning PATH, which no version listing will tell you. Fix in-repo by declaring the dependency explicitly.
- **A dependency upgrade's real test is the rendered OUTPUT, not the exit code.** Astro 7 changed the default Markdown processor, whitespace handling (`compressHTML: 'jsx'`) and CSS ordering all at once; the build went green while every one of 26 pages changed bytes. Diff the built output with styles/scripts stripped and scoped-style hashes normalized — that proved prose byte-identical 26/26 — then check the whitespace change specifically for INLINE-element adjacency (`</a><a>`), and confirm the containers space via CSS `gap` rather than assuming. A whitespace-normalizing diff would have masked exactly the defect the change could cause.

- (2026-08-27) **A social card built from a product SCREENSHOT goes stale the moment the product does — and the cache makes it permanent.** The site's `og:image` was the landing teaser's poster frame: real, on-brand, already shipping, and therefore an easy call. It was also a picture *of the Playground hub*, so a positioning change left the card showing the old `talk. build. run.` hero beneath a correct new title — a card whose picture contradicts its own words, which is worse than a plain one. The trap is the timing: social caches are keyed per URL and sticky, so **the re-scrape you run to publish the fix is what pins the stale image on every platform for weeks**. Check what the card actually depicts before triggering any inspector. The durable fix is to DRAW the card (a generated SVG carrying the positioning) rather than capture it, so it cannot drift behind a UI change. Second, sharper half: the stale `og:image:alt` survived a whole-codebase positioning audit because **nothing renders alt text visibly** — it is single-homed in one config file, invisible in every screenshot and every page walk. When auditing copy, grep the attributes a human never sees (alt, aria-label, title, meta) as a separate pass; that is where a retired claim outlives its own removal.
- (2026-08-27) **A caption, alt text, or label must describe the artifact it labels — not the copy you wish the artifact carried.** Two cases in one session, opposite resolutions, same rule. (a) The teaser video was recorded before a positioning change, so its on-screen words are the old ones; the caption beside it now describes the footage generically rather than quoting new copy the video does not contain. (b) The org banner's alt text described the old wordmark baked into the PNG — the first instinct was to "fix" the alt text to the new positioning, which would have told screen-reader users something sighted users could see was false. The right move was to leave alt text honest and **regenerate the image**, which turned out to be one command because a source existed. Generalises: when copy and an asset disagree, either regenerate the asset or describe it truthfully — never paper over the gap in the accessibility layer, which is exactly where the lie is hardest to notice.
- (2026-08-27) **Before reporting an asset as "no editable source, please regenerate by hand", search for a generator — binaries in this repo are usually built, not drawn.** The org profile banner looked like an opaque 476 KB PNG and was nearly reported as owner homework. It is produced by `scripts/build-social-previews.mjs`, which renders SVG and reads the brand palette out of `apps/playground/src/theme/tokens.css` so it cannot drift from the site. The whole change was two lines of text plus a re-run. Check `scripts/` and the runbooks before declaring an asset unmaintainable.
- (2026-08-27) **A running copy of the product fails the desktop gate leg, and the failure looks like a code defect.** `gate-local --all` reported `desktop FAIL — exited 1` with `[gate] shell exited (0)` immediately above it: the installed `Snug.app` was open and held the **single-instance lock**, so the gate's debug shell was refused and died before writing `gate-results.json`. The gate already prints the cause and the `ps aux | grep "[s]nug-desktop"` command to confirm it — read the FATAL line before diagnosing, because the enclosing verdict ("Do NOT merge") is indistinguishable from a real regression. Quit the app (gracefully, so its close-flush runs) and re-run `--legs=desktop`. Worth remembering whenever a leg that launches a real application fails on a developer machine but not in CI: CI has no logged-in desktop session, so this class of failure is local-only by construction.
- (2026-08-27) **A derived page's upstream source is the thing to edit first, or the gate will drag the old content back.** `apps/website/src/pages/index.astro` is listed in `docs-sync.json` as *authored from* `docs/product-vision.md`. Rewriting the page alone leaves the vision doc contradicting the site, green gate and all — and the next `/sync-website` walk re-derives the page from the stale source. Move the source, then the derived pages, then re-hash. The gate is only honest if the hashes describe a real derivation.

## Storage, config & mechanical edits

- (2026-09-04) **An anchored insert placed "before a declaration" can land between a modifier and its keyword.** Inserting a helper component above `function OpenUserFileConfirmDialog` split `export function` into `export /* helper */ function`, so the dialog silently stopped being exported and three unrelated tests failed with "Element type is invalid". Anchor on the FULL declaration line including its modifiers (`export function X`), or on the comment block above it — and when a Python patch script's assert fires on a later replacement, know that nothing before it was written either (the file is written once at the end), so re-run the whole script rather than assuming the early edits landed.
- (2026-09-04) **Widening a persisted TEXT enum is a write-time change, not a storage-version change — and bumping `USERDB_SCHEMA_VERSION` for it strands every older hub in the field.** The plan bumped v6→v7 for the `shared` provenance; the fresh-context plan review showed `migrate()` would stamp v7 on the first open of ANY v6 file, after which desktop v0.1.2 refuses the file and a v6 device's sync pull throws `BAD_IMPORT` — for users with no shared row at all. `linked_device` (ADR-0032) set the precedent: append the literal, keep the compile-time exhaustive `switch` (a `never` arm with a runtime fallback for values a NEWER file may carry), record it in the spec-changelog as an enum widening. Reserve a version bump for a change an older reader cannot survive.

- (2026-08-25) **A credential added to a config file can BREAK the tool that file configures — and unsetting the shell variable will not save you, because the tool reads the file.** Putting `CLOUDFLARE_API_TOKEN` in root `.env` (a deliberate, temporary exception to ADR-0054's "never put a token here") made the next deploy refuse with `REFUSED: pnpm exec wrangler whoami exited 1`: **wrangler reads root `.env` on its own**, a token there OUTRANKS the OAuth session, and that token lacked the `user (read)` scope `whoami` needs to enumerate accounts. `env -u` / `VAR= ` had no effect — the value came from the FILE. The rule the ADR stated as a secrets posture turned out to be a TOOLING constraint too. **Before adding any credential to a dotfile a CLI also reads, ask which auth it will now prefer and whether that identity can do everything the old one could** — a token scoped for one job (zone edits) is not a superset of the session it silently replaces, and the failure surfaces later, in an unrelated command, as a permissions error that reads like expiry.

- (2026-08-20) **`z.toJSONSchema` drops `superRefine` silently, so an exported schema of a refined contract is always WEAKER than the contract — publish the gap or don't publish.** The net-request export cannot express "no body on GET/HEAD" or the credential-header refusal; a connection-requirement export could express neither the lanHost XOR nor the kind coherence arms. Two rules (ADR-0044): state the gap in the artifact's own home (Appendix C + the SOURCES comment both say "a validator passing the schema has not validated the frame"), and pin the property that DID survive in both directions (strict files must carry `additionalProperties: false`, tolerant files must never) — a one-direction pin lets the next regeneration flip it without a red.

- (2026-08-18) **Putting a per-entity row in a SHARED key/value namespace buys "no migration" and owes a cascade.** `appModel:<appId>` in `snug_settings` skipped a schema bump entirely (ADR-0036 D2) — but `snug_settings` is not app-keyed, so `deleteApp` cannot sweep it by `app_id` and a missed key becomes a silent orphan that later applies to a REUSED id. Whenever a namespaced key is chosen over a column, name the delete path in the same change and mutation-check it. Prefer an EQUALITY delete over a `LIKE` prefix when there is exactly one row per entity: no metacharacter escaping, and no over-match against a sibling id.
- (2026-08-18) **Inheriting a default must be an ABSENCE, not a copy.** Storing no row means an un-picked entity FOLLOWS later changes to the global default, and "pinned" stays distinguishable from "inherited" both on screen and in the file. Copying the default in at first open freezes every entity at whatever the default happened to be that day, and the two states become indistinguishable forever after. Clearing a pick must therefore DELETE the row, not write an empty string — an empty-string row hydrates back as a falsy pick that different readers disagree about.

- (2026-08-03) Never `INSERT OR REPLACE`/upsert into a table you did not define without verifying the uniqueness constraint the conflict clause needs (`sqlite_sequence` has none; UPDATE-then-INSERT-if-zero is safe) — and restoration tests must exercise state that DIVERGES from what the system would re-derive (deleted-max rows), never the coincidentally-equal state.
- (2026-08-03) Durable browser-storage writes go to a NEW fixed-name file (A/B slots + pointer); reads are direct fixed-name lookups with magic checks and brief retries — OPFS teardown truncates in-place writes, and sql.js accepts zero bytes as a fresh DB, so an empty/magic-less read of a file that should exist is CORRUPT (quarantine), never "fresh".
- (2026-08-02) Config readers treat `''` as unset (`||` or trim-check) for any env var with a fallback — `SNUG_MODEL=` present-but-empty defeats `??`; env templates comment optional vars out rather than leaving them empty.
- (2026-08-17) An identifier that LOOKS like a number is not one: WhatsApp addresses people by LID (`123456@lid`, an internal id) as well as by phone jid, and rendering the LID's digits as "+123456" produced confident, wrong phone numbers — worse than a blank, because a plausible value invites trust. Render a formatted identifier ONLY for the address space that defines that format, and resolve the alias (Baileys ships `lidPnMappings` + `lid-mapping.update` for exactly this) before deciding two spellings are two people.
- (2026-08-17) A FAILURE is not a FACT, and caching it as one turns a hiccup into a permanent defect: avatar lookups cached "could not fetch" in the same slot as "has no picture", so one bad moment meant no profile pictures until the process restarted. Cache the negative only when the source states it (a clean "none") — never when the attempt merely failed.
- (2026-08-17) Read the dependency's own `.d.ts` before designing around a field you remember: Baileys reports `unreadCount` ONLY as a sync snapshot and never increments it live (it ships `shouldIncrementChatUnread` precisely because consumers must count for themselves), and `downloadMediaMessage` takes an optional `reuploadRequest` context without which every expired media link silently fails. Both would have shipped as "works in fresh fixtures, broken in real use".
- (2026-08-21) **A glob pattern written in prose inside a block comment can END the comment** — `examples/*/app.html` contains `*/`, so the doc comment terminated mid-sentence and esbuild failed the whole module on the next word. The failure surfaces as a baffling parse error lines below the cause. Spell glob patterns out in words inside `/* … */` comments (or use line comments); the codebase's existing modules already do this, which is why the pattern only ever appears in code strings.
- (2026-08-21) **Inside a template literal, a backtick in a COMMENT closes the string — the sibling of the glob rule above, one delimiter over.** Adding a probe to `gate/ipc.ts` meant writing a comment inside the giant `PROBE_HTML` backtick template; the comment referred to a command name in backticks, which terminated the literal and produced `Expected ";" but found "sidecar_fetch"` — a parse error naming a token two lines from the real cause. The general rule covers both: **prose written inside a delimited region must not contain that region's terminator**, and the terminator is easy to type by habit because the surrounding file uses it for markup everywhere else. When editing inside a template literal, drop the backticks from prose (write the name plainly) rather than escaping them.
- (2026-08-22) **An interrupted build-tool cache write is a THIRD state — neither fresh nor stale — and its symptoms point at your code, not the cache.** A killed Vite dev server left `node_modules/.vite/` holding only `deps_temp_*` (never promoted to `deps/`), so every pre-bundled dep answered `504 Outdated Optimize Dep` and the visible failure was "Failed to fetch dynamically imported module: RunView.tsx" — reading as an app defect, blamed on the newest edit. Compounding signature: THREE orphaned vite instances on 5173/5174/5175 from successive half-killed sessions, the oldest serving a module graph from before a starter was deleted, so "removed starter still shows" and "apps won't open" were ONE environmental cause. Remedy: kill the strays (verify by command line first), delete the app's `node_modules/.vite`, restart. Procedure change so it stays unreachable (per the 2026-08-08 journal rule): root `pnpm dev` (`scripts/dev.mjs`) runs the server+playground pair with SIGTERM teardown of both. Sibling mask, same session: a guard test validating sidebar slugs against DISK plus a STALE `dist/` stayed green while the site errored at runtime — a guard over a derived artifact needs a freshness tripwire (dist mtime vs newest source) or it vouches for an old build forever.
- (2026-08-21) **A derived cache stamped before a schema existed replays entries WITHOUT that schema's defaults — and a filter on a defaulted field then drops everything, far from the cause.** Astro's content-layer cache (`node_modules/.astro/data-store.json`) was populated before `content.config.ts` gave the docs collection its schema; Starlight then filtered `getCollection('docs', data.draft === false)` — a field whose `false` comes from a schema DEFAULT — so every entry vanished and the build failed with "sidebar slug does not exist", while `astro dev` (which re-syncs) was fully green. General shape: any pipeline that persists validated entries must be re-run when the validator gains defaults, because `undefined !== false` silently un-matches every strict-equality filter downstream.
- (2026-08-21) **"Newest file by mtime" selects the build system's INTERMEDIATE, not its product.** `stage-local-desktop` picked `rw.76850.Snug_0.1.0_aarch64.dmg` — create-dmg's read-write scratch image, written milliseconds after the shippable `bundle/dmg/*.dmg` — and would have served users an unconverted image. - (2026-08-14) A scripted extract-helper replacement must exclude (or run before inserting) the helper's own definition — the replace rewrote the helper's body into self-recursion. A sudden wide failure wave after a "safe" mechanical edit is the suite catching exactly this.
- (2026-08-24) **A guard that names the forbidden thing must KEEP naming it — the scrub's own targets include its enforcement.** Of 53 tracked references to the private strategy path, 10 were the C4 guard machinery (`check-website-sync.mjs` refuses manifest sources under that path; `navIntegrity.test.ts` fails if a website file mentions it), and a mechanical scrub would have disarmed the very guard enforcing the constraint the scrub exists to satisfy. The tell was in the baseline log: a `website-sync: FAIL … C4: source under <that path> refused` line is a PASSING test's expected output. Before removing a string tree-wide, split the hits into *references* and *enforcement*; allowlist the latter by file with a stated reason (never by line number — those rot). `check-sandbox-guard.mjs` had already documented the same trade for `allow-same-origin` in its negative tests.
- (2026-08-24) **A gate that cannot reach zero teaches people to skip it — and it will be a REAL finding it buries.** The flip-public term gate returned 119 hits; post-scrub it would still return 82 (the owner's byline 73, plus one ancestor codename that is also the ordinary English word "guardian", which Snug's own legal pages must use in "a parent or guardian set it up"). The runbook already blamed exactly this for burying a plaintext-codename BLOCKER under 353 false positives. Fixing it took TWO rounds, the second inside the fix: splitting the list into must-be-zero and review-only still left 9 hits, because a bare `sk-ant-api03-` term matched 7 synthetic redaction-test fixtures — so the term became a length-anchored pattern (`{90,}`) that matches a real 108-char key and none of the fixtures. **Design the gate so its passing state is reachable, then assert only against that list**; keep the ambiguous terms on a review-only list no gate counts.
- (2026-08-24) **A planted-sample test cannot prove a matcher's contract when the samples are unrepresentative by construction.** A repo-wide scanner hashes forbidden tokens, so a performance prefilter skipped windows containing characters no token can hold. Narrowing that prefilter to `/[a-z]/` — a plausible "tidy the regex" edit that silently stops scanning every window with a digit or dash — **passed all six tests**, because the only tokens recoverable by brute force are the two shortest and both are pure alpha, while the longer tokens that might carry a digit are unrecoverable *by design*. No planted-token test can ever reach them. The fix was to assert the prefilter's CONTRACT (read `TOKEN_CHAR` out of the script's own source; require every character of the published alphabet to be admitted) and to differential-test the skip arithmetic against a naive scan — 1,465,000 cases, zero mismatches, and an `i = j + 1` off-by-one fails it. Sibling of the 2026-08-24 centralization-lint entry: *the subject of a matcher's test must be the matcher's contract, not a convenient sample.*
- (2026-08-24) **Deleting a label from prose can delete a distinction the prose depended on.** Rewriting `<codename A>'s five-kind shapes reconciled with <codename B>'s fail-closed posture` to `one ancestor system's … the other's` reads fine — but only where an antecedent says there are two. In `params-to-auth-spec.ts` nothing did, so `the other's` dangled; in ADR-0017 the same pass produced `the ancestor system` (definite singular), asserting there was ONE and contradicting the two-system framing used everywhere else. Both slipped past the author and were caught by fresh-context review. When a scrub removes the tokens that were doing referential work, **re-read each rewritten sentence with no knowledge of the removed word** — and expect the failures to cluster in exactly the sentences that distinguished between the things you just stopped naming.
- (2026-08-14) An anchored Edit that consumes a heading must re-emit it verbatim, and append-only files get a headings-only grep afterward — a spec-changelog insert silently orphaned the prior entry's body under the new heading.
- (2026-08-25) **A code-signing/notarization ticket is keyed to the hash of ONE FILE — "the app is notarized" says nothing about the disk image carrying it.** Tauri's bundler submits the `.app` (as `Snug.zip`) during `tauri build`; the DMG it then wraps around that app is a different file with a different hash and was never submitted, so `xcrun stapler staple` on it fails with `CloudKit query … failed due to "Record not found"` — an error that reads like an Apple outage, not like a missing submission. Both artifacts need their own submission for different reasons: the DMG is what a human downloads and Gatekeeper judges at mount, the `.app` is what survives the drag to /Applications and is judged at every launch. Sibling trap in the same pipeline: `tauri build` writes the updater tarball from the app **as it stood before stapling**, so shipping that file hands every auto-updating client an unstapled bundle — the exact offline-first-launch failure stapling exists to prevent, delivered through the update path instead of the download path. Rebuild the tarball from the stapled app and re-sign it. General shape: **when a toolchain produces several artifacts from one source, ask of each one separately which attestations it actually carries** — and verify by extracting the shipped bytes and re-running the platform's own validator on them, never by reasoning from the source they were built from.
- (2026-08-25) **A new build step's OUTPUT DIRECTORY needs a .gitignore entry in the same change that creates it — `git add -A` will happily commit 35 MB of binaries.** `scripts/release-desktop.mjs` was written in an earlier task and its `apps/desktop/release-out/` was never ignored, because until this session the script had never produced anything. The first real release staged a DMG + tarball there, a routine `git add -A` swept them in, and they merged to `main` — permanently, since removing them means rewriting history. The repo's own `.gitignore` already carries a comment about a 1.5 MB `trace.zip` committed the same way on 2026-08-20, which is the tell: this is a *recurring* class, not a one-off. **When a script gains a step that writes artifacts, ignore its output path in the same commit** — and when a script runs for the first time, `git status` before `git add -A`, because that is the run that reveals what it actually writes. Publishing to a durable home (a GitHub Release) does not make a second copy in git harmless: it is the same bytes, forever, in every clone.
- (2026-08-25) **An UNSET secret-bearing env var is not an empty one — it means "ask a human", and there is no human.** `tauri signer` prompts for the key passphrase when `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` is absent; with no TTY the build dies `incorrect updater private key password: Device not configured (os error 6)`, a message that blames the password rather than naming the missing terminal. It cost two builds because the failure lands **after** the notarization round-trip — the slowest, most expensive step — so each diagnosis cycle was ~15 minutes plus an Apple submission. Where a tool distinguishes unset-from-empty, set the value explicitly inside the script to match the key's real state rather than relying on the caller's environment; and order a pipeline so its cheap credential checks run **before** its slow irreversible ones (the same run's `appleSigningPlan` refusal, which fired in three seconds instead of ten minutes, is the shape to copy).
- (2026-08-26) **A config knob that a sibling file already documents as MEASURED-INEFFECTIVE is a trap with a warning sign on it — read the sign, then check whether you have the same bug.** CI's first live run after flip-public reddened on two tests timing out at vitest's 5000 ms default, and the obvious fix (raise `testTimeout`) is exactly what `apps/playground/vitest.config.ts` records as *already tried, measured not to move the failure rate (2-of-6 before, 2-of-8 after), and reverted* — with the reason stated: *"an ineffective config change is worse than none, because it reads as a fix that holds."* Measuring instead of copying showed the two cases are opposites. The playground's flake was tests synchronizing on a **fixed wall-clock wait** instead of on their condition, where a longer timeout only widens the window the race can hide in. These suites are **CPU-bound by design** — `no-ancestor-tokens` brute-forces a few hundred thousand SHA-256s to *recover* a forbidden token rather than write it down (which is what lets the scrub grep reach zero), and `packages/db` pays `KDF_ITERATIONS = 600_000` PBKDF2 rounds per container open — so the timeout was genuinely too small: ~550 ms isolated, 3279 ms under a local `turbo` fan-out, **6501 ms on GitHub's 4-core shared runners, a 12-16x penalty**. Same symptom, opposite cause, opposite fix. The discriminator is mechanical: **does the test contain a timer or an await on wall-clock, or is it straight-line computation?** Only the second kind is honestly fixed by a bigger number. Both configs now cross-reference each other so the next reader classifies before copying — and the raise is safe only because a real failure here is a *wrong answer* (a violation found, a token unrecoverable, a container that will not open) which fails in milliseconds regardless of the ceiling; mutation-proven at 339 ms.
- (2026-08-26) **A leg kept deliberately red stops being evidence the moment it fails EARLIER than the assertion it was watching — and nothing announces the change.** ADR-0021 D8 keeps the Windows CI leg red on purpose, as live proof that R-5 (the WebView2 IPC-key leak) is still real, via a failing `keyReachable` assertion. But a later, unrelated task (TASK-20260820, macOS-only bundle) deleted `icons/icon.ico`, and since then the job dies at **compile** — `` `icons/icon.ico` not found; required for generating a Windows Resource file during tauri-build `` — never reaching the assertion. The dashboard looked identical before and after: red. **A genuine R-5 regression and a missing icon are the same colour**, so the leg had been vouching for nothing for weeks while still costing a permanent X on every PR — the exact "trains you to merge past reds" failure the workflow's own dormancy note warns about. General shape: **an expected-failure gate must assert WHICH failure it expects**, or it decays into an unconditional red that outlives its reason. Either pin the expected error (grep the log for the assertion's own message and fail on any *other* failure), or park the leg and write the restore preconditions where the next person will look — never leave a red whose meaning depends on remembering why it is red.
- (2026-08-26) **A required status check is matched by the check-run's NAME as produced, so read it from the API — a name typed from the workflow silently blocks every merge.** Adding required checks to the ruleset meant naming `desktop-shell (macos-latest)`, a string GitHub *generates* by appending the matrix value to the job id; the workflow file itself contains only `desktop-shell` and a matrix list, so any name you write by hand is a reconstruction. A context that matches no produced check is not an error — the PR simply waits forever for something that will never report, with no diagnostic pointing at the typo. Read the exact strings from `repos/{o}/{r}/commits/{sha}/check-runs` on a run that actually succeeded, and pin `integration_id` alongside each context so a different app cannot satisfy a same-named check. **Then prove the rule blocks**: open a throwaway PR, attempt the merge, require the refusal (*"the base branch policy prohibits the merge"*), and delete it. A ruleset that merely reads correctly is worth nothing — the same reasoning as any mutation test.
- (2026-08-26) **Symmetry between two repos is not a reason to give them the same rule — check what each one can actually satisfy.** `snug` and `spec` carry the same `main-pr-only` ruleset, so extending required status checks to both looked like the tidy move. `spec` has **no workflows at all**: a required check there would have waited forever, permanently deadlocking the repo including the owner's own SPEC_SYNC pushes, and the block would have arrived silently at the next push rather than at the moment of the change. One `ls .github/workflows/` on a shallow clone was the whole check. Generally: before copying an enforcement rule across repos, environments, or branches, verify the *producer* of the thing being enforced exists on each target — enforcement configured against an absent producer fails closed, at a distance, on someone else's schedule.
- (2026-08-26) **A guard that accepts two spellings of a secret must verify the one the downstream tool actually READS — otherwise it relocates the failure to the most expensive point in the pipeline.** `release-desktop.mjs` gated the release on `TAURI_SIGNING_PRIVATE_KEY || TAURI_SIGNING_PRIVATE_KEY_PATH`, which reads as generous and correct. But `tauri build` reads only the key's **contents** from the first spelling and has no `_PATH` support at all, so exporting `_PATH` alone sailed through the guard in three seconds and then died inside the bundler with *"A public key has been found, but no private key"* — an error naming the key rather than the variable, after a full universal compile. The `_PATH` form is not wrong, either: `tauri signer sign -f` later in the SAME script takes a file, which is exactly why both spellings looked interchangeable. Two consumers, two encodings, one `||`. The fix is for the guard to **materialise** what the strict consumer needs (read the file into the env var) rather than merely assert that one of them is set. General shape: an `||` across alternative spellings is a claim that every downstream consumer accepts either — check that claim against each consumer's own documentation, and where they disagree, normalise at the guard instead of validating a disjunction. Sibling of the 2026-08-25 unset-vs-empty entry one line up: same pipeline, same class — **a credential check that passes must mean the credential is USABLE by the thing that will use it**, not merely present in some form.
- (2026-08-26) **A required check that never reports and a required check that FAILS look nothing alike — and only one of them is your problem.** During a GitHub Actions **major outage**, inbound traffic was throttled: `workflow_dispatch` still dispatched, but `push` and `pull_request` events were silently dropped. So a PR sat `BLOCKED` / *"no checks reported"* for ~40 minutes while `workflow_dispatch` runs on the same commit went **green** — because branch protection matches a check-run produced by the `pull_request` event, and a run from a different event is a different check-run that can never satisfy it. Every instinct says the ruleset is misconfigured (it had been added two days earlier, so it was the obvious suspect); the ruleset was correct and doing its job. The discriminator costs one request: `githubstatus.com/api/v2/components.json` — an infrastructure outage is a fact you can read, not a thing to infer from your own repo. **Check the platform's status before debugging the platform's config**, and when a gate is waiting rather than failing, ask *which producer* is supposed to report and whether it ever ran at all. Corollary worth keeping: a green run is not evidence for a gate unless it came from the event the gate names — re-reading a passing run as "CI is green, the rule is broken" is how a correct rule gets disabled during an outage.

- (2026-08-26) **`rename(2)` cannot replace a non-empty directory — "atomic swap of a tree" is two renames plus a restore path, or it is a plan for data loss.** ADR-0060's first draft said "atomic rename over the previous tree"; on Unix that call fails `ENOTEMPTY`, and the naive fix (`rm -rf` then rename) has a window where the user's only helper is gone. The shape that works: old → `.old-<nonce>`, partial → target, remove `.old`; and every START path checks for a stranded `.old-*` and puts it back. Test the crash-between-renames case explicitly. Caught by the fresh-context plan review, not by the author.
- (2026-08-26) **A signature binds BYTES, not identity — reusing one signing key across artifact families makes every artifact ever signed a valid substitute for every other.** With the updater key also signing helper archives, a compromised release account could serve `Snug.app.tar.gz` (or an older helper) as "the helper" and the signature would pass. The fix is not a second key; it is a CONTENT pin in the consumer (per-arch sha256 in `REQUIRED_HELPERS`) so the manifest's sums become display data. Same review; same day.
- (2026-08-26) **Two `tar`s live on a Mac and they disagree on flags — pin the binary path, not the name.** Homebrew's GNU tar shadows `/usr/bin/tar` (bsdtar) on PATH; `--uid 0` is bsdtar-only and GNU tar aborts. A pack script that says `tar` builds different archives on different machines, and the failure is a cryptic "unrecognized option" in someone else's release run. `execFileSync('/usr/bin/tar', …)`.
- (2026-08-26) **A unix socket path is capped at ~104 bytes and the error arrives from the helper, not the shell — keep smoke sockets short.** A Rosetta smoke "died" only because the scratch directory's path pushed the socket to 108 bytes. `mktemp -d` under `$TMPDIR` is short enough; a session scratchpad is not.

- (2026-08-26) **`backdrop-filter` (like `transform` and `filter`) turns an element into the CONTAINING BLOCK for its `position: fixed` descendants — a "full-screen" overlay rendered inside such a header is the size of the header.** The update sheet lived in the header nav; `.shell-header` blurs its backdrop; `inset: 0` therefore meant a 50 px box, and the card sat "chopped off at the top centre" exactly as the owner described. Any overlay opened from the header must `createPortal` to `<body>`, and the test to pin is "the dialog is not a descendant of the mount point", not a CSS-rule regex.

- (2026-08-26) **A background command that ends in `; echo "exit $?" >> log` reports exit 0 to the harness every time — the real verdict is in the log, and a "completed (exit code 0)" notification is not a green gate.** Two full root-gate runs this session were read as green from the notification while the log said `exit 1` (a node:test file vitest tried to collect; a `ProbeReport` literal the desktop test typecheck rejected). Read the last line of the log, or let the command's own exit propagate.
- (2026-08-26) **`vitest` collects any `*.test.mjs` it can see, `node --test` files included, and fails the package with "No test suite found" — name node:test files `*.node-test.mjs`.** `apps/whatsapp-sidecar` runs both runners; the same file cannot serve both.

- (2026-08-26) **A release script that BUILDS is not a "finish the staging step" script — re-running it without the credentials the first run had silently destroys the signed artifact.** A signed+notarized v0.1.2 DMG sat on disk with only the staging step missing; re-running `release-desktop.mjs` (to stage it) rebuilt from source with no Apple trio in the environment, took the `appleSigned = false` branch, and replaced the notarized bundle with an adhoc one — the warning scrolled past among build output and the run reported success ("staged … — UNSIGNED build"). Nothing was published and the build is reproducible, so the cost was ~9 minutes and an Apple round trip, but the shape is general: **before re-running any pipeline over existing artifacts, ask what it will overwrite and whether this invocation can reproduce what is already there.** The fix is a refusal, not a note: `refuseUnsignedRebuildOverSignedBuild` now `spctl`s the existing DMG and refuses an uncredentialed rebuild over `source=Notarized Developer ID`.

- (2026-08-26) **A CLI flag and its env var are the SAME argument — fixing the flag while leaving the variable set reproduces the identical conflict, one layer down.** `tauri signer sign` maps `-k` → `TAURI_SIGNING_PRIVATE_KEY` and `-f` → `TAURI_SIGNING_PRIVATE_KEY_PATH` and refuses the pair however it arrives. The release script materialises the CONTENTS form (the only one `tauri build` reads) and also passed `-f`: error. Dropping the flag left both env vars set: the same error, and a second failed release run. `--help` states the mapping in one line — read the tool's own contract before the first fix, not after the second. The child now runs with the PATH spelling deleted, proven by signing the real tarball, and pinned by a source-level test.
- (2026-08-26) **A success check must accept every wording the tool emits — `stapler staple` says "The staple and validate action worked!", `stapler validate` says "The validate action worked!".** The check matched only the first while the script calls the second, so a correctly signed, notarized and STAPLED DMG was refused by its own verification, after the notarization round trip. ## Security features that can lose data

- (2026-08-20) **A recovery path a session cannot reproduce is a recovery path that silently disappears.** The first `SNUGENC1` implementation rebuilt the container from "the secrets this session holds" on every write. A session unlocked with the passphrase alone cannot produce the Recovery Key, so every save quietly dropped the recovery slot — discoverable only on the day the user forgot their passphrase and reached for the key we told them to keep. Re-seal into the EXISTING container (same header, same slots, fresh nonce) instead of rebuilding it. Generally: when a secret grants access, ask what a session that holds only *one* of the accepted secrets will write back.
- (2026-08-20) **Keep "wrong secret" and "damaged file" distinguishable, or you will tell users a frightening lie.** Both fail the same AEAD unwrap, so the naive implementation reports one for the other. Telling someone their passphrase is wrong about a file that is actually damaged sends them hunting for a secret that was never the problem; telling them a file is damaged when they merely mistyped invites them to destroy it. An unkeyed header checksum separates the cases — it does not need to resist an attacker (AAD does that), it only needs to pick the honest sentence.
- (2026-08-21) **When a signature covers one artifact in a multi-artifact flow, say which one — the unsigned half is where the attack moves, and it is usually the half the user reads.** Tauri's updater verifies minisign over the downloaded ARTIFACT; `latest.json` — version, date, notes, and the asset URL — is trusted on TLS to the host alone. It is easy to write "updates are signed" and believe the channel is closed; what is actually closed is *binary substitution*, while *the update prompt* stays fully attacker-authorable by anyone who takes the publishing account. That inverts the design question from "can they install something" (no) to "what can they make the user do" (anything the dialog can say) — which is why the fetched notes render as plain text with no linkification, the version is syntax-gated, and the UX offers no button pointing anywhere but the flow itself. **Name the covered artifact in the ADR and the threat model, then design the UX for a hostile version of every field the signature does not reach.** Generalizes beyond updaters: any flow where a signed payload travels with an unsigned manifest, receipt, or description.
- (2026-08-21) **An erasure needs a WRITE TOMBSTONE: enumerate every writer that can run AFTER the wipe, silence them first, and test by invoking the real registered handler.** The Telepath deep delete wiped the helper's auth store — and the shell's reap is TERM-first precisely so the process-exit flush RUNS, which would have re-written the thread cache into the wiped directory (a `creds.update` from logout teardown re-writes `creds.json` the same way). The fix is a `forgotten` flag checked by every writer, set before the wipe. Two test traps the first cut fell into: letting timers elapse never reaches an `'exit'` handler — grab the listener `process.listeners('exit')` gained and CALL it — and a mutation check proved the debounce-only version vouched for nothing. Related but distinct from the 2026-08-18 flush-signal lesson (is the handler ever RUN?): this one is about a handler that runs and must now say nothing.
- (2026-08-21) **An equivalence test over ONE derived subset does not force the sibling hand-written table — a wizard-only route changes the app subset NOT AT ALL.** Adding `POST /session/forget` to the sidecar contract left the Rust/TS route equivalence green whether or not anyone touched the hand-written `WIZARD_ROUTES`, because that test compares only `APP_ROUTES` and the `/session/` prefix excludes the new route from the derived app subset — a forgotten Rust entry ships the feature dead at runtime with every suite green. When a contract has N restatements, each needs its OWN equivalence pin (the wizard table is now pinned equal to the FULL contract), plus one positive admission test per new entry.
- (2026-08-20) **Renaming a file the product looks for is a data-loss operation until proven otherwise.** The new name is absent, the open path takes its "no file yet" branch, and the user gets a pristine empty database over intact-but-unreferenced data — no crash, no error, no clue. Every derived name moves with it: the sync sidecar (orphaning it manufactured a phantom "divergence" whose obvious resolution discards local work) and the remote sync path (a fallback that reads the old path but writes the new one hands a foreign revision to a conditional write and wedges sync permanently). Read-and-adopt-forward; never rename, copy or delete the user's only copy.
- (2026-08-22) **A delivered video's container dimensions are not its content's dimensions — probe AND look before shipping.** The final "mobile" teaser arrived as portrait content pillarboxed inside a 1920×1080 landscape canvas (no rotation metadata, so `ffprobe` alone reads it as landscape); shipping it verbatim would have rendered black bars into the portrait slot with a wrong aspect-ratio hint. `cropdetect` across sampled frames found a stable `608:1080:656:0` crop. Two adjacent traps from the same session: a lossless remux of the desktop master (38 MB) is not a web encode — the website's 20 MB buildOutput guard rightly failed it, and re-encoding (crf 25, 8 MB) was the fix, never loosening the guard; and macOS screenshot filenames carry U+202F (narrow no-break space) before "AM/PM", so a path typed from `ls` output fails `cp` — glob instead.
