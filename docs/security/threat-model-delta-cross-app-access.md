# Threat-model delta — access between apps (one app reads another's tables under a user-granted access grant)

**Task:** TASK-20261010-cross-app-access · **ADR:** [0075](../decisions/0075-cross-app-data-access.md) · **Date:** 2026-10-10

Until this change every Snug app was an island: its tables lived under `app_<token>__*`,
were materialised into its own runtime database, and no frame let one app see another's rows
(ADR-0010; §5's "LLM-authored SQL cannot reach hub tables or other apps' data"). ADR-0075 adds
the ONE sanctioned crossing — a reader app reads a source app's tables, read-only, through an
**access grant** the user gives on host chrome the app cannot draw over, scoped to tables
with their columns frozen, timed, revocable from anywhere, and logged on the source's own
row. C1 and C2 are unchanged **in policy**: no credential enters a frame, a grant, a history
line or a result; the sandbox and the network ceiling are untouched; a read has no powers its
reader did not already hold over its own data. What follows are the new *channels* those
policies must survive: two published frames, app-authored SQL executed by the host, a host
record that travels with the file, a consent surface, and a second app's rows crossing into a
frame whose model will read them.

## What is new

| Surface | The threat | What holds |
|---|---|---|
| **Two published frames** (`snug:access-request` strict · `snug:access-response` tolerant; spec 1.1 Part VI) | A reader names a source, another reader or itself; a frame smuggles a credential, a control sequence or bidi text the consent sheet will render; an unknown key becomes a real-world effect; a stale or duplicate request gets two answers or none | The REQUEST is `strictObject` at every level with NO app-id seat (`packages/protocol/src/frames.ts`): the runner's binding `accessAppId` is HOST-assigned exactly like `dbNamespace` (`packages/runner/src/host.ts` — ONE `routeCapability` ladder shared with db and net), so the announce `appId` identifies no one and a call under another id is answered like an unknown grant. A purpose or hint word is one line of visible text — every control (Cc) and format (Cf) code point, the line/paragraph separators, U+034F and the blank fillers are refused, as is leading/trailing whitespace and a credential shape; the query's `sql` refuses bidi controls and C0/C1 other than tab/LF/CR. The RESPONSE is tolerant (nothing in it is an effect; a reserved `access: 'write'` seat is never a MAJOR bump). Both ride the 256 KiB class; an over-cap answer is a SMALL terminal `ACCESS_SIZE_EXCEEDED`, never silence; a malformed request with a recoverable `requestId` is answered `MALFORMED`, never hung. Pinned by `packages/protocol/src/__tests__/access.test.ts` ("an unknown key on every request op is MALFORMED", "refuses EVERY Unicode format (Cf) code point", "a credential-shaped purpose or hint word is refused at the frame too", "a query response of exactly MAX_FRAME_BYTES passes; one byte more is refused") and `packages/runner/src/__tests__/host-access.test.ts` ("routes to the handler with the HOST-assigned accessAppId — the announce appId "evil" is ignored", "drops an access-request bound to a stale instance", "refuses a duplicate in-flight access requestId", "an over-cap handler result becomes a SMALL terminal ACCESS_SIZE_EXCEEDED", "a pre-ready request carrying instanceId: null … is answered MALFORMED", "an access-RESPONSE reflected back by the app is dropped"); the runner stays value-blind — `net-value-blind.test.ts` refuses any import of `@snugprotocol/db`, `sql.js`, a Worker or the engine. |
| **App-authored SQL executed by the host** | A read reaches a table outside the grant through a view, a trigger, a CTE, a subquery, `sqlite_master`, an ATTACH, a PRAGMA or a second statement; a write; a `SELECT api_key AS harmless` carries a credential column out under a name no mask recognises; an unbounded `WITH RECURSIVE` hangs every shell (sql.js has no interrupt — the plan review's blocker); a wasm abort takes the live user db with it | The read runs on a **scoped scratch copy** in a **dedicated Web Worker with its own sql.js** (`apps/playground/src/access/scopedRead.worker.ts`; D10): the pure `scopedScratchRead` (`packages/db/src/scoped-read.ts`) DROPs every trigger first, then every view, then every table outside the grant, `snug_kv` and `sqlite_stat*`, VERIFIES the drops against `sqlite_master`, WITHHOLDS every credential-named column of a granted table (`'***'`, else NULL, else random; fail closed — D27), sets `PRAGMA query_only`, checks the recorded columns for drift, then runs the two guards in order — `isReadOnlySelect` (any PRAGMA/ATTACH/DETACH, multi-statement, CTE write) THEN `forbiddenStatementReason` — before ONE statement under a row cap (500) and a UTF-8 byte cap (192 KiB). A non-granted table is physically ABSENT ("no such table"), not name-guarded. The host side (`access/scopedRead.ts`) serialises reads through one worker, starts a 2 s wall clock per read, TERMINATES the worker when it fires and builds a fresh one next time; three consecutive timeouts suspend the grant `reader-misbehaved`. Rows cross as objects keyed by column name: any cell under a credential-named column, and any cell the value scan rejects, is `***`. Pinned by `packages/db/src/__tests__/scoped-read.test.ts` ("a table outside the grant is ABSENT", "every trigger is gone — including one ON the granted table whose body names a dropped table", "`PRAGMA query_only = 0; SELECT 1` is refused by the FIRST guard and never reaches the engine", "a write is refused and the input bytes are byte-identical afterwards", "a credential-named column of a granted table is never in scope — and an alias cannot carry its value out: it crosses as ***", "the byte cap is measured in UTF-8 BYTES"), `apps/playground/src/__tests__/scopedReadWorker.test.ts` ("a read that never answers is cut at the timeout … the worker TERMINATED, and the next read builds a fresh one", "a thrown worker (a wasm abort) answers failed, is terminated, and is replaced") and `accessHandler.test.ts` ("rows are scanned keyed by COLUMN NAME", "a read that outruns the wall clock → … three CONSECUTIVE timeouts suspend the grant"). |
| **The grant record** (`accessGrant:<id>`, a namespaced `snug_settings` row — normative for a hub implementing Part VI) | A grant reaches a hub from an imported `.snug`, a sync pull or a hand-edited row as readily as from the consent sheet; a planted grant names a credential column, carries a key in its purpose, or arms itself on open; a hub reads a row that says one thing and keys another; a grant survives the app it names | `accessGrantSchema` is `strictObject` at every level, byte-capped at 16 KiB, and a credential anywhere (the ONE walk, `record-guards.findRecordCredential`, shared with scheduling) is a parse refusal; a credential-named column is never in a scope (D23 — `security.isCredentialKeyName`, the scan's own rule); `status` and its reasons agree (D25); `expired` is derived, never stored; a session grant never persists. The accessors (`packages/db/src/userdb/access.ts`) parse BEFORE they write (a refused write leaves the file byte-identical), refuse a grant naming an app the file does not hold (D28), cap live grants at 100 and prune ended rows after 30 days. On an UNTRUSTED import every grant whose canonical intent differs from a local grant of the same id lands `suspended / imported` (a revoked grant stays revoked; an unparseable row is removed and reported — D29); a TRUSTED pull keeps every row; declines and mutes are dropped on an untrusted import. `deleteApp` sweeps every grant where the app is reader OR source, its history, its declines and its mute inside the cascade transaction. Pinned by `packages/protocol/src/__tests__/access.test.ts` ("an unknown key at the root, in scope, in a scope table, or in the duration is refused", "a credential-named column is NEVER in a scope", "exactly ACCESS_GRANT_MAX_BYTES passes; one byte more refuses"), `packages/db/src/userdb/__tests__/access.test.ts` ("parses BEFORE it writes: a credential-shaped purpose is ACCESS_INVALID and the file is byte-identical", "a grant naming an app the file does not hold is NOT_FOUND"), `userdb.test.ts` ("an UNTRUSTED file: a grant the hub has never seen lands suspended / imported", "a TRUSTED pull keeps every grant exactly as it is", "a grant row that does not parse is REMOVED and reported on an UNTRUSTED import") and `delete-app.test.ts` ("removes every grant where it is the reader / the source", "the sweeps run INSIDE the cascade transaction"). |
| **The history** (`accessLog:<sourceAppId>` — the source keeps it) | A reader floods the source's history so the real reads scroll out; a logged statement carries a key straddling the 200-character cut; an imported history lies about by whose act access began; a hidden (scheduled) reader writes lines nobody is watching | One bounded row per source (≤ 200 entries, ≤ 64 KiB; ≤ 1 MiB across sources): identical `(grantId, sql)` reads within 60 s coalesce; pruning takes `read` entries before any lifecycle kind and NEVER the latest `granted`/`revoked`/`suspended`/`released` entry of a grant the file still holds; the statement is walked WHOLE before the cut and the seat omitted on a hit; imported entries are tagged on an untrusted import; the `read` line is written BEFORE the rows leave (a history that refuses the line fails the read — D35); every `query` op counts against the per-app minute FIRST, and a hidden frame's `refused` line is written at most once per minute per grant (D32). Pinned by `packages/db/src/userdb/__tests__/access.test.ts` ("reads are pruned before any lifecycle entry", "NEVER prunes the most recent granted / revoked / suspended / released entry of a grant", "coalesces an identical (grantId, sql) read within 60 s") and `accessHandler.test.ts` ("the history keeps the statement's first 200 characters — and OMITS the seat when the FULL statement is credential-shaped", "a hidden reader cannot wipe the source's history: a prior read survives 250 refused calls", "a HIDDEN frame is rate-limited like any other"). |
| **The ask and the consent surface** (the strip, then the sheet) | An app opens a modal, or asks on every load until the user gives in; a reader re-announces to mint a fresh ask or limiter slot; the sheet names the reader by text the reader chose; a purpose spoofs the sheet's own words; a tap lands on *allow* before the sheet was seen (tap-jacking); the sheet opens over a pending network or open-url confirm; a dead frame's ask blocks the next frame of the same app | An app's `request` renders a STRIP (role=status, never a modal — ADR-0074 §4's ladder, `state/appAsk.ts` shared with the schedule suggestion); limits key on the host-assigned id + the frame GENERATION (one pending per generation; the 10 s window per APP, so a remount or re-announce cannot mint a slot — D31); declines by semantic hash (sorted hints + `renew`, the purpose excluded, lists normalised); mutes per reader and per browser. *Review*, a user act on host chrome, opens the sheet (a `ConfirmOverlay` the iframe cannot draw over); the reader is named by its LIBRARY row and tile plus a provenance line the host derives from `install_source` (D11), name collisions said; the purpose is quoted in a bidi-isolated block under *says:*; the primary arms only after 600 ms of visibility and ignores an activation whose `pointerdown` preceded the render; initial focus is *not now*; Escape and the backdrop are *not now*; the sheet yields to a pending net/open-url confirm. An ask whose frame ended while the candidates were gathered parks nothing and is answered *not now* (D33); a (re-)announce dismisses the previous instance's ask. A hidden frame's ask is `ACCESS_UNATTENDED` — nothing recorded. Pinned by `accessHandler.test.ts` ("a reader that RE-ANNOUNCES … is rate-limited by APP — a new generation cannot reset it", "a recorded decline for the ask's semantic hash → ACCESS_DECLINED and NO strip", "a frame retract WHILE the candidates are gathered parks NOTHING", "parks ONE pending named by the LIBRARY row with the host-derived provenance line") and the W3b sheet suites (the arming delay with its mutation check, the isolated quote, the yield rule). |
| **Discovery** | A reader learns the user's app inventory, or probes it with hints; a count-only answer leaks the fact that a source exists | The ranking (`access/relevance.ts`) is deterministic and host-side, shown to the USER in the sheet; the app learns only the grant it was given (the source's display name and icon, the granted tables with their columns, the duration) and otherwise one of two facts: `ACCESS_NO_SOURCES` after a user-gesture `request`, or nothing. Apps with no shareable table, apps over the 16 MiB export cap and apps holding a WhatsApp fact are excluded and said in one footer sentence. Pinned by `accessRelevance.test.ts` and `accessHandler.test.ts` ("NO eligible source → ACCESS_NO_SOURCES: no strip, nothing recorded"). |
| **"Where this can go"** | The sheet says "stays on this device" under a list of hosts the reader can reach; it names a brain the transport will not route to; it omits the link path | `egressFor` (`access/egress.ts`) composes the brain exactly as `createAppTransport` routes it (platform pin → mode → the per-app pin under the same guard → key presence read from the FILE's secret rows → `adapterKindFor`), every APPROVED connection by provider and host, every DECLARED one as *not connected yet*, a revoked one not at all, the sidecar's symbolic host as the helper by name, ALWAYS the open-url line for an owned reader, the away line when unattended, and closes "the copy is made here, on this device; <Source> keeps a history of every read". Pinned by `accessEgress.test.ts` ("a STALE key-presence store never names a keyed brain the transport will not route to", "ALWAYS carries the open-url line for an owned reader", "never says the data stays on this device under a list of places it can go"). |
| **Revocation, drift, updates, imports** | A revoke that takes effect "soon"; a reader updated by a share link or an agent hand-in keeps reading under consent given to older code (R-39's lineage shape); a source that gains a column the user never saw; a source that gains a WhatsApp fact; a session grant that outlives its frame | *Stop* anywhere (the source's sheet, the reader's, the strip's undo, Settings) or `release` from the reader takes effect on the NEXT query — a stop that lands while a read is in flight wins and no rows leave (D35) — and rings the reader `host-event 'access-changed' { grantId }` (ids only, R7). A shared or agent update of the reader suspends its grants `reader-updated` through the ONE `onAppVersionChanged` fan-out that also pauses schedules (E8's rule — the user's own edit and a starter update change nothing; a source scan refuses any direct call); a column change on a granted table suspends `source-changed`; a WhatsApp fact on the source suspends `source-restricted` at every query and at the connection-approve/import seam; a session grant belongs to the visible frame of its generation and dies with it, is never readable by the hidden frame (D30), and every memory grant, limiter and cached copy is dropped at the delete seam and every file-swap seam. Pinned by `accessDrift.test.ts` ("a shared/agent update of the READER pauses every live access it holds", "no module but state/appVersionChanged.ts calls pauseSchedulesForAppVersion or suspendAccessForAppVersion", "every resetThreadSessions() in the tree is paired with resetAccessSession()"), `accessGrants.test.ts` ("a session grant dies when its reader's frame closes") and `accessHandler.test.ts` ("a hidden frame NEVER reads a session grant", "a source that holds a WhatsApp fact at query time suspends the grant source-restricted", "a change to a granted table's columns suspends the grant source-changed"). |
| **Every shell, one source** | A host advertises `access` where no Worker can be constructed, so the first read hangs or fails late | A host offers only what it can run (ADR-0072 §4): the kit's boot probes a blob Worker once (`canConstructWorker`) and composes `access: false` where it cannot; the runner advertises `host-ready.capabilities.access` only with a handler; the SDK answers a non-retryable `HOST_ERROR` on a host that does not advertise it; the playground and the desktop inherit the engine through the one source. Pinned by `apps/host/src/__tests__/platform-host.test.ts`, `hostCapabilitiesFactory.test.ts`, `host-lifecycle.test.ts` and the SDK's `access.test.ts`. |

## What is NOT changed

- C1: no credential crosses the bridge in either direction — a credential-shaped purpose, hint, statement or history seat is a parse refusal; a credential-named column is never in a scope and is withheld on the copy; a credential-shaped cell is masked.
- C2: the sandbox flags and the CSP are byte-identical; the read is in the host page's own engine (a Worker of the host, never of the app); the app↔host exchange is in-page `postMessage` routed by `event.source` — there is no network hop between the two apps to intercept.
- Persistence rides the file's existing custody line (R-3, R-40); the import path is where a planted grant is disarmed, exactly as a planted connection or schedule is.
- Writes are deferred by name (ADR-0075 §10): `access` is a one-member enum and the response's `write` seat is reserved, not implemented.

## Residual risks (recorded, not fixed)

- **R-71 — The reader's model sees what it reads.** Rows cross into a frame whose model will read them; a source's cell can carry an instruction the reader's model follows (R-8's class, now from a second app's data). *Bounded by:* the user chose the source and the tables with the sheet in front of them; every read is logged on the source; the mask and the withheld columns keep credentials out of the rows; the reader's own net ceiling and the open-url confirm bound where an instruction can send anything.
- **R-72 — Rows can leave through the reader's own approved paths.** A reader with an approved connection can carry rows to that host in a GET, or into a link it asks the user to open. *Bounded by:* both paths are named in the sheet under *where <Reader> can send what it reads* (the connection by provider and host; the link line always); a mutating call still meets the confirm gate; the link still meets the open-url confirm with the full address.
- **R-73 — The user's own edits keep the grant.** A builder edit of the reader (`own`) does not suspend its grants (E8's rule — the user is the one who changed the app), so code the user wrote after consenting reads under that consent. *Bounded by:* the user's own act; a shared or agent update DOES suspend; the history shows every read.
- **R-74 — Two instances of the source.** A read copies the source's live runtime (an unflushed write counts), so a read can observe mid-write state of a source that is open or running a scheduled job (R-70's class). *Bounded by:* a read is a copy — it can never block or corrupt the source; the row count the sheet shows is of the same bytes.
- **R-75 — A session grant dies with a reload, a persisted grant survives a trusted sync.** A `day`/`week`/`always` grant is a row in the file and rides a TRUSTED pull to another device as given, where the same reader may read under it. *Bounded by:* trusted means the user's own sync origin; an UNTRUSTED import disarms every grant not intent-identical to a local one; every device shows the grant in Settings with *stop*.
- **R-76 — Names and sizes of dropped objects can leak, never rows.** The granted table's own DDL may name a non-granted table through a `REFERENCES` clause (readable through `pragma_foreign_key_list`); `pragma_freelist_count` reveals how many pages the dropped objects held; `sqlite_sequence` names dropped AUTOINCREMENT tables. *Bounded by:* every reach INTO a dropped table still fails "no such table" — the residual is a name or a size from the source's own constraint text, never content; `sqlite_sequence` is the one-line belt queued for W6.
- **R-77 — The provenance line trusts `install_source`.** The sheet reads an app with no `install_source` as *built here*, and an untrusted import carries that column verbatim, so a planted app can wear the most trusted provenance. *Bounded by:* the reader is still named by its LIBRARY row (never the announce); the provenance line is one line of several the user sees (the tables, the egress, the history); no app-level "arrived with an imported file" marker exists yet — it is the named follow-up.
- **R-78 — The hidden frame's generation.** The scheduler's hidden frame has no generation and therefore never uses a session grant (D30); a persisted grant ticked *also while I'm away* is readable by a scheduled run of the reader with nobody watching. *Bounded by:* the opt-in is a separate, default-off checkbox whose sentence names the condition; every such read is logged *while you were away*; the hidden frame runs under the refusing net gate, so what it reads cannot be sent anywhere a confirm would have gated.
