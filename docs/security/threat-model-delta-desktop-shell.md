# Threat-model delta — Desktop shell (Tauri 2)

- **Task:** TASK-20260812-desktop-hub-scaffold · **ADR:** 0021 · **Status:** shipped with the desktop scaffold (draft until task close)
- **Scope:** what the native shell ADDS to the attack surface relative to the browser hub, what defends each addition, and what is **accepted and not mitigated**.

## 1. Posture change

The hub client gains a native process boundary: a Rust host with filesystem access, a native HTTP client, an OS-level loopback listener, and an IPC bridge into the webview. C1 (credential custody) and C2 (app-iframe sandbox) are unchanged **in policy**; every addition below is a new *channel* those policies must survive, not a new policy.

## 2. New surfaces and their defenses

| Surface | What an attacker could try | Defense |
|---|---|---|
| **Tauri IPC bridge** (`invoke`: user-file read/write, opened-file read, export, oauth start/cancel) | A hostile micro app inside the sandboxed iframe invokes `read_user_file` → whole `user.sqlite` incl. `snug_secrets` (C1 break), or native fetch (C2 exfil) | Capabilities scoped to the **main window only** (`capabilities/main.json`); the in-shell hard gate (AC7) asserts IPC is unreachable-or-refused **from inside a sandboxed srcdoc iframe** as an enforcement-signal check on every gated platform. **Measured on macOS (gate run, 2026-08-12):** WKWebView exposes the raw `webkit.messageHandlers.ipc` transport to all frames (wry registers it process-wide), but `__TAURI_INTERNALS__`/`__TAURI__` — carrying the invoke API and the runtime `Tauri-Invoke-Key` — are absent in subframes, and a keyless `read_user_file` invoke posted through the raw transport **does not execute** (verified against tauri 2.11.5's `on_message` key check; the gate asserts absence-of-effect, a fired callback = FAIL). IPC-in-subframes with no off-switch remains defined as structural breakage → Electron fallback (ADR-0021 §8). |
| **Loopback OAuth listener** (`127.0.0.1:41420` fixed / ephemeral) | (a) Local process or drive-by page fires forged `code`/`state` at the callback; (b) local process races the REAL redirect, injecting its own authorization code under the **valid** state | (a) dies at HMAC state verify / held `expectedFlowId` / nonce single-use — unchanged guards. (b) is defeated only by provider-side **PKCE challenge binding**, which is why `pkce:false` + loopback posture is refused structurally at registry-test time (ADR-0021 §2); such providers get non-loopback postures (GitHub OAuth-app → device-flow, refused-until-built). |
| **Native fetch (reqwest, CORS-free)** | Widening egress beyond the browser's | **Corrected 2026-10-09 (TASK-20261008-p0-clearance W3).** The connected-fetch executor is NOT the only host-side caller of the platform fetch: OAuth token/refresh/revoke POSTs (the wizard's `serviceFetchDep` and the executor's `oauthFor`), the SimpleFIN token claim, the local-model adapter, BYOK and discovery, the share relay, release notes and the Ollama probe all call `fetchImpl` outside connected-fetch's scheme and host-class gates (4/5). For connected-fetch traffic the Tauri scope is a belt behind the frozen per-connection ceiling; **for those other callers it is the port and loopback limit**, so it is stated and tested as policy. **The scope, stated exactly** (`capabilities/main.json`; behaviour pinned by `src-tauri/src/http_scope.rs`, which runs the plugin's own matcher over the file, and by the in-shell gate's `net-scope-*` checks against the real plugin; the strings by `src/__tests__/netTransportCapability.test.ts`): **allow** `https://*:*` (any host, any port — R-14: a port is not host identity; an approved https host on :8123/:5001 failed on desktop while working on the web); `http://` on the three RFC-1918 ranges as **exact-octet regex hosts** (10/8, 172.16/12, 192.168/16 — equal, address for address over a swept sample, to `lanfetch::is_rfc1918_ipv4_literal`); and exactly two single-purpose loopback ports — `127.0.0.1:11434` (Ollama probe, §3.5) and `127.0.0.1:43120` (debug gate net-stub; inert in release, where the host remap that targets it does not exist). **deny** (wins over allow): https to `localhost` and its subdomains, to 127/8, to 0/8, and to every IPv6 literal, on every port. **The dead window:** from the first shell (2026-08-12) to this fix the http ranges were written `http://192.168.*.*:*` & co. and matched NOTHING — urlpattern 0.3 IPv4-parses fixed hostname digits, so the entry compiled to the host `192.0.0.168*.*` — so the effective ceiling was TIGHTER than documented (no exposure; the plain-http LAN rung simply never worked), and `https://**` admitted only :443. Blanket `http://localhost:*` / `http://127.0.0.1:*` stay absent — connected-fetch refuses loopback outright, so nothing legitimate needs them. |
| **Native fetch: redirect following** | An open redirect on an APPROVED host bounces a credential-bearing request to an attacker host; reqwest strips only `Authorization`/`Cookie`/`Proxy-Authorization` across hosts, so **injected** custom headers (`X-API-Key`, HMAC signature seats) would be forwarded, and the executor would see only the final 200 | The desktop `fetchImpl` passes **`maxRedirections: 0`** on every call. This is load-bearing, not defence-in-depth: `@tauri-apps/plugin-http`'s JS shim reads only `maxRedirections`/`connectTimeout`/`proxy`/`danger` from `init` and **never reads `init.redirect`**, so connected-fetch gate 9's `redirect: 'manual'` and oauth-service `postForm`'s B2 guard ("a credential POST never follows a redirect") were both silently inert on this transport; Rust installs `Policy::none()` only for `maxRedirections == Some(0)`, otherwise reqwest's default `Policy::limited(10)` follows up to ten hops. Pinned by `src/__tests__/netTransport.test.ts` on every outbound path (red-proven against the old wiring); a plugin upgrade that begins honouring `init.redirect` must re-prove it there before the field is dropped. |
| **LAN scheme widening** (`transportPolicy.allowHttpForPrivateHosts`, desktop only) | SSRF into the LAN; using Snug as a pivot | Admits **only** RFC-1918 IPv4 **literals** (octet-parsed; 172.16/12 boundary-tested) that the user explicitly approved into the frozen ceiling via the wizard's strong review. Loopback, link-local, `localhost`, `.local`/`.internal`, DNS names, IPv6 all stay refused regardless of policy. Approved private literals are reachable over https as well (host-class-based; Hue v2 speaks https). Browser profile byte-identical to before. **Live on desktop only since 2026-10-09** (TASK-20261008-p0-clearance W3): the plugin scope's http entries never matched before (see *Native fetch*), so this rung's plain-http leg was dead in every release up to v0.1.3 and reaches users with the next desktop release. |
| **Opened-file path** (`.snug` double-click, second-instance argv) | Argv injection (flag-/URL-shaped), tricking the shell into reading arbitrary files, silent import of a hostile DB | Single-use allowlist admits only *existing files* with `.snug`/`.sqlite` extension that arrived via a real OS open event; `read_opened_file` serves an allowlisted path once; there is **no generic path-read command**. The import itself requires an explicit confirm dialog and routes through `importUserFile`, arming the F15 endpoint-confirm guard (foreign executable config never runs unconfirmed). |
| **Export path** | Webview writes to arbitrary paths | Save dialog and write live in ONE Rust command; the webview supplies bytes + a sanitized *suggested name* only. |
| **User-file commands** | Path traversal via `name` | Bare-filename charset check (no separators, no dotfiles, ≤128 chars); all writes temp+fsync+rename+**dir-fsync** inside `~/Snug`. The atomicity is now pinned by *mechanism*, not outcome: the write is factored so a test can inject a failure in the crash window (tmp written and fsynced, target untouched) and assert the target still serves the OLD complete bytes — previously, replacing the whole sequence with a plain `fs::write` kept every test green. |
| **`~/Snug` litter after a kill-mid-write** | Orphaned `user.sqlite.tmp-XXXXXXXX` files accumulated forever — one full-size copy of the database per crash, with no collector — and the rename itself was not durable across a power cut | Best-effort sweep of `*.tmp-*` older than 10 minutes runs on the write path (the only code that creates them, so no boot-ordering dependency); the age floor means a concurrent in-flight write is never swept. `fsync` of the containing directory after the rename makes the rename durable on unix (no-op on Windows; NTFS journals it). Both tested, including the negative — a fresh tmp survives the sweep, and real files/`.corrupt-*.bak` quarantines are never candidates. |
| **`~/Snug` location on Windows** | An environment-set `HOME` (git-bash, MSYS2, Cygwin, most CI images set it; Windows itself does not) silently relocates `~/Snug` and boots a **fresh empty database over a user who has real data** in `%USERPROFILE%\Snug` — data loss presenting as "the app forgot everything" | `USERPROFILE` takes precedence on Windows, `HOME` on unix, each falling back to the other; neither ever defaults to CWD or `/`. The precedence is a pure function taking the platform as a **parameter**, so both orderings are exercised by the suite on every host — a `#[cfg(windows)]` branch would be uncompiled and untested on the macOS/Linux legs, which is exactly how this shipped. |
| **crypto.subtle fallback** (installed only when the webview lacks WebCrypto) | A weaker or divergent HMAC/SHA implementation weakens state signing | Pure-JS SHA-256/HMAC pinned byte-for-byte against real WebCrypto vectors incl. RFC 4231; installed only on desktop entry, never web; `getRandomValues` (nonce/verifier entropy) is context-independent and never polyfilled. |
| **Gate-mode host remap** (debug builds) | A strictness knob shipping to users | Compiled under `cfg(debug_assertions)` / DEV-only bundles, active only with `SNUG_SHELL_GATE=1` read once at start; the gate itself asserts the remap is inert without the env and absent from release artifacts. |

## 3. Accepted residuals (not mitigated, by decision)

1. **Authorize-URL visibility to local processes.** The system browser is opened with the URL (incl. `state`) in argv/`ps`-visible form on some platforms. `state` is not a secret against the PKCE-bound code exchange; the residual is local-process flow *disruption*, not credential theft. Accepted — same class as a local process killing the listener.
2. **DNS rebinding for public hostnames.** The LAN policy keys on IP literals, so a public DNS name rebinding to a private IP mid-flight is refused as a *name* only by the existing browser-edition guard; native pin-resolution (resolve-then-connect-by-IP) is deferred — queued in next-steps. The frozen host ceiling still bounds *which names* are reachable at all.
3. **Loopback port squatting.** A local process may pre-bind 41420, DoS-ing fixed-port sign-ins. Surfaced as an honest wizard error naming the port. A squatter receiving the redirect still lacks the PKCE verifier and the HMAC key; accepted as availability-only.
4. **`~/Snug/user.snug` is a plaintext file BY DEFAULT** readable by any process running as the user — exactly the custody ADR-0014 promises (the USER owns the file; OS user-account boundary is the perimeter). **Since 2026-08-20 the user may opt into whole-file passphrase encryption (ADR-0043)**, after which the bytes at rest are AES-256-GCM ciphertext and this residual applies only to unprotected files; it never covers an already-unlocked running session. Full-disk-encryption and OS keychain wrapping remain out of scope pre-1.0 (KeyProvider/KMS is the roadmap's host-blindness track).
5. **Ollama probe** talks plaintext to `127.0.0.1:11434` outside the connected-fetch guards (it is an LLM adapter surface, not an app connection). Model names are the only data read.

## 4. Verification record

- Registry structural tests: posture presence, loopback⇒PKCE refusal (red-proven), posture-union runtime assertion.
- Transport core: 22 tests (recorded-URI identity across service calls and listener teardown, single-flight, TTL, forged/malformed-state non-delivery, fixed-port bind-failure honesty).
- LAN policy: 17 tests incl. octet boundaries (172.15/172.16/172.31/172.32), policy-absent regression, probe carry-through.
- File backend: 12 tests (absence vs corruption vs rejection; both magics; sidecar round-trip) + **24 Rust tests** (traversal refusal, atomic overwrite, no tmp survivors, injected-crash-in-the-rename-window, partial tmp never shadows the target, production path proven to stage through a tmp, stale-tmp sweep with the fresh-tmp negative, dir-fsync-after-rename, HOME/USERPROFILE precedence in both directions) + single-use allowlist test. The atomicity, sweep and precedence tests are **mutation-proven**: plain-`fs::write`, tmp-skip, sweep-removal, age-check-removal, dir-fsync-removal and HOME-first mutants each go red.
- Desktop transport: `netTransport.test.ts` (7) pins `maxRedirections: 0` on every `fetchImpl` path incl. no-init and remapped-URL calls, plus init non-mutation; `netTransportCapability.test.ts` (7) pins the HTTP capability belt. Both red-proven against the pre-fix wiring.
- In-shell hard gate (AC7/AC8): **macOS GREEN 2026-08-12** — 24/24 checks (env probes; 14/14 `BROWSER_CSP_CHECKS` enforced by WKWebView incl. the network positive control; 4 IPC checks incl. the keyless-invoke absence-of-effect assertion; remap armed/inert/absent-from-release trio) + wizard journey 1 complete inside the shell (HMAC-signed headers observed at the stub, scrubbed body in the app, no secret material in the DOM). `tauri://localhost` measured as a secure context on this wry version (`isSecureContext: true`, native `crypto.subtle`) — the pure-JS subtle fallback ships as defense-in-depth and was not needed. **Windows/WebView2 leg authored, pending first CI run** — desktop is not "first-class" until it is green (roadmap A6 vs L6).
