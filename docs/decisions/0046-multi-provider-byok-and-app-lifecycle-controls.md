# 0046 — Multi-provider BYOK defaults, per-app provider pins, and the app-lifecycle controls (rename, version delete, deep delete)

- **Status:** accepted (owner pre-approved run-through, 2026-08-21 interview)
- **Date:** 2026-08-21
- **Task:** TASK-20260821-ui-polish

## Context

BYOK held keys per provider (`byok:anthropic` / `byok:openai` were already separate `snug_secrets` rows) but the UI and routing admitted only ONE active provider at a time, with one global `model` setting behind it (ADR-0036 kept per-app MODEL pins on top of that single provider). Separately, three lifecycle gaps stood: an installed app could not be renamed (and every run's announce overwrote `display_name` anyway), a stored version could not be deleted, and deleting Telepath erased the user-DB side (ADR-0040's cascade) while the WhatsApp helper's on-disk session — keys, minted token, thread cache under `~/Snug` — survived the app that justified it.

## Decision

1. **The default provider RESOLVES; only choices are stored.** `providerStore` stays the store every consumer reads, but it now carries `resolveDefaultProvider()`: an explicit `providerChoice` settings row (absence = derived) → anthropic-if-keyed → openai-if-keyed → the demo brain. An explicit choice is honored UNCONDITIONALLY, keys or not — silently re-routing a stale choice to a different provider would send the user's data somewhere they did not pick. The legacy `provider` row adopts forward into `providerChoice` once at hydrate and is kept written as a synced twin (old builds on a roaming file still read it); neither legacy row is ever deleted.
2. **Default models are per provider** (`providerModel:<provider>` settings rows; absence = the adapter's own default, live). The legacy byok `model` row adopts into the resolved provider's row once; local and subscription keep reading the global `model` (an Ollama pick is not a per-provider fact). The standalone Settings "model" card is retired into its mode's section.
3. **A pin is a PIN: per-app picks store provider AND model** (`appProvider:<appId>` beside ADR-0036's `appModel:<appId>`, same namespaced-key contract, both deleteApp-swept). Inheriting stays an ABSENCE — clearing deletes both rows. Resolution is per SEND at every adapter-construction site (transport, builder, inference ladder), because the transports memoize and a captured provider freezes a mid-session pin. A pin whose key is gone still routes (and fails visibly); the selector marks it "key missing" rather than hiding it.
4. **The build page carries the selector** — the attached app's own control when the thread has one; a session-scoped pending pick otherwise, transferred to the new app as its pin on install.
5. **Rename is a user fact with a marker.** `display_name` stays the one name everywhere; `appRenamed:<appId>` marks that the USER set it, and the announce merge (`recordAppMeta`) respects the marker at both altitudes — the synchronous store and the async DB write, which re-checks against the DB because an announce can race hydration. Uniqueness (trimmed, case-insensitive, self allowed) is enforced at the library layer; the DB deliberately gains no constraint.
6. **`deleteAppVersion` guards in order** unknown → `VERSION_PINNED` → `VERSION_CURRENT`. Every pinned factory version is protected (owner decision: ALL pins, not the newest — reset-to-factory and the ADR-0045 vouch chain both address pins), and so is the running version. No VACUUM per row delete; the next deleteApp/export reclaim covers it.
7. **Deleting the LAST sidecar app is a full device unlink** (owner decision). The user-DB cascade runs first and can never be failed by the helper path. Then: `POST /session/forget` (a new wizard-only contract route — nonce-ONLY at the helper router, because the `/session/` branch otherwise accepts the app token and forget is destructive) performs a best-effort Baileys logout and erases the auth store behind a **persist tombstone** (the TERM-first exit flush and `creds.update` writers are silenced first — without it the reap's own clean shutdown re-writes the thread cache into the wiped directory); then `sidecarCtl('forget')` stops the helper and removes the session directory in Rust — the disk backstop for a helper that cannot run. A sidecar fact on ANY other app vetoes the unlink (the same orphanhood rule as ADR-0040's directory wipe). Residual, recorded: if the helper cannot start, the phone keeps a dead companion entry until removed there; the disk is still wiped.

## Consequences

- No schema bump, no migration, no spec-changelog: every new fact rides `snug_settings` namespaced keys (`app-settings-keys.ts` is the one contract) or the internal-draft sidecar contract. The price, per the 2026-08-18 lesson, is cascade entries — `appProvider:` and `appRenamed:` joined the deleteApp sweep, mutation-checked.
- ADR-0036's per-app MODEL half stands; its "global model" fallback is superseded by the per-provider defaults in byok mode (this ADR), and its resolution function grew a provider sibling.
- The Rust `WIZARD_ROUTES` table is now pinned equal to the FULL TS contract by a second equivalence test — the app-table test alone never forced it, which is how a wizard-only route could ship dead.
