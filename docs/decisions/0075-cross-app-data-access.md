## Context

A Snug app's data is physically its own: its tables live under `app_<token>__*`, are materialised into its own runtime database, and the runner hands a frame only the `dbNamespace` the HOST assigned (ADR-0010). Nothing on the wire lets one app read another's rows, and the threat model leans on that (C2; §5 "LLM-authored SQL cannot reach hub tables or other apps' data"). It is also a product gap the owner named on 2026-10-10: the user's own apps cannot cooperate — a budget app cannot see the ledger, a planner cannot see the pantry — and the only workaround is to rebuild one app inside the other.

The owner asked for cross-app data sharing where **the user is in full control and has complete transparency**: explicit permission, one-time or timed or indefinite, revocable at any moment; the user told what is shared and **where the data could reach**; frictionless after consent until expiry; **logs kept by the app giving access**; one-to-many and either direction; **auto-discovery** of relevant apps, with permission; a UI simpler than Apple's permission sheets yet more transparent, native to the runner, shipped in every shell from one source; and the spec bumped with the whitepaper to follow.

Read from the code (and probed, where the plan review demanded it):

- **The pattern for a governed capability exists three times** — db, net, open-url: a frame pair, a host-assigned binding on the runner (`dbNamespace`, `netAppId`), a value-blind router, a `host-ready` flag, one host-side handler with authority, a confirm surface the iframe cannot draw over. Access is the fourth instance.
- **Reads on an isolated copy exist** (`scratchRun`, ADR-0019) — but synchronously, on the main thread, through a sql.js build with **no interrupt** (probed: `Database.prototype` exposes none; an unbounded `WITH RECURSIVE` aggregate never returns). Today only the user's own builder reaches it; handing it to app code the user may not have written is a hang every shell would share.
- **Consent-then-freeze exists** (connections, ADR-0017) and **an app that asks at runtime exists, bounded** (`scheduleRequest.ts`, ADR-0074 §4: a strip, never a modal; one pending per frame generation; a rate limit keyed on the host-assigned id; declines by semantic hash; mutes). The announce `displayName` is written into the app row (`appMeta.ts`), so a reader's name is text the reader chose.
- **An update pauses what trusted the old code** (`pauseSchedulesForAppVersion`, called from the shared-install and hand-in paths; `noteAppVersion` has no production caller; the starter path has no hook).
- **Host state is settings rows** (§8.1): a new `snug_` table is a v7 stamp that strands every fielded hub (ADR-0063/0074). But §8.1 also calls such rows "host-internal machinery … nothing required of a conforming host" — which cannot hold for a record whose import reconciliation IS the security property.
- **The spec is at 1.0; additive changes bump the minor.** Adding frames changes `schemas/`, §2, Appendix C, the website's generated pages and the whitepaper's frame count — and the in-repo draft carries three items the spec repo never received (§12.14 app bundles, the `shared` provenance, the §8.1 scheduling keys).

## Decision

1. **Access is protocol — a fourth governed capability.** Two published frames: `snug:access-request` (**strict** — it carries SQL and a release act; `op ∈ request | query | list | release`) and `snug:access-response` (**tolerant**, the db-response shape — nothing in it becomes a real-world effect, and a strict host→app frame would turn every reserved growth seat into a MAJOR bump because the SDK drops what `parseFrame` rejects). Both ride the 256 KiB class; `host-ready.capabilities.access?` is an optional flag. The runner routes a request to a host-assigned `AccessHandler` bound by `accessAppId` (≡ `dbNamespace`'s discipline) through the ONE `routeCapability` helper db and net now share, and stays value-blind. Spec **1.0 → 1.1**: §2's inventory becomes fifteen; a new **Part VI — Access between apps** (§21 the model · §22 the access-grant record · §23 the frames · §24 host obligations) is inserted after Part V and **Conformance becomes Part VII**; Appendix A gains the `ACCESS_*` codes, Appendix B the constants, Appendix C sixteen schema files with the access pair's precise exception stated (the exported schemas are complete for the frames; §24's obligations bind the host, not the parser). The spec always says *access grant* (Part III's *connection grant* is a different record). The whitepaper becomes edition 4 and its five absolute isolation claims gain the clause "without a user-granted, logged access grant".

2. **An access grant is read-only, per table with frozen columns, user-written, and normative for a hub that implements Part VI.** `AccessGrant = { id (uuid v4), readerAppId, sourceAppId, scope: { tables: [{ name, columns }] }, access: 'read', purpose, duration, unattended, status, suspendedReason?, provenance, readerVersion, timestamps, counters }`, persisted as `accessGrant:<id>` in `snug_settings` (≤ 100 live per file, ≤ 16 KiB, strict at every level, a credential-shaped purpose a parse refusal). Only the user's act on a host surface writes one. A hub implementing Part VI MUST persist under that key, MUST reconcile imported grants (suspend unless intent-identical to a local grant), MUST sweep on app delete — §8.1 gains the carve-out. `access` is a one-member enum: writes are deferred (§10). Columns are disclosed AND frozen: a granted table whose columns later differ suspends the grant (`source-changed`) until the user looks again; credential-named columns are never shared and always masked. `snug_kv` is never in scope.

3. **Four durations; the default never touches the file.** *While Budget is open* — the DEFAULT — is a MEMORY grant bound to the reader's frame generation (host-owned; a re-announce cannot mint a fresh one); *for a day*, *for a week* and *until I stop it* persist. *Also while I'm away* is a separate opt-in (`unattended`, default off): a hidden scheduled frame may `query` only under it, and its `request` is always answered `ACCESS_UNATTENDED` (retryable, nothing recorded). `expired` is derived at read. Every read is logged whatever the duration.

4. **A running app asks through a strip, never a modal; the sheet opens on the user's act.** `request` renders `.connection-note.is-strip` above the reader's frame — *review* · *not now* · *stop asking* — the fourth instance of ADR-0074 §4's ladder, and the promise is held until the user acts (a retract or re-announce dismisses it with nothing recorded). *Review*, a user act on host chrome, opens the consent sheet. Three distinct negative acts: *not now* records nothing (`ACCESS_DECLINED`, retryable); *don't allow* records the ask's semantic hash (sorted hint tables, sorted hint words, `renew` — the purpose is free text and is excluded); *stop asking* mutes the reader. Declines are listed in the reader's sheet with *allow…*. A reader with no eligible source gets `ACCESS_NO_SOURCES` and no strip. Limits key on the host-assigned app id and frame generation: one pending per generation, one `request` per 10 s, 60 `query` a minute.

5. **Discovery is host-ranked and shown to the user, never to the app.** The sheet ranks the user's apps by a deterministic match over table names, column names, app name and description — no brain call — matched candidates first, the rest behind *more apps…*, unusable apps (no tables, over the size cap, holding a WhatsApp fact) collapsed into one sentence; tables carry column chips and row counts; matched tables pre-selected. The reader is named by its **library row and tile plus a provenance line the host derives** (*built here · v12* / *installed from a share link on 3 Oct · not built by you* / *handed in by your agent* / *a starter from Snug*; name collisions are said), and its purpose is quoted under *Budget says:* in a bidi-isolated block — the announce never names anyone. The app learns only the grant: the source's display name and icon, the granted tables with their columns, the duration and expiry — never the inventory, never a library id.

6. **A read is one SELECT on a scoped scratch copy inside a bounded Worker.** The host exports the source's live runtime bytes (refused above 16 MiB), posts them to a dedicated Web Worker that owns its OWN sql.js instance (a wasm abort cannot reach the live user DB), and the pure `scopedScratchRead` DROPs every trigger first, then every view, then every table outside the granted set and `snug_kv`, sets `PRAGMA query_only`, checks the recorded columns for drift, refuses anything but one read-only `SELECT`/`WITH` (`isReadOnlySelect` — every PRAGMA, ATTACH, DETACH, multi-statement and CTE write — then `forbiddenStatementReason`), caps rows (500) and UTF-8 bytes (192 KiB) with `truncated`, and discards the copy. A 2 s wall clock terminates the worker (`ACCESS_QUERY_FAILED`, the page stays responsive); three timeouts suspend the grant `reader-misbehaved`. Rows are scanned as objects keyed by COLUMN NAME: a credential-shaped cell, or any cell under a credential-named column, crosses as `***`. The scoped bytes are cached per grant for 10 s. Where no blob Worker can be constructed (measured per host at boot), the host composes `access: false` — a host offers only what it can run (ADR-0072 §4).

7. **The source keeps the history.** `accessLog:<sourceAppId>` — one bounded row per source (≤ 200 entries, ≤ 64 KiB; ≤ 1 MiB across sources): `granted`, `read` (the statement's first 200 chars unless the credential walk refuses it, rows, `attended`), `refused`, `revoked`, `expired`, `released`, `suspended`. Consecutive reads coalesce only on an identical `(grant, sql)` pair within a minute; pruning takes reads before lifecycle entries and never the latest lifecycle entry per grant, so the history can never be made to lie about when or by whose act access began. Shown in the source's header sheet and in Settings in words (*read transactions · 412 rows · 2 min ago · while you were away*); travels with the file; imported entries are tagged and shown under their own heading.

8. **"Where this can go" is derived, not written, and complete.** The sheet names the reader's brain exactly as the transport would route it (the platform pin → mode → the per-app pin under the same guard → key presence → `adapterKindFor`, so a keyless pin reads *(key missing)*), every APPROVED connection by provider and host, every DECLARED one as *not connected yet*, the sidecar helper by name, **always** the link path (*any link it asks you to open — you see the address first*), the away sentence when unattended is ticked, and closes with "the copy is made here, on this device; Ledger keeps a history of every read". It never says "stays on this device" under a list of hosts.

9. **Revocation is everywhere and immediate; nothing survives a doubt.** *Stop* in the source's sheet, the reader's sheet, the strip's outcome line (the undo) or Settings; `release` from the reader. The next `query` answers `ACCESS_REVOKED`; the reader's live frame is rung `host-event 'access-changed' { grantId }` (ids only). A **shared or agent update of the reader suspends** its grants (`reader-updated`; E8's exact rule — the user's own edit and a starter update change nothing), through ONE `onAppVersionChanged` fan-out that also pauses schedules, and the update confirm names them. An **untrusted import** lands every grant `suspended / imported` unless its canonical intent equals a local grant's; a trusted pull keeps them; declines and mutes are dropped on an untrusted import. A **source that gains a WhatsApp fact** suspends (`source-restricted`) — checked at every query and at the connection-approve seam, because R-9's scrub binds the sending app, not a reader. **Deleting either app** sweeps the grants, the deleted app's history, declines and mute. The consent sheet arms its primary only after 600 ms and ignores a click whose press preceded its render; *not now* holds initial focus; Escape and the backdrop are *not now*.

10. **Deferred, by name.** Write access. User-chosen column scope. Sharing `snug_kv`. A source→reader change hint (the doorbell). A builder-time access declaration. Grants inside shared bundles. Sidecar-fact sources. A count-only discover answer. A SOURCE-initiated grant (the source side is read-only at v1). A hint to the source app that it was read. Cross-app content flow in the data lane and the scheduler's think step (ADR-0074 §8's "its own disclosure" — this ADR is the frame, not that flow). Two-device history appends surfacing as a CAS divergence. An arming delay on the sibling confirms. Absorbing the hook into the embedded block. A Hub tile badge.

## Alternatives considered

- **ADR-0074's kv handshake on the existing frames** (the host writes content into the reader's kv, the event carries ids). Rejected: (a) another app's rows would be written into the reader's own namespace and persisted in the user's file; (b) `HOST_KV_VALUE_MAX_BYTES` is ≈ 1.3 KiB against a 192 KiB result; (c) a read is a request/response carrying app-authored SQL — the shape the strict net pair already governs; (d) the owner asked for the spec version to be incremented. The §8 trigger it sets ("only if a second implementation asks") is amended by this ADR: a capability whose content must cross the bridge in-band and transiently is a wire revision.
- **Four frame pairs.** Cleaner per-op typing; four §2 rows, eight schema files. The db frames carry five ops on one pair. Rejected for two frames.
- **A strict response.** R2's reason for strictness is "fields become real-world effects"; a host→app answer has none, and strictness would make the reserved `write` seat a major bump. Rejected.
- **Letting the app see the inventory**, or **a count-only discover answer**. Rejected / deferred: the sheet is the discovery; `ACCESS_NO_SOURCES` is the one fact a reader learns.
- **An LLM ranking the candidates.** Spends the brain and makes the ranking unexplainable. Rejected.
- **A parser-based table allowlist on the full copy.** Rejected for physical absence.
- **A synchronous main-thread read** (the data lane's shape). Rejected: no interrupt exists in sql.js; a Worker with its own instance and a wall clock is the only bound.
- **`ALTER TABLE … DROP COLUMN` in the scratch** to enforce frozen columns. Available (probed) but fragile across constraints; suspend-on-drift is simpler and honest. Rejected.
- **A modal on the app's `request`.** Contradicts ADR-0074 §4, the threat model's "a strip, never a modal", and the KB's promise to apps. Rejected for the strip.
- **"Just this once" as one read**, or **a persisted week as the default**. Rejected: the default is the narrowest option and is named for what it is (*while Budget is open*).
- **Writes in v1.** Their own consent copy, the data-write doctrine and R-70's two-instance problem. Deferred.
- **A `snug_access_grants` table.** A v7 stamp strands every fielded hub. Rejected for settings rows, normatively described.
- **Grants that survive a shared update.** The lineage-forgery shape R-39 names. Rejected; suspend and re-ask.
- **A versioned draft filename** (`SPEC-1.1.md`). Rejected for `SPEC.md` with the version in the header, so no future minor touches a filename or an append-only ADR.
- **Stripping the three unpublished draft items from the staged 1.1.** Rejected: that leaves the draft and the published spec diverging forever (SPEC_SYNC calls it drift); they are promoted and recorded (Q13).

## Consequences

- Positive: the user's apps can finally cooperate, from one engine in every shell; every read is user-granted, scoped to frozen columns, bounded in time and memory, logged, revocable, and refused the moment the reader's code or the source's shape changes under it; the spec gains its first post-1.0 minor with a self-contained Part VI; the runner's three capability routes become one helper and the app-ask intake ladder one module.
- Negative / residuals (the threat delta names them): the reader's brain sees what it reads; a reader can carry rows to an approved host in a GET the confirm gate never sees, or into a link it asks the user to open; rows are prompt-injection input to the reader's model (R-8's class); the user's own builder edits of the reader keep its grants (R-7's class); two instances of the source can make a read observe mid-write state (R-70's class); session grants die with a reload and persisted grants survive a trusted sync; persistence rides the file's custody line — a file written by the same OS user (R-3), the loopback data plane (R-40) and a trusted sync origin arm grants exactly as they arm scheduled tasks, and only the import path disarms them; a `request` outside a user gesture is a nag the KB forbids and the rate limit bounds; a Worker-less host (measured, not assumed) has no access at all.
- Docs owed: architecture (a section + the dependency note), code-map rows, glossary (access grant, reader, source, scope, access history), product-vision (one sentence), `docs/security/threat-model-delta-cross-app-access.md` + the fold (v3.7, the rewritten §5 row, R-71 …), SPEC 1.1 + spec-changelog (Q13's item list; the 2026-08-27 entry corrected), whitepaper edition 4, ADR-0074 §8's amendment line, next-steps (the deferrals and the sibling-confirm arming delay), lessons at Gate 6.

## Folded from the implementation (2026-10-10)

The fresh-context reviews of each implementation phase (W1 protocol · W2 runner/sdk/db · W3 engine · W3b UI · W4 shells) tightened the decision without changing its shape. Recorded here so the ADR reads true against the code; the task file's D23–D36 carry the reasoning:

- **A credential-named column is never in a scope** (D23): `security.isCredentialKeyName` — the C1 value scan's own key rule — decides; `accessGrantSchema` refuses a scope naming one; the sheet shows it as *never shared*; the drift check ignores such live columns; the scoped read WITHHOLDS the column on the copy (`'***'`, else NULL, else random; fail closed — D27) so an alias cannot carry the value out, and the handler masks by column name as the belt.
- **The record's invariants** (D25): `suspended ⇔ suspendedReason`, `revoked ⇔ revokedAt`, `readerAppId ≠ sourceAppId`, no duplicate table or column; every grant id — a memory grant's too — is a lowercase uuid v4; the view's `access` is an open string (D24) while the record's is `literal('read')`.
- **The display rule is total** (D26): a purpose, hint word or history reason refuses every `\p{Cc}`/`\p{Cf}` code point, the line separators, U+034F and the blank fillers; the statement seats refuse bidi controls; the credential walk is shared with scheduling and now sees a value glued by an operator or quoted inside a literal; the ask's hash normalises hint lists.
- **The store's postures** (D28, D29): a grant or history for an app the file does not hold is refused; a revoked grant stays revoked on an untrusted import; a trusted pull keeps even a row it cannot parse; the scoped copy also drops `sqlite_stat*` and verifies the drops against `sqlite_master`.
- **Memory grants and the hidden frame** (D30, D31, D32, D33, D35, D36): a session grant belongs to the visible frame of its generation and is never readable by the scheduler's hidden frame, whatever the opt-in says; the asking window is per app; every `query` counts against the minute first; an ask whose frame ended mid-gathering parks nothing; a stop that lands during a read wins; the `read` line is written before the rows leave; `renew` re-activates the reader's own suspended or expired grant in place.
- **The user's own act** (D34): a grant the user starts from host chrome carries the host's purpose, never the act's label as if the reader had said it.
