# 0066 — Tool-free brains carry the authoring knowledge in the prompt: one `knowledge` seat, three deliveries

- **Status:** accepted (the owner confirmed all seven interview points on 2026-09-06)
- **Date:** 2026-09-06
- **Task:** TASK-20260906-tool-free-kb-inlining (child of TASK-20260905-binding-a-artifacts / TASK-20260904-skill-only-snug)

## Context

The app-authoring knowledge base (ADR-0004) reaches the builder model through a tool: the 30 system layer says *"Before writing ANY Snug app … call the `snug_app_builder` tool … Never write an app from memory"*, and the KB summary beneath it repeats the instruction. That is right for every brain that has the tool.

Two builder arms have no tools. The webllm arm (ADR-0015) runs a 1–3B model in the page whose function calling excludes the builder's system prompt; it swaps the artifact-write tool for a fenced-HTML suffix. The host kit's pinned brain (ADR-0065 §2, Binding A) is a Claude artifact's `sample`, which takes one string and can call nothing; T2 generalised the webllm arm to it (`toolFree` when `PlatformBrain.tools` is false). Both inherited the suffix — and the suffix replaces the WRITE mechanism, never the KNOWLEDGE consult.

T4's hosted walk (2026-09-06, on a real artifact) found the consequence: told to fetch rules it could not fetch and forbidden to proceed without them, the model built a `localStorage`-persisted app with no bridge hooks, said plainly that it could not pull the template, and the frame rendered a white page (no `snug:app-announce`, nothing to render). Every unit test was green: they assert which adapter a purpose routes to, none reads the prompt as the model would.

Inlining the whole KB is not an option: rendered, it is 78,019 bytes against `sample`'s measured 65,536-byte input cap. The fix has to SELECT, and the selection is a decision. Two more facts shaped it: the pinned webllm model (`Llama-3.2-3B-Instruct-q4f16_1-MLC`) ships with a 4,096-token context window and the essential core alone is ~10K tokens; and the e2e that finally read the wire found the USER-slot template citing the tool too.

## Decision

1. **One seat on the assembly: `HostSystemPromptOptions.knowledge: 'tool' | 'inline' | 'none'`, default `'tool'`.** It is a builder-branch seat only (the runtime branch and the no-builder branch ignore it), and the default assembles byte-identically to before — every golden and every tooled caller rests on that. Like `platform`, a brain's delivery never changes mid-session, so ADR-0012's cached-prefix discipline holds per client.
2. **`'inline'` = the 35 layer + the five-file core, each file its own system block.** The core is pinned by name in `packages/knowledge/src/layers.ts` (`INLINE_KNOWLEDGE_CORE_FILES`, served by `getInlineKnowledgeCore()` with the same rendering the tool gets): `10-overview-and-contract`, `20-html-template`, `30-bridge-protocol`, `40-persistence-and-db`, `80-cdn-compatibility` — 37,437 rendered bytes. Every one is named by an acceptance criterion (the loop and hard rules; the template with the copy-exactly hooks; the reply contract; the db rule whose absence produced `localStorage`; the CDN table with the artifact rules). Left out: the optional tier (50 catalog, 60 design, 70 defensive, 95 runtime contract — 19,136 bytes, which would leave ~5 KB for everything else) and 90 connected APIs (no connected apps under Binding A, ADR-0065 D4). The selection is **static**: one assembly per platform, provable, never shaped from the request. The template rides **whole** — copy-exactly is the contract and a trimmed twin would need its own SDK sync-lock for a ~1 KB gain.
3. **The 35 layer (`35-app-builder-inline.md`) is the 30 layer's tool-free rewrite.** It names no tool, says the rules FOLLOW rather than "fetch them", restates the persistence rule at the top (`localStorage` refused by name), keeps the real-schema doctrine where the app can carry it itself (startup `CREATE TABLE IF NOT EXISTS` through `useAppDB`), tells the model to omit the template's `useConnectedFetch` section unless the app calls an API (its mere presence marks a build as connected and sends the post-turn recovery inferrer after the first URL in the file — the CDN), and replaces the docs tool with a plain-language note in the reply.
4. **`'none'` = the 36 layer (`36-app-builder-unaided.md`) alone — for webllm.** Honest that no knowledge base is reachable and no tools exist; the single-file rule, the CDN allowlist, no network, no browser storage, and the guidance to build apps that are complete on their own. This is the AC2 half of the fix for webllm; AC1 cannot hold there until its context window is raised (a next-steps item under ADR-0015), and that is recorded rather than papered over.
5. **The callers pick the delivery from the same fact the tool-free arm rests on.** `builder.ts` passes `knowledge: isWebllm ? 'none' : 'inline'` on its tool-free arm and keeps `WEBLLM_BUILD_SUFFIX` (the write mechanism); the tooled arm passes nothing. The build view picks the user message's tool-free twin (`## User Message Template (tool-free)` in `ui/build-app-prompt.md`) from `buildsToolFree(brain)` in `state/webllm.ts` — THE one derivation, beside `resolveTurnMode` — because a tool named in the user slot is the same defect as one named in the system slot.
6. **The inline assembly has a ceiling, measured on the wire's own ruler.** `HOST_BUILDER_SYSTEM_MAX_BYTES = 45,056` (44 KiB) in `promptBudget.ts`; `apps/host`'s test measures the inline assembly plus the suffix with `measurePrompt` (the shaper the adapter sends with — lesson 2026-08-05) and pins that the ceiling leaves ≥ 20,480 bytes for the request, the app context and history. A layer growing past it fails that test, never a build turn on the artifact. Over budget at run time stays **refuse by name** through T4's ladder (history oldest-first, html never cut): with the core inline, a host-side EDIT of an app above ~10 KB with saturated schema/docs/history is refused, and the refusal already names the playground as the place to edit. `HOST_CONTEXT_CAPS` values are unchanged; their comment carries the new arithmetic.
7. **The proof reads the prompt as the model would.** Knowledge tests assert the inline assembly's CONTENT against the package's own accessors and constants (the frame literals, the tool-name constants, the persistence text) — never a retyped sentence or a byte count. The host e2e's fake `sample` lifts the template out of the prompt it RECEIVED (following the template's own omit-otherwise rule for section 5) and the built app must render `<main>` with the connecting copy gone — the announce → host-ready round trip inside the sandboxed frame, i.e. not a white page. The builder turn plus the contract synthesis are pinned at two `sample` calls.

## Consequences

- The tool-free host builder now sends ~41.3 KB of system text per build turn (measured 2026-09-06) instead of 4.1 KB. Under `sample` that is a viewer-billed prompt; ADR-0012's cached-prefix discipline does not apply to `sample` (`cache: false` by design), so the cost is per turn. The room beside it is ≈ 24 KB, ≈ 10 KB once the edit-turn context caps are saturated. T4's budget fixtures were retuned to that arithmetic (18 KB app fits under the ceiling; 51 KB — S11's whole-app case — is now the refused example).
- Adding a KB file to the core is a one-line change with a test that refuses it past the ceiling; the optional tier stays behind the tool for tooled brains and is simply absent on tool-free ones.
- The webllm arm is now honest but still unaided; the `'none'` layer is the floor, and raising its window (context_window_size override, VRAM cost) is the only way to give it AC1.
- Follow-up recorded in next-steps: under Binding A the post-turn connection recovery inferrer (`finalizeConnectionDeclaration`) can still fire on a build whose html merely defines `useConnectedFetch`, a paid viewer call for a connection that cannot exist there — the 35 layer tells the model to omit the section, and the pipeline-side skip is its own item.
- **Lesson (docs/lessons.md 2026-09-06):** "which adapter" and "what did the prompt actually say" are different questions; a prompt assembled for a tool-free brain needs a test that reads it — both slots — as the model would.
