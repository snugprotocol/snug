- **2026-08-17 — An installed starter never receives a rebuild (found by the owner's first run of TASK-20260817-telepath).** `install_source` is a unique identity and `RunView` redirects an installed starter straight to the stored app row, so re-bundling a starter's HTML reaches only users who have NOT installed it — a rebuilt starter is invisible to exactly the people most invested in it, and "delete it and reinstall" costs them their connection, credentials, analyses and app data. Shape of the fix: on opening an installed starter whose bundled HTML differs from its current version, save the new bytes as a NEW VERSION of the existing app (connection, secrets and DB untouched; the old version stays revertable via the existing version machinery) — plus a visible "updated to vN" disclosure, since silently swapping running code is its own hazard. Open questions: whether the copy is automatic or offered, and what happens when the user has re-authored their own version (do NOT clobber — the `installStarterRuntimeContract`/`installStarterDocs` never-overwrite posture is the precedent).
